User Center · Detailed Design

用户管理模块

用户中心自建账号，接入应用（AI TeamFlow、Atlas 等）通过开放接口获取用户、组织与权限（统一登录本期不做，以后用 Keycloak）。用户管理模块负责账号的建立、维护、状态与密码：新建、编辑、停用 / 启用、解锁、重置密码，以及用户本人的个人中心。直属上级不存储，由组织架构按部门负责人计算。岗位、角色、菜单与数据权限不在这里维护——它们由权限管理模块授予用户或组织，用户详情只做只读展示。

自建账号账号不可修改、不物理删除临时密码只显示一次首次登录必须改密停用即注销所有会话岗位在权限管理中授予直属上级由组织计算

01定位与范围

本模块负责

  • 用户档案：姓名、账号、邮箱、手机、所属部门
  • 账号状态：未激活 / 正常 / 已锁定 / 已停用，及其转换
  • 管理员侧密码操作：生成临时密码、重置密码、解锁
  • 用户详情：基本信息、权限（只读）、登录记录、可访问的应用
  • 个人中心：本人修改邮箱 / 手机、修改密码、查看可访问的应用

不在本模块

  • 部门树、部门负责人、直属上级的计算 → 组织架构模块
  • 岗位、角色、菜单、数据权限的授予 → 权限管理模块
  • 用户中心管理台的登录、会话、密码策略、锁定规则 → 认证与安全策略模块（本模块调用其服务）；不对外提供统一登录，以后用 Keycloak
  • 应用的可访问范围 → 应用接入模块
  • 日志查询页面 → 审计日志模块（本模块只负责写入事件）
  • 本期不做：批量操作、批量导入、导出；HR 系统同步（用户中心即人员数据来源）
设计原则账号是各系统识别人的依据：账号创建后不可修改，用户不做物理删除（离职走停用），保证接入应用里的历史数据、审计记录始终能对上人。

02术语

术语含义
账号 account登录名，小写字母、数字、点、下划线，3–32 位；全局唯一，创建后不可修改，停用后也不回收复用。
主键 id / 逻辑主键 uuidid 为自增主键，仅库内使用；uuid 为逻辑主键（UUIDv7），业务关联、API、开放接口都使用它；以后接入 Keycloak 时作为用户的稳定标识。
临时密码新建、重置时由系统生成的一次性密码，只向管理员显示一次；用户用它登录后必须修改密码。
激活用户首次登录并按策略设置了自己的密码。激活前状态为「未激活」。
须改密用户下次登录必须先改密码的标记（must_change_password）。临时密码、密码过期都会置位。
直属上级不存储。从用户所在部门开始向上，取第一个「不是本人、未停用」的部门负责人（见第 06 节）。
主部门用户所属的唯一部门（dept_uuid）。本期一人一个部门，兼职多部门见「待确认」。
会话用户中心管理台的登录会话，由认证与安全策略模块管理，本模块在停用 / 重置密码时请求注销。接入应用的会话由应用自己管理（用户中心通过开放接口返回用户状态，P1 起推送变更通知）。

05领域模型

属性规则谁能改
姓名 name必填，1–32 字符，去首尾空白；可重名管理员
账号 account必填，^[a-z0-9._]{3,32}$，全局唯一（含已停用），不可修改—
邮箱 email必填，格式校验，小写存储，全局唯一（含已停用）管理员 / 本人
手机 phone选填，中国大陆 11 位手机号；不做唯一校验（不用于登录，可多人共用座机 / 前台号码）管理员 / 本人
部门 dept_uuid必填，必须是存在的部门；可以是根部门管理员
直属上级不是用户属性，由组织架构按部门负责人实时计算（第 06 节）—（改部门负责人即改变）
状态见第 07 节；由 status、activated_at、locked_until 推导展示状态系统 / 管理员
岗位、角色不是用户属性。由权限管理授予（可经部门继承），本模块只读展示权限管理
为什么岗位不放在用户上一个人可以有多个岗位，岗位也可以按部门整体授予；放在用户表上会形成两套来源。统一由权限管理授予后，用户列表的「岗位」列只是展示计算结果。

06直属上级（由组织计算）

直属上级不存储在用户上，由组织架构模块根据「用户所在部门 + 各部门负责人」实时计算。部门更换负责人后，相关人员的直属上级自动跟着变化，不需要批量修改用户数据，也不会出现数据不一致。

计算规则

managerOf(user):
  d = dept(user.dept_uuid)
  while d is not null:
    leader = d.leader
    if leader is not null and leader != user and leader.status != disabled:
      return leader
    d = parent(d)                // 本人是该部门负责人，或部门无负责人 / 负责人已停用 → 向上一级
  return null                    // 根部门负责人没有直属上级

示例（原型数据）

用户所在部门部门负责人直属上级说明
何超研发中心 / 交易中台李工李工普通成员 → 本部门负责人
陈运研发中心 / 技术中心陈运（本人）李工本人是负责人 → 上级部门「研发中心」的负责人
李工研发中心 / 交易中台李工（本人）林远同时是「研发中心」负责人 → 连续跳过本人，取「星海科技」负责人
林远星海科技（根）林远（本人）—根部门负责人
更换负责人的效果把「交易中台」负责人从李工改为刘洋：何超、许晴的直属上级立即变为刘洋；刘洋自己的直属上级为研发中心负责人李工。整个过程只改了部门表的一个字段。

对外提供

  • 负责人约束：每个部门一名负责人，且必须是该部门子树内未停用的用户（见组织管理模块），保证计算结果唯一。
  • 组织模块提供 OrgService.managerOf(user_uuid)；部门树（含负责人）缓存在内存，部门或负责人变更时失效，计算不查库。
  • 用户详情「基本信息」只读展示，并注明来源（所在部门负责人 / 上级部门负责人）。
  • 接入应用需要直属上级（如审批流）时，调用开放接口查询用户信息（实时计算），不应长期缓存。
  • 「我的直属下属」（P2）= 所有 managerOf(x) = 我 的用户。只需遍历我负责的部门及其下级部门的成员，由组织模块基于部门树计算。

07账号状态与生命周期

存储字段：status ∈ {active, disabled}，配合 activated_at（是否激活过）、locked_until（锁定到期时间）、must_change_password。展示状态按下面的优先级推导，避免「锁定」「未激活」与「停用」互相覆盖丢失信息：

优先级条件展示状态
1status = 'disabled'已停用
2locked_until > now()已锁定
3activated_at is null未激活
4其他正常（must_change_password 为真时附「须改密」标记）
当前动作结果附带
—新建status=active，activated_at=null，must_change=true → 未激活生成临时密码
未激活首次登录并改密activated_at=now，must_change=false → 正常写登录日志
未激活 / 正常连续失败 N 次（认证模块）locked_until=now+M 分钟 → 已锁定系统审计「锁定账号」
已锁定到期 / 管理员解锁locked_until=null，失败计数清零 → 回到未激活或正常—
未激活 / 正常 / 已锁定重置密码新临时密码，must_change=true，同时解锁；激活状态不变注销全部会话
未激活 / 正常 / 已锁定停用status=disabled → 已停用注销全部会话
已停用启用status=active；activated_at 有值 → 正常，否则 → 未激活；锁定信息清空—
已停用重置密码 / 解锁不允许，先启用—

密码过期（安全策略 expireDays）只在登录时置 must_change=true，不改变展示状态。

08新建用户与临时密码

管理员填写表单 → 服务端校验（格式 / 唯一 / 部门存在） → 事务内：插入用户 + 写凭据（临时密码哈希，must_change=true，temp_expires_at）+ 写审计 → 响应中返回一次明文临时密码 → 页面弹窗显示「只显示这一次」+ 复制按钮 → 管理员通过安全渠道告知用户 → 用户首次登录 → 强制改密 → 激活

临时密码规则

  • 使用 CSPRNG 生成，长度 max(12, 策略最小长度)，保证满足当前密码策略（大写 / 数字 / 特殊字符），去掉易混淆字符（0/O、1/l/I）。
  • 服务端只存哈希（argon2id），明文只出现在这一次响应里；不写日志、不写审计、不落库。
  • 有效期默认 7 天（temp_expires_at），过期后登录提示「临时密码已过期，请联系管理员重置」。P1
  • 响应带 Cache-Control: no-store；前端弹窗关闭后从内存清除，不进入任何前端状态持久化。

09编辑用户

  • 可改：姓名、邮箱、手机、部门。账号只读并提示「账号创建后不可修改（各系统以它识别用户）」。
  • 使用乐观锁：请求带 If-Match: <version>，版本不一致返回 VERSION_CONFLICT，前端提示「该用户已被他人修改，请刷新后重试」。
  • 部门变更：只改 dept_uuid，同一事务写审计「调整部门：A → B」。直属上级随之按新部门重新计算；若该用户是某部门负责人且调出了该部门子树，该部门负责人被自动清空（规则见组织管理 · 部门负责人），保存前提示。影响（按部门继承的授权、应用可访问范围）在用户中心内实时生效；接入应用在刷新授权快照（或收到变更通知）后生效，界面提示「接入应用中的权限将在几分钟内更新」。
  • 邮箱变更：唯一性校验；不触发重新激活。
  • 审计记录字段级差异（{field: [old, new]}），邮箱 / 手机在审计中脱敏（138****0003）。
  • 已停用用户也可编辑档案（例如更正姓名），不改变状态。

10停用 · 启用 · 解锁 · 重置密码

操作前置校验效果确认文案要点
停用不能停用自己；停用后至少保留一名可用的超级管理员（调用权限模块计算，含经岗位 / 部门获得的）status=disabled，记录 disabled_at / by / 原因；注销用户中心会话；开放接口随即返回 status = disabled、can_access = false；授权、数据权限保留无法登录用户中心及所有接入应用；数据保留，可随时启用
启用—status=active；按 activated_at 回到正常或未激活；清空锁定—
解锁当前为已锁定locked_until=null，失败计数清零—
重置密码不能是已停用生成临时密码，must_change=true，解锁；注销全部会话；返回一次明文原密码立即失效；各应用登录会话被注销

会话注销的生效时间

  • 用户中心管理台会话：立即失效。
  • 接入应用：开放接口立即返回已停用；应用缓存的授权快照最长 5 分钟内仍可能放行。需要立即踢出的应用订阅变更通知（Webhook user.disabled）。P1
停用不级联清授权停用是可逆操作，授权与数据权限都保留；有效权限计算时排除已停用用户（例如「至少保留一名可用 Owner / 超级管理员」都不把已停用用户计入）。

13个人中心（自助）

  • 所有登录用户可用，不需要任何操作码。
  • 可改：邮箱（唯一性校验）、手机。姓名、部门、岗位只读，提示「由管理员维护」。
  • 修改密码：需当前密码；新密码按当前策略校验，不能与当前密码相同（密码历史见安全策略模块）；成功后注销除当前会话外的全部会话。
  • 修改密码连续输错当前密码 5 次，计入登录失败锁定（防止会话被盗后暴力猜测）。
  • 「我可以访问的应用」只列启用中的应用。

14数据模型

假设：PostgreSQL 15+。凭据单独成表，便于收紧访问与审计。

主键约定（全部表通用） id bigint 自增主键，只在库内使用（聚簇、分页游标），不对外暴露、不用于任何关联； uuid uuid 逻辑主键（UUIDv7，按时间有序、对索引友好，由应用生成），表间关联、外键、API、开放接口、审计对象都使用它。 关联字段统一命名为 xxx_uuid，外键引用对方表的 uuid；API 中的 id / xxx_id 取值即对应的 uuid。
-- 用户档案
CREATE TABLE uc_user (
  id               bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,   -- 自增主键，仅库内使用
  uuid             uuid         NOT NULL,          -- 逻辑主键（UUIDv7）
  account          varchar(32)  NOT NULL,
  name             varchar(32)  NOT NULL,
  email            varchar(128) NOT NULL,          -- 小写存储
  phone            varchar(20),
  dept_uuid        uuid         NOT NULL REFERENCES uc_dept(uuid),
  status           varchar(16)  NOT NULL DEFAULT 'active',   -- active | disabled
  activated_at     timestamptz,                    -- null = 未激活
  disabled_at      timestamptz,
  disabled_by      uuid,                           -- 操作人 uc_user.uuid
  disabled_reason  varchar(200),
  last_login_at    timestamptz,
  last_login_ip    varchar(45),
  created_at       timestamptz NOT NULL DEFAULT now(),
  created_by       uuid,
  updated_at       timestamptz NOT NULL DEFAULT now(),
  updated_by       uuid,
  version          int NOT NULL DEFAULT 1,
  CONSTRAINT uk_user_uuid    UNIQUE (uuid),
  CONSTRAINT uk_user_account UNIQUE (account),
  CONSTRAINT uk_user_email   UNIQUE (email),
  CONSTRAINT ck_user_status  CHECK (status IN ('active','disabled'))
);
CREATE INDEX ix_user_dept    ON uc_user (dept_uuid);
CREATE INDEX ix_user_created ON uc_user (created_at DESC);
CREATE INDEX ix_user_search  ON uc_user USING gin ((name || ' ' || account || ' ' || email || ' ' || coalesce(phone,'')) gin_trgm_ops);

-- 凭据与登录保护（认证模块读写，本模块在新建 / 重置时写入）
CREATE TABLE uc_user_credential (
  id                   bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  uuid                 uuid NOT NULL,
  user_uuid            uuid NOT NULL REFERENCES uc_user(uuid),
  password_hash        varchar(255) NOT NULL,      -- argon2id
  must_change_password boolean NOT NULL DEFAULT true,
  temp_expires_at      timestamptz,                -- 临时密码有效期；改密后置空
  password_changed_at  timestamptz,
  failed_count         int NOT NULL DEFAULT 0,
  locked_until         timestamptz,
  CONSTRAINT uk_cred_uuid UNIQUE (uuid),
  CONSTRAINT uk_cred_user UNIQUE (user_uuid)      -- 一人一条凭据
);
展示状态不落库「已锁定」「未激活」由 locked_until、activated_at 实时推导，锁定到期无需定时任务解锁；列表按状态筛选时用对应条件查询（locked_until > now() 等）。

19异常与边界

场景处理
两个管理员同时新建相同账号数据库唯一约束兜底，后到者 ACCOUNT_EXISTS
两个管理员同时编辑同一用户乐观锁，后到者 VERSION_CONFLICT
部门在填写表单期间被删除提交时 DEPT_NOT_FOUND；组织模块删除部门前已校验「无用户」
停用唯一的超级管理员（包括经岗位 / 部门获得）LAST_SUPER_ADMIN
部门负责人被停用计算直属上级时跳过该负责人，继续向上找；组织架构页提示该部门「负责人已停用」，引导更换
部门没有设置负责人继续向上找上级部门负责人；全部为空则直属上级为空
用户是根部门负责人（如 CEO）直属上级为空
用户同时是本部门和上级部门的负责人连续跳过本人，取更上一级的负责人（例：李工 → 林远）
未激活用户的临时密码丢失重置密码（对未激活用户即「重新生成临时密码」）
用户被停用时正在应用中操作应用下次获取授权快照时得知已停用并终止会话；订阅 Webhook 的应用立即踢出
修改邮箱为他人已停用账号的邮箱拒绝（唯一性含已停用），需先更正对方邮箱

20非功能

安全

  • 密码哈希 argon2id；临时密码 CSPRNG，满足策略
  • 明文密码不进日志、审计、数据库、前端持久化
  • 含密码的响应 Cache-Control: no-store
  • 重置密码接口按操作人限流（如 30 次 / 分钟）

性能与容量

  • 按 5 万用户设计：列表 p95 < 300ms（trgm 索引 + 部门 id 列表过滤）
  • 直属上级计算走内存中的部门树缓存（部门变更时失效），单次 O(部门深度)，不查用户表以外的数据

个人信息保护

  • 审计中邮箱 / 手机脱敏
  • 停用用户的个人信息保留；删除 / 匿名化见「待确认」

可观测

  • 指标：新建 / 重置 / 停用次数
  • 告警：短时间内大量重置密码或停用（可能是误操作或越权）

21与原型的差异

原型用于确认交互，以下几处在详细设计中收紧，实现以本文档为准（直属上级改为组织计算、去掉批量 / 导入 / 导出，原型已同步修改）：

项原型详细设计原因
重置正常用户的密码状态变为「未激活」保持「正常」，附「须改密」标记「未激活」应只表示从未登录过，否则统计和筛选会失真
启用一律变为「正常」按是否激活过回到「正常」或「未激活」从未激活的人启用后仍须用临时密码首次登录
临时密码有效期无默认 7 天降低临时密码泄露后的风险
停用原因无可选填写，进入审计离职 / 违规等便于追溯

22测试要点

  • 账号格式边界（2 / 3 / 32 / 33 位、大写、非法字符）；账号与已停用账号重复。
  • 邮箱大小写归一后的唯一性；手机格式。
  • 直属上级计算：普通成员 → 本部门负责人；本部门负责人 → 上级部门负责人；同时负责多级部门 → 连续跳过本人；负责人已停用 → 跳过；部门无负责人 → 向上；根部门负责人 → 空。
  • 更换部门负责人后，相关成员的直属上级立即变化，且用户表无写入。
  • 用户调整部门后直属上级按新部门计算。
  • 状态机全部转换（第 07 节表格逐行）；锁定到期后无需操作自动变回原状态。
  • 临时密码：满足各种策略组合；只返回一次；过期后不能登录；首次登录强制改密。
  • 停用：自己、唯一超级管理员（直接 / 经岗位 / 经部门继承）；停用后用户中心会话失效、开放接口返回已停用。
  • 重置密码：已停用拒绝；已锁定被解锁；会话注销。
  • 权限：每个按钮 / 接口在缺少对应操作码时隐藏且返回 403。
  • 乐观锁冲突提示；审计中无明文密码、联系方式已脱敏。

24待确认

  1. 临时密码分发方式：管理员手工告知（当前设计），还是系统邮件发送激活链接（更安全，但依赖邮件服务）？
  2. 临时密码有效期默认 7 天是否合适？
  3. 停用原因是否必填？是否需要原因字典（离职 / 长期休假 / 违规）？
  4. 删除与匿名化：离职人员个人信息是否需要在一定期限后匿名化（合规要求）？
  5. 兼职多部门：是否需要一人多部门（主部门 + 兼职部门），兼职部门是否参与授权继承、应用可访问范围与直属上级计算？
  6. 忘记密码自助找回：是否需要（依赖邮箱验证；手机号非必填、不唯一，不能用于找回）？本期默认由管理员重置。
