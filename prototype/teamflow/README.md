# AI TeamFlow — AI 协同工作流平台（可点击高保真原型）

> 让 AI Agent 作为团队成员，和人按组织规范流程协作完成工作，全过程可审计、可度量。

本原型为 **纯静态单页应用（SPA）**，无任何外部 CDN / 构建依赖。样式与脚本全部为本地文件，图标使用内联 SVG 与 emoji。

---

## 一、如何打开

**方式 A（最简单）：双击打开**
直接在文件管理器中双击 `index.html`，用任意现代浏览器打开即可（Chrome / Edge / Safari / Firefox）。

**方式 B：本地静态服务器（推荐，hash 路由体验更一致）**

```bash
cd <本项目根目录>
python3 -m http.server 8080
# 然后浏览器访问 http://localhost:8080/index.html
```

> 说明：本项目使用 **hash 路由**（地址形如 `#/process/p1`），因此方式 A 直接以 `file://` 打开也能完整工作，无需服务器。

## 二、文件结构

```
.
├── index.html          主入口（SPA 外壳：侧边栏 + 顶栏 + 内容区 + 模态/Toast 容器）
├── assets/
│   ├── styles.css      全部样式（设计系统 / 布局 / 组件 / 响应式）
│   └── app.js          全部逻辑 + Mock 数据 + 渲染 + 交互
└── README.md           本说明
```

`index.html` 以相对路径引用 `assets/styles.css` 与 `assets/app.js`。所有 Mock 数据集中在 `app.js` 顶部（`TEAMS（成员与 Agent） / PEOPLE / AGENTS / TEMPLATES / ARTIFACT_DEFS（文件模板） / NODE_DOC / CHAT / PROJECTS（角色分配） / PROCESSES / AUDIT`）。`AUDIT` 目前只记录、不展示。

## 三、页面清单（hash 路由）

> 层级：**团队 → 项目 → 流程**。左侧导航：团队管理、流程模板、文件模板。

> 总览仪表盘与度量与审计暂不纳入本期设计，已移除；产出物管理改为**文件模板管理**（不再管理产物实例；只支持 Markdown）；「流程管理」并入项目（流程属于项目）；默认进入 `#/teams`，旧地址 `#/dashboard`、`#/metrics`、`#/processes` 回落到团队管理。

| 路由 | 视图 | 核心功能点 |
| --- | --- | --- |
| `#/templates` | 流程模板列表 | 5 个模板卡片（研发 / 内容生产 / 合同合规 / 数据分析 / 故障处理），显示版本号、节点数、被引用次数、适用范围 |
| `#/templates/:id` | 模板详情 / 流程编辑 | 流程图：顺序节点 + **并行轨道**（上游就绪即同时开工，全部完成后汇合）。**「编辑流程」**进入草稿：箭头处「＋」插入节点或并行轨道、并行组「新增轨道」、轨道内「＋ 节点」、删除节点 / 轨道（轨道只剩一条时退化为顺序节点）；「发布 vX.Y」或「放弃修改」，发布后仅对新建流程生效（在途流程保存了创建时的模板快照）。节点配置：执行方式固定**人机协同**；**执行角色**（人机协同成员，可选或新建）；**产物名称**（节点自定义）；**文件模板**下拉（规定产物格式，来自文件模板管理）；输入产物由流程图上游决定；**准出 / 准入评审 = 角色 + 规则**（任一人同意 / 所有人同意；角色，不是人）；不再配置退回目标 |
| `#/file-templates` | 文件模板管理（卡片） | 文件模板 = 一份 Markdown 规则文件。卡片：用途标签（产物格式 / 评审规则 / 其他）、模板文件（.md 名称 / 大小 / 版本）、被引用节点数、更新时间；按用途筛选；未上传文件的排前并提示 |
| `#/file-templates/:id` | 文件模板详情 | 模板文件（下载、上传新版本）；**模板内容**：Markdown 渲染 / 源码切换；**版本历史**：点击查看任一历史版本；引用该模板的节点。上传弹窗：只接受 .md、≤ 100 KB、UTF-8、非空、内容须有变化，选中后预览，必填更新说明，提示进行中的节点不受影响 |
| `#/teams` | 团队管理 | 团队卡片：说明、成员与 AI Agent 头像、成员数、Agent 数、项目数、进行中流程数 |
| `#/teams/:id` | 团队详情 | **项目**卡片（绑定模板、角色分配完成度、流程数）+「新建项目」（选模板）；**成员**表（岗位、在各项目担任的角色）；**AI Agent** 列表（能力说明、模型、担任的角色） |
| `#/projects/:id` | 项目首页（处理流程） | 进项目就是为了处理流程：**流程列表**为主，筛选「全部 / 待我处理 / 进行中 / 已完成」+ 搜索；每个流程显示「卡在哪个节点、等谁协同 / 审批」、进度、缩略流程图；**待我处理**的流程红色标记并排在最前；「发起流程」。角色未分配完时只显示一行提示 +「去配置」 |
| `#/projects/:id/settings` | 项目设置（低频） | 基本信息；绑定的流程模板（可更换，仅影响新发起的流程）；**角色分配**：执行角色与评审角色，每个角色从团队里选人和 AI Agent |
| `#/process/:id` | **流程详情**（重点） | 顶部**流程图**：按模板结构画（含并行轨道），每个节点显示状态与审批进度（如「准出 1/2」），点击切换节点。左侧**人机协同**为主操作区：与 Agent 对话下达指令（Enter 发送），「提交准出评审」。右侧**审批**：当前节点的准出 / 准入，显示角色、规则（任一人同意 / 所有人同意）、每位评审人的状态与「同意 / 驳回」（原型可代任一评审人操作）；驳回可退回本节点修改或打回到更早阶段。右侧**产物**：本流程已产出的产物列表 + 预览。状态流转：人机协同中 → 待准出 → 待准入 → 已通过 → 上游全部通过的下游自动开工 |

状态徽标配色统一：**待开始=灰、人机协同中=蓝、待准出=橙、待准入=紫、已通过=绿、已打回=红**。

## 四、推荐演示动线

> 团队管理 → 团队 → 项目（角色分配）→ 发起流程 → 流程详情。

1. **团队与项目 `#/teams` → `#/teams/trade` → `#/projects/pj-account`**
   - 交易中台：4 名成员、7 个 AI Agent；成员表和 Agent 列表里能看到各自在项目中担任的角色。
   - 进入「账号体系升级」：首页就是流程列表。「支持微信一键登录」停在 PRD 准出、等张明（当前用户）审批，红色标记「待你审批」并排在最前；切到「待我处理」「已完成」筛选，或搜索流程名。
   - 点 **「⚙ 项目设置」**：基本信息、绑定的流程模板、角色分配（例如「架构设计 = 李工 + 架构 Agent」、「技术负责人 = 李工 + 刘洋」）。
   - 「优惠券中心重构」只分配了 3 个角色：首页一行提示「8 个角色未分配 · 去配置」。
   - 在团队页 **「＋ 新建项目」** → 项目设置里分配角色 → 回到项目首页 **「＋ 发起流程」**。

2. **流程详情 `#/process/p1`**（重点演示，从项目页的流程卡片进入）
   - 顶部流程图：「技术方案」停在 **准出 1/2**（规则「所有人同意」，李工已同意、刘洋待审）；「测试用例设计」在并行轨道上人机协同中。
   - 右侧审批卡片：给刘洋点 **「同意」** → 准出 2/2 通过 → 进入准入；给王测点 **「同意」** → 技术方案已通过。「编码」仍待开始（要等并行的测试用例）。
   - 点流程图上的「测试用例设计」→ 在人机协同区与 Agent 对话（Enter 发送）→ **「📨 提交准出评审」**。
   - 点 **「驳回」** → 填批注、选择退回本节点或更早阶段 → 节点回到人机协同中；重新提交后同意准出、准入 → 「编码」汇合开工。
   - 右侧产物列表点任一产物，下方预览。

3. **流程模板 `#/templates` → `#/templates/tpl-dev`**
   - 查看流程图：「技术方案」「测试用例设计」两条并行轨道；点任意节点，下方显示节点配置（人机协同、执行角色、产物名称、文件模板、输入产物、准出 / 准入评审角色）。
   - 点 **「✏️ 编辑流程」**：
     - 箭头上的 **「＋」** → 插入节点 / 插入并行轨道；
     - 并行组 **「＋ 新增轨道」**，轨道末尾 **「＋ 节点」**；
     - 悬停节点右上角 **×** 删除节点，轨道右侧「删除轨道」；
     - 在节点配置里改名称、产物名称、选文件模板、选评审角色。
   - 点 **「发布 v1.4」**：模板版本升级；打开进行中的流程 `#/process/p1`，仍是原来的 7 个节点（在途流程不受影响）。

4. **文件模板 `#/file-templates` → `#/file-templates/prd`**
   - 切换用途筛选「产物格式 / 评审规则」；「技术方案准出检查规则」是为未来自动准出准备的评审规则模板。
   - 进入「PRD 编写规范」：Markdown 渲染 / 源码切换；点版本历史里的 v1 查看历史内容。
   - 点 **「⬆ 上传新版本」**：选 .md 文件（非 .md、超过 100 KB、非 UTF-8、空文件都会被拒绝），预览后填写更新说明 → 成为 v4。
   - 「发布方案规范」故意没有文件：在上传区选文件 → 变为 v1。
   - 流程模板节点配置里，「产物名称」由节点定义，「文件模板」选择产物格式；流程详情的产物预览上方显示「依据文件模板」。

## 五、交互与状态说明

- 所有主要按钮均有真实反馈：切换视图、打开模态、变更状态、Toast 提示。
- 全局 **Toast 组件**：右下角弹出，含 成功 / 信息 / 警告 / 错误 四种样式，自动消失。
- 全局 **模态组件**：支持遮罩点击与 `ESC` 关闭。
- 数据为**内存态 Mock**：节点状态、审计日志、对话、新建流程等在一次会话内实时变化，刷新页面后重置（原型定位，不做持久化）。
- 顶栏**团队切换器**（交易中台 / 技术中心 / 内容中心）可切换并给出 Toast 反馈。
- 响应式：窄屏（≤780px）侧边栏收起为顶部横向栏，多列网格降为单列。

## 七、技术约束（已遵守）

- 纯静态，双击 `index.html` 即可用。
- **无任何外部 CDN 依赖**，无第三方 JS/CSS 库（图表全部为纯 CSS 绘制）。
- 图表用 CSS（柱状/环形 conic-gradient/趋势），节点连线用 CSS 定位 div 正交路由，图标用内联 SVG 或 emoji。
