AI TeamFlow · Detailed Design

团队管理模块

团队由人和 AI Agent 组成。团队里创建项目，项目绑定一个流程模板，并把模板中的角色分配给团队里的人和 Agent；流程属于项目。用户进入项目是为了处理流程，因此项目首页以流程列表为主，绑定模板与角色分配放在低频的「项目设置」里。

团队 = 人 + AI AgentAgent 来自 Atlas项目绑定流程模板角色分配到人与 Agent项目首页 = 流程

01定位与范围

在范围内团队的创建与维护；团队成员的管理入口（人员与级别存于用户中心，见权限设计）；团队 AI Agent 的接入与可用性同步；项目的创建、设置、归档；项目绑定流程模板；角色分配；项目首页（流程列表、筛选、待我处理）的页面与聚合规则；分配的锁定时机约定。
不在范围内流程的运行、审批投票（流程模块）；流程模板与文件模板的定义（各自模块）；用户账号与权限体系（用户中心提供）；Agent 本身的配置与运行（Atlas）。
设计原则
  1. 高频在前，低频收起：项目首页只放流程；配置项目集中在项目设置。
  2. 角色落到人与 Agent 只在项目里发生：模板只有角色名，团队只有成员，二者在项目里相遇。
  3. 分配可改，进行中的不乱：执行 Agent 与评审人名单在节点开工 / 进入评审时锁定（§9）。
  4. 不复制 Atlas：Agent 只存 Atlas 的引用，能力与配置以 Atlas 为准。

02术语

术语含义
团队一组人和 AI Agent，如「交易中台」。项目、流程都归属团队。
成员对团队有读写权限的人（用户中心数据权限，每个团队一条，可经部门获得）；团队管理员对团队是 Owner。与流程模板中的「流程角色」是两回事。
团队 Agent被团队接入的 Atlas AI Agent，可在本团队的项目中担任执行角色。
项目团队内的一项持续工作，如「账号体系升级」。绑定一个流程模板，包含若干流程。
角色分配项目中「模板角色 → 成员 / Agent」的映射，如「架构设计 = 李工 + 架构 Agent」。
执行角色 / 评审角色来自流程模板：执行角色完成节点（人机协同），评审角色负责准出 / 准入。
待我处理当前用户需要动手的流程：他是待投票的评审人，或是进行中节点执行角色里的人。

05领域模型

User（用户，来自用户中心） │ * ▼ * Team（团队）─── 成员与级别存于用户中心（数据权限 Team：只读 / 读写 / Owner） │ └── 1:* ──▶ TeamAgent（团队 Agent：atlas_agent_id, 名称 / 模型快照, available） │ 1:* ▼ Project（项目：flow_template_id, status: active | archived） │ 1:* ▼ RoleAssignment（流程角色分配：role_name → 成员 / 团队 Agent，有序） │ └── 流程（Process，属于流程模块）按项目发起；开工 / 评审时把分配结果锁定到流程内

06人员与身份

项规则
登录本期 TeamFlow 自行登录，按账号与用户中心对齐；以后统一用 Keycloak。TeamFlow 不保存密码
建档首次登录时创建 user 记录（id、姓名、邮箱、岗位、头像），之后每次登录刷新这些字段
添加成员团队管理员在团队设置中添加个人或部门（读写）；TeamFlow 带 operator 调用用户中心写入数据权限
角色用户中心里 TeamFlow 的三个角色：平台管理员（模板）、团队管理员（配置团队的项目）、团队成员（处理流程）→ 操作码与菜单，见权限设计
团队数据权限每个团队一条（数据编码 Team + 团队 Id）：读写 = 团队成员（默认）；Owner = 团队管理员
多团队一个人可加入多个团队，各团队中的级别独立
离职用户中心停用后，TeamFlow 标记用户为停用：不能登录，在团队中显示「已停用」；其分配与待办按 §16 处理

07AI Agent 接入

TeamFlow 不创建、不配置 Agent，只引用 Atlas 中已有的 Agent。

团队管理员「添加 Agent」──▶ 拉取 Atlas 已启用的 Agent 列表 ──▶ 选择 ──▶ 保存 team_agent（atlas_agent_id + 快照） │ 后台同步（每 10 分钟 / 打开团队页时）──▶ 读取 Atlas Agent 状态 ──▶ 更新快照与 available
项规则
保存内容atlas_agent_id，以及名称、头像、说明、模型的快照（用于展示；能力以 Atlas 为准）
同一 Agent 多团队允许。不同团队各自引用同一个 Atlas Agent
不可用Atlas 中被停用或删除时，available = false：团队页标「不可用」；担任执行角色的项目在项目首页与设置中提示；新节点开工时若执行 Agent 不可用，节点停在「人机协同中」并提示更换（由流程模块处理）
移出团队若 Agent 担任某项目的执行角色，先列出受影响的角色，确认后从这些分配中移除；进行中节点已锁定的 Agent 不受影响

08项目与角色分配

8.1 绑定流程模板

  • 项目绑定模板 id，跟随模板当前版本；只能绑定已发布、未停用的模板。
  • 需要分配的角色 = 当前版本的 roles（执行角色 + 评审角色，由流程模板模块在发布时推导）。
  • 模板发布新版本后新增的角色，在项目中显示为「未分配」；删除的角色，其历史分配保留但不再显示（换回含该角色的模板时恢复）。
  • 更换模板只影响之后新发起的流程。

8.2 分配约束

角色类型约束不满足时
执行角色至少 1 人 + 恰好 1 个可用的团队 Agent（人下达指令、评审成果；Agent 执行）该行标红：「缺少人」/「缺少 Agent」/「Agent 不可用」
评审角色至少 1 人；P1 只能分配人该行标红：「未分配」
通用被分配者必须是本团队成员 / 团队 Agent；同一人可担任多个角色保存时拒绝

约束不满足不阻止发起流程（团队可能分阶段配置），但项目首页显示一行提示「N 个角色未分配或不完整 · 去配置」，发起流程弹窗中再次提示。

8.3 评审规则与成员数

评审规则在模板中定义（任一人 / 所有人同意），成员在项目中分配。「所有人同意」的人数 = 进入评审时锁定的名单人数（§9）。分配页在评审角色旁显示其涉及节点的规则，帮助判断要不要多分配人。

09分配的生效时机

分配随时可改，但已经开始的事不能被打乱。约定如下（由流程模块执行）：

时机锁定内容之后修改分配的影响
节点开工（进入人机协同中）执行 Agent（启动 Agent 会话）不影响该节点；执行角色中的「人」实时读取，新加入的人可以参与
节点进入待准出准出评审人名单不影响本轮评审；驳回后重新提交时重新锁定
节点进入待准入准入评审人名单同上
尚未开工的节点不锁定使用开工时的最新分配
分配：技术负责人 = 李工 + 刘洋 节点「技术方案」进入待准出 ──▶ 锁定名单 [李工, 刘洋]，规则「所有人同意」，需 2 票 （此时把王五加入技术负责人）──▶ 本轮仍需 2 票；下次提交准出时名单为 [李工, 刘洋, 王五]

10项目首页：处理流程

数据来自流程模块，本模块定义展示与聚合规则。

元素规则
筛选全部 / 待我处理 / 进行中 / 已完成，各带数量；搜索流程名称
排序待我处理 → 进行中 → 已完成；同组内按最近更新时间倒序
待我处理满足任一条件：① 某节点处于待准出 / 待准入，我在锁定名单中且未投票；② 某节点处于人机协同中，我在其执行角色中
每行显示流程名称、状态、「待你审批 / 待你协同 · 节点名」标记；进行中的节点及「等谁」（待投票的评审人，或执行角色中的人）；进度（已通过节点数 / 总数）；缩略流程图；发起人与时间
提示条角色未分配或不完整、执行 Agent 不可用、绑定的模板已停用、项目已归档 —— 各一行，带「去配置」链接
空状态「发起第一个流程」；归档项目不显示发起按钮
分页每页 20 条，滚动加载

14页面设计

以原型为准，补充原型未表达的细节：

  • 项目卡片在上；成员表与 Agent 列表在下

  • 归档放在页面底部「危险操作」区，需二次确认

16异常与边界

场景处理
移除成员阻塞项：在某个锁定的评审名单中且未投票；或是某进行中节点执行角色中唯一的人。有阻塞项时拒绝并列出（P2 提供转交）；无阻塞项时一并移除其角色分配，确认弹窗列出受影响的角色
成员离职（用户中心停用）标记停用；其待投评审在项目首页对团队管理员显示「评审人已停用」，P1 由管理员把该人从角色中移除后，流程模块按剩余名单重新计算（所有人同意的人数随之减少）
Atlas Agent 不可用见 §7；已开工节点继续使用已锁定的会话，能否继续由 Atlas 决定，失败时由流程模块提示人工接管
模板新增角色项目中显示为未分配，首页提示
模板被停用已绑定的项目照常发起流程；项目设置提示「绑定的模板已停用，建议更换」
最后一名团队管理员不能移除或降级（用户中心 Owner 保护，last_admin）
归档项目不能发起流程、不能改分配；进行中的流程照常完成
删除团队 / 项目P1 不提供删除，只提供归档（流程与审计需要可追溯）

17非功能

项要求
规模团队数百级、单团队成员 ≤ 500、Agent ≤ 100、项目 ≤ 200；单项目流程数万级（项目首页分页）
性能团队页、项目设置 P95 < 300 ms；项目首页首屏 P95 < 500 ms（待我处理由流程模块维护的「当前待办」索引支撑，不现场遍历全部流程）

18测试要点

  • 分配约束：执行角色缺人 / 缺 Agent / 多个 Agent / Agent 不可用；评审角色分配 Agent 被拒；非团队成员被拒
  • 生效时机：进入待准出后修改评审角色，本轮人数不变；驳回重提后使用新名单
  • 待我处理：评审人已投票后不再出现；执行角色中的人出现；锁定名单之外的新成员本轮不出现
  • 移除成员：有阻塞项被拒；无阻塞项时连带移除分配；最后一名管理员不可移除
  • Agent 同步：Atlas 停用后标记不可用，项目首页出现提示
  • 更换模板：只影响新流程；新模板角色显示未分配
  • 归档：不能发起流程与改分配；进行中的流程可完成
  • 权限：非成员看不到团队；成员不能管理团队与项目设置

19落地计划

阶段内容
M1用户中心对接（登录、授权快照、团队权限）、团队与成员管理
M2Atlas Agent 接入与状态同步；项目新建、绑定模板、项目设置、角色分配与约束校验
M3与流程模块对接：分配接口与锁定时机、项目首页（列表、筛选、待我处理、提示条）、归档
M4（P2）评审转交、跨项目「我的待办」、评审角色分配 Agent（随自动准出）
