文件模板模块

文件模板是一份带版本的 Markdown 规则文件，写明「某件事该怎么做、做到什么样」。流程中的节点通过选用文件模板，把规则交给 AI Agent：现在用于规定产物的格式与写作要求，未来用于写自动准出的判定规则。模板由平台统一维护、所有团队共用；进行中的节点不受模板更新影响。

只支持 Markdown平台统一定义文件即规则不解析文件内容版本不可变开工即锁定依赖：Atlas AI Agent

01定位与范围

文件模板回答一个问题：「这件事的规则是什么」。它只管规则文件本身，不管某次流程实际产出了什么。

用途说明阶段
产物格式流程模板的节点为自己的产物选用一个文件模板，Agent 按模板产出（如 PRD 编写规范）。P1
自动准出规则节点的准出评审可选用一个文件模板作为判定规则，由 AI 按规则自动判断能否准出。本文只预留引用方式（§9.3），功能由流程模块后续设计。预留
在范围内文件模板的增、改、停用；Markdown 文件上传与版本管理；在线查看与下载；查询被哪些流程模板节点引用；向流程模块提供「该用哪个版本、内容是什么」。
不在范围内不解析文件内容（不提取章节、不做结构化）；流程实例中实际产物的存储与评审（流程模块）；流程模板编排（流程模板模块）；自动准出的判定逻辑（流程模块，未来）；Agent 本身的运行（Atlas）。
设计原则
  1. 文件即规则：规则的唯一来源是上传的 Markdown 文件。平台不解析、不转换，原样交给 Agent 阅读。
  2. 只支持 Markdown：纯文本、可读、可对比，能直接放进 Agent 的指令里（§5.2）。
  3. 模板与用途解耦：文件模板不知道自己被用来规定产物还是判定准出，用途由引用它的地方决定。
  4. 版本不可变：上传即产生新版本，旧版本永不修改，任何产物都能追溯到当时依据的那一版。
  5. 开工即锁定：节点开始执行时锁定当时的生效版本；之后模板再更新，进行中的节点不变。

02术语

术语含义
文件模板一份规则的定义，如「PRD 编写规范」。有名称、说明、图标、用途标签，以及一个生效版本。
模板文件某个版本对应的 Markdown 文件（.md，UTF-8）。
模板版本某次上传形成的不可变快照：Markdown 内容 + 更新说明。版本号 v1、v2… 在同一模板内递增。
生效版本新开工的节点将使用的版本。每个模板最多一个；未上传文件时为空。
锁定版本某个流程节点开工时记录下的版本，该节点之后一直用它。
用途标签产物格式 / 评审规则 / 其他。只用于列表筛选与选择时的提示，不限制模板被用在哪里。
产物流程节点的输出，名称由节点定义。不属于本模块。

05领域模型与状态

FileTemplate（文件模板） 1 ──── * FileTemplateVersion（模板版本，不可变） id, name, icon, description id, template_id, version_no usage: artifact | review_rule | other file_name, content（Markdown）, size_bytes, sha256 status: active | disabled change_note current_version_id ──────────────────▶ uploaded_by, uploaded_at

5.1 模板状态

状态含义可做的操作
active正常。可能还没有生效版本（未上传文件）。上传版本、编辑、停用
disabled停用。流程模板节点不能再新选它；已引用的不受影响。启用、查看、下载

版本没有状态：上传成功即可用，立即成为生效版本。不提供物理删除版本。

5.2 为什么只支持 Markdown、且不解析

考虑结论
Agent 读得懂Markdown 是纯文本，可以直接嵌入 Agent 指令，不依赖 Agent 读取 Word / Excel / PDF 的能力
人读得懂标题、列表、表格都能表达规则，在线查看只需渲染 Markdown
可追溯版本之间可以做文本 diff，看得清规则改了什么
不解析规则的写法多样（产物格式偏「章节 + 要求」，准出规则偏「检查项 + 判定标准」），平台不强加结构，原样交给 Agent
代价已有的 Word / PDF 规范需要先转成 Markdown；平台侧不做「章节覆盖核对」，靠 Agent 自查与人工评审

07文件格式、存储与查看

7.1 文件格式

项规则
扩展名只接受 .md（也接受 .markdown，保存时统一）
编码必须是合法 UTF-8；含 BOM 时去掉；含 NUL 字节视为二进制文件拒绝
大小1 字节 ～ 100 KB。理由：内容要整段放进 Agent 指令（§9.1），过大会挤占上下文；规则写到 100 KB 以上通常也说明需要拆分
内容不校验 Markdown 语法（任何文本都是合法 Markdown）；不允许为空白

7.2 存储

Markdown 体积小，直接存数据库（file_template_version.content），不使用对象存储：

  • 上传：浏览器以 multipart/form-data 直接提交到「上传新版本」接口，服务端校验后与版本行同事务写入。
  • 下载：服务端直接返回内容，Content-Type: text/markdown; charset=utf-8，Content-Disposition: attachment。
  • 不可变：版本行只插入不更新；数据库账号对该表不授予 UPDATE / DELETE（或由触发器拒绝）。

7.3 在线查看

项规则
渲染前端渲染 Markdown（支持标题、列表、表格、代码块、引用）；可切换查看源码
安全白名单渲染：不渲染原始 HTML、不执行脚本、不加载外链图片；链接强制新窗口打开并带 noopener
历史版本版本历史中点击任一版本即可查看其内容

08版本规则

规则说明
版本号同一模板内从 v1 递增
生效版本上传成功即成为生效版本，旧版本进入历史
锁定流程节点开工（进入「人机协同中」）时锁定生效版本；被驳回回到本节点修改时不重新锁定，同一节点前后只用一套规则
打回到更早阶段被打回的上游节点沿用它原来锁定的版本
流程模板的引用只存模板 id，跟随生效版本；流程模板不需要因文件模板升级而重新发布
时间轴： v2 生效 ─────────── v3 生效（上传新版本）──────────────▶ 节点 A： 开工锁定 v2 ─── 执行 ─── 驳回 ─── 修改（仍是 v2）─── 通过 节点 B： 开工锁定 v3 ─── 执行 ─── 通过

09在流程中的使用

本模块只提供「锁定哪个版本」和「内容是什么」。如何交给 Agent、如何展示，由流程模块实现；这里约定接口与行为。

9.1 产物格式：交给执行 Agent

节点开工 ──▶ resolve(模板 id) 得到生效版本 ──▶ 锁定到 process_node │ 启动 Agent 会话 ◀── content(锁定版本) 取 Markdown 原文 · 原文直接嵌入给 Agent 的指令（不走附件） · 指令写明：按「{模板名} v{n}」的结构与要求产出
# 流程模块给 Agent 的指令片段（示例）
你在本节点要产出「PRD」。下面是本产物的文件模板《PRD 编写规范》v3，
请严格按它的结构与要求产出；某部分确实不适用时写「不适用：原因」。产出后对照模板自查一遍再提交。

<file-template name="PRD 编写规范" version="3">
{模板 Markdown 原文}
</file-template>
规则说明
嵌入方式原文放在定界标签中，与指令的其他部分分开；原文中若出现相同的结束标签，由流程模块转义
没有生效版本指令中写明「该产物暂无文件模板，按通用结构产出」；节点页提示
自查靠指令要求 Agent 对照模板自查；平台不做章节核对（不解析文件）

9.2 评审：展示依据版本

准出 / 准入评审时，产物旁显示「依据：PRD 编写规范 v3」，可展开查看模板内容。若模板已有更新的生效版本，提示「模板已更新到 v4，本节点按 v3 执行」。

9.3 自动准出规则（预留）

未来节点可配置「自动准出」：选用一个文件模板（通常用途为评审规则）写明判定标准，节点提交准出时由 AI 读取「规则 + 产物」给出通过 / 不通过与理由。本模块为此需要的准备：

  • 引用方式与产物格式相同：流程模板存 id，节点开工时锁定版本（§6.3 预留字段）。
  • 规则同样是 Markdown，能以同样方式嵌入判定用的 Agent 指令。
  • 用途标签 review_rule 便于在配置自动准出时筛选；「引用该模板的节点」区分引用方式。

判定由谁执行、结果如何与人工评审组合，属于流程模块的设计，不在本文范围。

11权限

操作码能做什么
file_template:view只读：列表、详情、在线查看、下载、查看引用（三个角色）
file_template:manage新建、编辑、上传版本、停用 / 启用、删除（平台管理员）

文件模板是平台级资产、所有团队共用。操作码登记在用户中心，由角色授予：平台管理员管理，团队管理员与团队成员只读，见权限设计。准出规则直接影响流程能否推进，写操作只给少数人。

12页面设计

以原型 #/file-templates 为准。

列表页 #/file-templates

  • 筛选：全部 / 产物格式 / 评审规则 / 其他；可显示已停用
  • 排序：未上传文件的排前，其余按更新时间倒序
  • 卡片：图标、名称、用途标签、说明、文件（名称 / 大小 / 版本）、被引用节点数、更新日期
  • 停用的置灰并标「已停用」；非管理员不显示「新建文件模板」

详情页 #/file-templates/:id

  • 模板文件卡：文件名、大小、上传人、时间、更新说明、生效版本；「下载」「上传新版本」
  • 内容区：渲染后的 Markdown，可切换「渲染 / 源码」
  • 右侧：版本历史（点击切换查看历史版本）、引用该模板的节点（标明产物格式 / 准出规则）

上传新版本弹窗

字段规则
文件拖放或选择，只接受 .md；前端先校验扩展名与大小（≤ 100 KB），以服务端校验为准；选中后显示内容预览，确认无误再提交
更新说明必填，≤ 500 字
影响提示「上传后，新开工的节点使用新版本；进行中的 N 个节点继续使用 v3」—— N 来自流程模块的统计

流程模板节点配置中的选择器

节点「产物」处选择文件模板：默认只列用途为「产物格式」的，可切换显示全部；列表显示生效版本或「未上传模板文件」；已停用的不可选。

13审计

写操作与业务数据同事务写入 TeamFlow 全局审计表 audit_log，本模块只定义事件。

事件记录内容

file_template.updated变更前后字段
file_template.version_uploaded版本号、文件名、大小、sha256、更新说明；旧生效版本 → 新生效版本

14异常与边界

场景处理
两人同时上传新版本上传时校验 row_version，后到的返回 stale_row_version，不建版本；提示刷新后决定是否重新上传
节点开工时模板没有生效版本锁定为 NULL，Agent 按通用结构产出；节点页与评审页提示「暂无文件模板」
节点开工时模板已停用仍锁定其生效版本并正常执行（停用只阻止新选用）；流程模板页提示该节点引用了已停用的模板
删除存在任何流程模板节点引用，或任何流程节点锁定过它的版本 → 409 template_in_use，引导改为停用
上传非 .md / 非 UTF-8 / 超大 / 空文件分别返回 unsupported_file_type / invalid_encoding / file_too_large / empty_content，弹窗内就地提示
模板中含有类似「忽略以上要求」的文字模板由平台管理员维护，视为可信规则；嵌入时用定界标签与指令其他部分隔开（§9.1），降低误读

15非功能

项要求
规模模板数百级、单模板版本数十级；单版本 ≤ 100 KB，总量在 MB 级，数据库存储无压力；列表不分页，版本历史分页（每页 20）
性能列表 / 详情 P95 < 300 ms；resolve P95 < 50 ms（可缓存，按 row_version 失效）；content P95 < 50 ms（版本不可变，可长期缓存）
可用性只依赖数据库，没有额外的外部存储依赖
安全只接受 UTF-8 文本；在线查看白名单渲染，不渲染原始 HTML、不加载外链资源

16测试要点

  • 上传 → 立即成为生效版本；版本号递增；相同内容拒绝
  • 格式校验：非 .md、改了扩展名的二进制文件、GBK 编码、带 BOM、超过 100 KB、空文件、只有空白
  • 并发上传：只有一个成功，另一个返回 stale_row_version
  • 节点开工锁定版本；之后上传新版本，该节点（含驳回后修改、被打回）仍用旧版本；新开工节点用新版本
  • 在线查看：Markdown 中的 HTML、脚本、外链图片不被执行或加载
  • content 接口返回的原文与上传文件逐字节一致（BOM 除外）
  • 删除保护：被引用 / 被锁定过的不可删；停用后不可新选、已引用的照常执行
  • 权限：非管理员调用写接口返回 403；内部接口不带令牌返回 401

17落地计划

阶段内容
M1表结构；新建 / 编辑 / 列表 / 详情；上传新版本与格式校验；下载；版本历史；停用 / 启用；Markdown 在线查看
M2被引用节点查询；与流程模块对接 resolve、锁定版本、content 接口；评审页展示依据版本
M3（P2）版本对比、回退生效版本、在线编辑；配合流程模块的自动准出启用 exit_rule_file_template_id
