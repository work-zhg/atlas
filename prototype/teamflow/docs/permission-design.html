AI TeamFlow · Detailed Design

权限设计：角色、操作与数据权限

TeamFlow 不自建账号与权限体系：人员、角色、操作码、菜单、数据权限都在用户中心维护，TeamFlow 作为接入应用，在服务端调用用户中心开放接口取得结果并执行。TeamFlow 只有三个角色：平台管理员管模板，团队管理员配置团队的项目，团队成员处理流程。每个团队对应一条数据权限（数据编码 Team + 团队 Id）：团队成员默认读写，团队管理员是 Owner。

三个角色一个团队一条数据权限成员 = 读写团队管理员 = Owner节点分工 = 流程角色分配

01定位与范围

本文负责

  • TeamFlow 在用户中心登记的角色、操作目录、菜单、数据编码
  • 角色、团队数据权限、流程角色分配三者如何组合判定（第 09 节矩阵）
  • 团队成员与团队管理员的维护方式
  • TeamFlow 侧的执行方式，以及对用户中心开放接口的新增需求

不在本文

  • 用户中心自身的授权模型 → 用户中心 · 权限管理
  • 流程角色（模板里的执行角色 / 评审角色）的定义与分配规则 → 流程模板、团队管理
  • 登录：本期 TeamFlow 自行登录、按账号与用户中心对齐；以后统一用 Keycloak

02术语

术语含义
角色用户中心里 TeamFlow 应用的角色：平台管理员、团队管理员、团队成员。= 一组操作码 + 菜单，决定能做哪一类事。
流程角色流程模板里的执行角色 / 评审角色（如「架构设计」「技术评审」），在项目里分配给成员与 Agent，决定流程中谁做、谁审。原文档称「角色」，统一改称「流程角色」。
团队数据权限用户中心的一条数据：数据编码 Team、数据 Id = 团队 Id、数据名称 = 团队名称。决定在哪个团队里做。
团队成员对该团队有读写（及以上）的人，可直接授予或经部门获得；另加团队接入的 Agent。
团队管理员对该团队有 Owner 的人。

03权限模型

① 角色（能做哪一类事）
  • 平台管理员：模板
  • 团队管理员：配置团队与项目
  • 团队成员：处理流程
  • 用户中心 · 角色授权
② 团队数据权限（在哪个团队做）
  • 一个团队一条：Team + 团队 Id
  • 成员 = 读写，团队管理员 = Owner
  • 用户中心 · 数据授权
③ 流程角色分配（节点谁做谁审）
  • 项目里「流程角色 → 成员 / Agent」
  • TeamFlow 自己维护
判定规则允许 = 角色的操作码 ∧ 团队级别 ∧ 流程角色（仅节点动作）。团队管理员类操作要求对该团队 Owner；团队成员类操作要求对该团队 读写；平台管理员类操作不看团队。例如：李工有「团队管理员」角色，但只对「交易中台」是 Owner，他就只能配置交易中台的项目。
层在哪里维护变更生效
角色用户中心 · 角色授权授权快照刷新后（≤ 5 分钟）
团队数据权限TeamFlow 团队设置（调用用户中心）最长 30 秒（第 10 节）
流程角色分配TeamFlow 项目设置按锁定规则（节点开工 / 评审开始时锁定）

04角色

角色（编码）负责需要的团队级别建议授予
平台管理员
TF_PLATFORM_ADMIN		配置流程模板与文件模板；新建团队并指定团队管理员；调整任意团队的管理员；系统设置不需要平台负责人（个人）
团队管理员
TF_TEAM_ADMIN		配置团队的项目（新建、绑定流程模板、流程角色分配、归档）；管理团队成员与 Agent；编辑团队信息对该团队 Owner各团队负责人（个人或岗位，如「技术负责人」）
团队成员
TF_TEAM_MEMBER		处理流程：发起、节点协同、准入 / 准出评审对该团队读写全员：授予根部门（含下级）。能进哪个团队由团队数据权限决定
  • 角色可以叠加：团队管理员通常也是团队成员（同时有两个角色、对团队是 Owner），既能配置项目也能处理流程。
  • 「团队成员」角色授予全员不会放大权限：没有某个团队的读写，就进不了那个团队。
  • 能登录 TeamFlow 的人由应用的可访问范围决定。

📋 待我处理（todo）/todo团队成员
👥 团队（teams）/teams公共菜单：人人可见，列表只含我有数据权限的团队（平台管理员看全部）

07团队数据权限

每个团队对应一条数据权限：在用户中心「应用接入 → AI TeamFlow → 数据编码」登记一次数据编码 Team（团队），每个团队是其中的一条数据（数据 Id = 团队 Id，数据名称 = 团队名称）。不为每个团队单独登记数据编码 —— 数据编码表示「一类数据」，团队增减不需要改用户中心的登记。

级别谁含义
读写团队成员团队成员默认的级别：可以查看团队的项目与流程、处理流程（配合「团队成员」角色）
Owner团队管理员可以配置团队与项目、管理成员（配合「团队管理员」角色）；Owner 也包含读写
只读—本期不使用（以后若需要「观察者」再启用）
  • 授予对象可以是个人，也可以是部门（含下级）：例如把「交易中台」团队的读写授予「研发中心 / 交易中台（含下级）」，部门新人自动成为团队成员。
  • 项目、流程、产物继承所属团队的权限，不再单独设数据权限；流程模板、文件模板是平台资产，只看角色。
  • 团队 Agent 不是用户中心的用户，仍由 TeamFlow 的团队 Agent 表维护。

08团队成员与管理员的维护

动作谁TeamFlow 调用用户中心
新建团队、指定团队管理员平台管理员（team:create）建团队后一次写入：指定的管理员 = Owner（可多人），可同时写入初始成员 = 读写
添加成员（个人或部门）团队管理员（team:member + Owner）写入读写，带 operator = 当前用户
设为 / 取消团队管理员团队管理员级别改为 Owner / 读写（用户中心保证至少一名可用 Owner）
移除成员团队管理员删除该授权
调整任意团队的管理员平台管理员（team:manage_all）以「数据管理员」身份修改（需用户中心新增能力，第 11 节）—— 用于团队管理员全部离职等情况
团队改名团队管理员（team:edit）同步数据名称

角色与级别的一致性

  • 指定某人为团队管理员时，TeamFlow 检查他是否有「团队管理员」角色；没有则提示「该用户还没有团队管理员角色，请在用户中心授予」—— 只有 Owner 没有角色，他进团队后看不到配置按钮。
  • 「团队成员」角色建议授予全员，所以添加成员时一般不用再授角色；若某人没有该角色，同样提示。
  • TeamFlow 不替用户中心授角色：角色只有一个来源。

成员列表与候选人

团队成员列表、项目里流程角色分配的候选人 = 用户中心中对该团队有读写及以上的人（展开部门）+ 团队 Agent。某人被移出团队或停用后，已分配给他的流程角色保留但不可执行，项目设置中标红提示团队管理员改派。

10TeamFlow 侧的执行

环节做法
登录后按账号查用户中心用户（不存在 / 已停用 → 拒绝）；取授权快照（can_access 为假 → 拒绝），roles / permissions / menus 存入会话，最长缓存 5 分钟
操作码后端 require_op("project:configure") 读会话；配置流程模板、系统设置等敏感操作走用户中心实时校验
团队级别require_team(team_id, "OWNER" | "WRITE")：调用 GET /open/v1/data-permissions/check?data_code=Team&data_id=…，进程内缓存 30 秒（P1 订阅 Webhook 即时失效）；有 team:manage_all 时团队查看放行
团队列表GET /open/v1/data-permissions/accessible?data_code=Team&min=WRITE 得到团队 Id，再查 TeamFlow 库；平台管理员看全部
流程角色TeamFlow 本地判定（分配表 + 锁定名单）
用户中心不可用缓存有效期内放行只读请求；写请求与新登录失败并提示稍后重试

示例：配置项目

PUT /api/projects/{id}/roles/{role}      // 流程角色分配
  1. require_op("project:configure")                       // 有「团队管理员」角色
  2. require_team(project.team_id, "OWNER")                // 是这个团队的管理员
  3. 校验被分配的人对该团队 ≥ 读写（或是团队 Agent）
  4. 保存分配

13审计

  • 角色授予、团队成员与级别变更由用户中心记录（TeamFlow 代表用户写入的，记录为「应用 + operator」）。
  • TeamFlow 记录业务动作：建团队、项目设置、流程角色分配、发起 / 终止流程、评审投票、模板发布。

14异常与边界

场景处理
有「团队管理员」角色但不是该团队 Owner能进入（若是成员），看不到配置按钮
是团队 Owner 但没有「团队管理员」角色看不到配置按钮；团队设置页对平台管理员提示「管理员缺少角色」
团队管理员全部离职用户中心标「无可用 Owner」；平台管理员用 team:manage_all 指定新管理员
成员被移出团队，仍有进行中节点或待投评审分配保留但不可执行；项目设置标红提示改派
新建团队时写入用户中心失败回滚团队，提示重试
用户不在 TeamFlow 可访问范围，却是某团队成员不能进入 TeamFlow；成员列表中标「不可访问 TeamFlow」

15测试要点

  • 判定矩阵逐行：缺操作码、缺团队级别、缺流程角色分别被拒。
  • 团队管理员只能配置自己是 Owner 的团队；平台管理员不是 Owner 也能调整管理员（team:manage_all）。
  • 团队成员级别来源：直接授予、部门授予（含 / 不含下级）。
  • 新建团队：多名管理员一次写入；写入失败时团队回滚。
  • 移除最后一名团队管理员被拒（用户中心 Owner 保护）。
  • 菜单：团队成员只有待我处理、团队、文件模板；团队管理员多流程模板；平台管理员多系统设置。

17待确认

  1. 新建团队：本文由平台管理员新建并指定团队管理员。是否也允许团队管理员角色的人自己建团队？
  2. 团队成员角色授予全员（建议）还是只授予实际参与流程的人？
  3. 团队管理员是否默认也处理流程：本文靠叠加两个角色实现；是否改为「团队管理员」角色直接包含流程处理的操作码？
  4. 平台管理员调整任意团队管理员依赖用户中心新增「数据管理员操作码」能力，是否认可这个做法？
