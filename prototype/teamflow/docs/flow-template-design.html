流程模板模块

流程模板定义一类工作「怎么做」：有哪些节点、谁执行（执行角色）、产出什么（产物与文件模板）、谁把关（准出 / 准入评审角色与规则），以及节点之间的先后与并行。模板只写角色，不写人；由项目把角色分配给团队里的人和 AI Agent。模板有版本，发布后不可修改；进行中的流程不受模板修改影响。

步骤序列 + 并行轨道节点一律人机协同角色而非人草稿 → 发布版本流程发起即锁定版本

01定位与范围

在范围内流程模板的新建、复制、停用；流程结构编辑（节点、并行组、轨道）；节点配置（执行角色、产物、文件模板、准出 / 准入评审）；草稿与版本发布；版本历史；角色库；查询被哪些项目绑定；向项目与流程模块提供「当前版本的定义」。
不在范围内流程实例的运行与状态流转、审批投票（流程模块）；角色分配给人和 Agent（项目模块）；文件模板本身（文件模板模块）；Agent 的运行（Atlas）。
设计原则
  1. 结构简单、语义确定：流程是步骤序列，步骤可以是并行组；不做任意连线，节点依赖由结构推导。
  2. 模板描述规则，项目落实到人：模板里只有角色名称，同一模板可被多个团队、多个项目复用。
  3. 版本不可变：编辑只改草稿，发布生成新版本；已发布版本永不修改。
  4. 发起即锁定：流程发起时锁定模板当前版本，之后模板再发布新版本，进行中的流程不变。

02术语

术语含义
流程模板一类工作的定义，如「研发流程模板」。有名称、图标、说明、适用范围，以及一个当前版本。
模板版本某次发布形成的不可变定义（流程结构 + 全部节点配置），版本号如 v1.3。
草稿正在编辑、尚未发布的定义。每个模板最多一份。
步骤流程结构的一级元素：单个节点，或并行组。步骤按顺序执行。
并行组 / 轨道并行组包含 ≥ 2 条轨道，每条轨道是一串顺序执行的节点。各轨道同时开工，全部完成后汇合进入下一步骤。
节点一项人机协同的工作单元，产出一份产物，经准出、准入评审后完成。
执行角色完成节点的角色（如「架构设计」）；项目为它分配人与 AI Agent，人下达指令、Agent 执行。
评审角色负责准出或准入评审的角色（如「技术负责人」）。
准出 / 准入准出：产出方把关产物质量；准入：下游把关产物能否作为输入。准入可选。
评审规则any 任一人同意即通过；all 角色下所有成员都同意才通过。任一人驳回即退回。

05流程结构模型

5.1 结构

流程是步骤序列；步骤是单个节点或并行组；并行组由 ≥ 2 条轨道组成，每条轨道是 ≥ 1 个节点的序列。不支持嵌套并行。

需求澄清
PRD
并行组
轨道 A
技术方案
编码
轨道 B
测试用例设计
测试执行
发布上线
// 定义（JSON）中的结构部分，对应上图
"flow": [
  { "type": "node", "id": "clarify" },
  { "type": "node", "id": "prd" },
  { "type": "parallel", "tracks": [
      { "nodes": ["tech", "code"] },
      { "nodes": ["testcase"] } ] },
  { "type": "node", "id": "testexec" },
  { "type": "node", "id": "release" }
]

5.2 运行语义（由结构推导依赖）

位置上游（依赖）
第一个步骤的节点无，流程发起即开工
单节点步骤上一步骤的全部「出口」：上一步是节点 → 该节点；上一步是并行组 → 每条轨道的最后一个节点（汇合）
轨道中的第一个节点上一步骤的全部出口（各轨道同时开工）
轨道中的后续节点同一轨道中的前一个节点

上例推导结果：tech、testcase 都依赖 prd；code 依赖 tech；testexec 依赖 code 与 testcase。节点在依赖全部通过后自动开工，「上游产物就绪即可开工」由此实现。

5.3 结构规范化

每次结构编辑后自动规范化，保证结构始终合法：

  • 空轨道删除；
  • 只剩 1 条轨道的并行组，退化为该轨道节点的顺序步骤；
  • 没有轨道的并行组删除；
  • 流程至少保留 1 个节点（删除最后一个节点被拒绝）。

5.4 为什么不做任意连线

考虑结论
编辑成本插入 / 新增轨道即可表达常见的顺序与并行，不需要拖线，非技术用户也能上手
运行语义开工与汇合规则唯一确定，不会出现环、悬空节点、无法汇合等需要额外校验的情况
代价不能表达嵌套并行、跨轨道依赖（如 B 轨道某节点依赖 A 轨道中间节点）、条件分支；列入待确认（§20）

06节点模型

字段必填说明
id是模板内唯一，创建时生成，之后不变（流程实例按它记录节点状态）
name是节点名称，模板内唯一，≤ 32 字
exec_role是执行角色。执行方式固定为人机协同：该角色下的人下达指令、评审成果，Agent 执行并产出
output_name是产物名称（如「技术方案」），模板内唯一；下游节点的「输入产物」即上游的产物名称
artifact_file_template_id否产物格式所依据的文件模板；为空时 Agent 按通用格式产出
exit_review是{ "role": "技术负责人", "rule": "all" }：准出评审角色与规则
admit_review否{ "role": "测试负责人", "rule": "any" } 或 null：准入评审；为空则准出通过即完成
exit_rule_file_template_id否预留 自动准出的规则文件
exit_mode否预留 manual（默认）/ auto / auto_then_manual

6.1 节点生命周期（由流程模块实现，本模块定义语义）

人机协同中 ──提交准出──▶ 待准出 ──准出规则满足──▶ 待准入 ──准入规则满足──▶ 已通过 ──▶ 下游依赖全部通过的节点开工 │ 任一人驳回 │ 任一人驳回 ▲ └──▶ 回到本节点修改，或打回到更早的节点 ◀──┘ │ 未配置准入时，准出通过即「已通过」
规则说明
any 任一人同意评审角色中有 1 人同意即通过
all 所有人同意评审角色中每个成员都同意才通过（成员数在项目中决定）
驳回任一评审人驳回即退回；本阶段已有的同意记录清空
输入产物由结构推导：节点的上游节点的产物名称；不单独配置

07版本与草稿

┌───────── 编辑（自动保存）─────────┐ 当前版本 v1.3 ──「编辑流程」──▶ 草稿 ──「发布」（校验通过）──▶ 当前版本 v1.4（v1.3 进入历史） └──「放弃修改」──▶ 删除草稿
规则说明
版本号v{主}.{次}。每次发布次版本 +1；主版本 P1 不提供手动升级（新建模板从 v1.0 开始）
不可变已发布版本的定义只读；所有修改都通过草稿 → 发布完成
草稿数量每个模板同一时间最多一份草稿；草稿记录编辑人
并发编辑他人打开时显示「张明 正在编辑草稿（10 分钟前）」，可只读查看或「接管编辑」；保存草稿带 row_version，冲突时提示刷新
草稿基线草稿记录创建时基于的版本；发布时若当前版本已变化（他人先发布），要求在新版本基础上重新编辑
历史版本可查看；P1 不提供「回滚」，需要时在草稿中改回后发布

09发布校验

草稿编辑过程中实时提示；发布时执行完整校验，错误阻止发布，警告可确认后发布。

级别规则
错误至少 1 个节点；结构合法（并行组 ≥ 2 条轨道、每条轨道 ≥ 1 个节点、无嵌套并行）
错误节点 id、节点名称、产物名称在模板内唯一
错误每个节点有执行角色、产物名称、准出评审（角色 + 规则）；准入评审若配置则角色与规则齐全
错误引用的文件模板存在且未停用
警告引用的文件模板没有生效版本（节点将按通用格式产出）
警告有下游的节点未配置准入评审
警告本次发布新增了角色：绑定该模板的 N 个项目需补充分配
错误更新说明为空

10编辑交互

10.1 结构编辑（编辑态）

操作位置与效果
插入节点任意两个步骤之间、首尾的「＋」→「插入节点」：新增一个顺序节点并选中，下方配置名称等
插入并行轨道同一「＋」→「插入并行轨道」：新增一个含 2 条轨道（各 1 个节点）的并行组
新增轨道并行组右上「＋ 新增轨道」：追加一条含 1 个节点的轨道
轨道内新增节点轨道末尾「＋ 节点」：在该轨道末尾追加节点
删除节点悬停节点右上「×」；之后按 §5.3 规范化
删除轨道轨道右侧「删除轨道」：删除该轨道及其节点；之后规范化

10.2 节点配置面板

字段控件
节点名称 / 产物名称输入框，失焦保存
执行方式只读展示「人机协同」
执行角色角色库下拉 + 「或输入新角色名」
文件模板下拉，默认只列用途为「产物格式」的文件模板，显示生效版本或「未上传文件」；可选「不使用」
输入产物只读，由结构推导
准出评审角色下拉 + 规则（任一人同意 / 所有人同意）
准入评审开关「需要准入」+ 角色下拉 + 规则

10.3 保存

每次结构或配置变化后防抖 1 秒保存草稿；顶部显示「草稿已保存 · 刚刚」。离开页面不丢失，下次进入继续编辑。

10.4 发布弹窗

  • 新版本号（如 v1.4）、更新说明（必填）；
  • 校验结果：错误列表（不可发布）、警告列表（需勾选「已知晓」）；
  • 影响：「绑定该模板的 3 个项目，新发起的流程将使用 v1.4；进行中的 6 个流程仍按原版本执行」；新增角色时列出需补充分配的项目。

11与项目、流程的衔接

场景行为
项目绑定项目存模板 id，跟随当前版本；只能绑定已发布、未停用的模板
角色分配项目设置读取当前版本的 roles，为每个角色分配人和 Agent；模板发布新版本后新增的角色在项目中显示为「未分配」
发起流程流程记录 flow_template_version_id，之后完全按该版本定义运行；模板再发布不影响
节点开工流程模块按版本定义取节点的执行角色、文件模板 id 等；文件模板版本在此时锁定（见文件模板设计）
项目更换模板只影响之后新发起的流程

validation_failed422发布校验有错误，返回错误列表
warnings_not_acknowledged422存在警告未确认
template_in_use409被项目绑定过，不能删除

13权限

操作码能做什么
flow_template:view只读：列表、查看任一版本、查看绑定项目（平台管理员、团队管理员）
flow_template:manage新建、复制、编辑草稿、发布、停用 / 启用、删除；维护流程角色库（平台管理员）
内部服务读取版本定义

操作码登记在用户中心，由角色授予：平台管理员配置，团队管理员只读（绑定项目时选择），见权限设计。流程模板是「组织规范」，团队自建模板列入待确认（§20）。

以原型 #/templates、#/templates/:id 为准，补充原型未表达的细节：

  • 卡片显示「有未发布的草稿」角标（仅管理员可见）
  • 停用的模板置灰并标「已停用」

  • 编辑态：顶部草稿条「草稿已保存 · 刚刚」「放弃修改」「发布」；校验错误数以红点标在「发布」上
  • 节点卡片上有校验错误时红框提示，点开配置面板定位到字段
  • 右侧（或下方）：版本历史、绑定的项目

15审计

事件记录内容
flow_template.created名称、是否复制自某模板
flow_template.updated基本信息变更前后
flow_template.draft_created / draft_discarded / draft_taken_over编辑人

草稿的每次保存不记审计（频繁且未生效），发布时记录与上一版本的差异摘要。

16异常与边界

场景处理
两人同时编辑后来者看到「正在编辑」提示，可只读或接管；接管后原编辑人保存时收到 draft_locked
编辑期间他人发布了新版本发布时返回 base_version_outdated；草稿保留，提示对照新版本重新调整（P2 提供合并辅助）
删除了有进行中流程的节点不影响：进行中的流程使用发起时锁定的版本
新版本新增了角色绑定的项目显示「N 个角色未分配」；新发起的流程走到相应节点时无人协同 / 审批，项目首页已有提示
停用模板不能被新项目绑定；已绑定的项目照常发起流程，项目设置中提示「绑定的模板已停用」
删除模板只允许从未被项目绑定的模板；否则引导停用
引用的文件模板被停用已发布版本不受影响（照常运行）；下次发布校验报错，需更换
节点改名节点 id 不变，进行中流程不受影响；历史流程显示其版本中的旧名称

17非功能

项要求
规模模板数十至数百；单模板 ≤ 50 个节点、并行组 ≤ 8 条轨道；定义 JSON ≤ 256 KB
性能详情 P95 < 300 ms；草稿保存 P95 < 200 ms；内部读取版本定义 P95 < 50 ms（版本不可变，可长期缓存）
一致性发布（生成版本 + 切换当前版本 + 删除草稿 + 角色入库 + 审计）在同一事务中完成

18测试要点

  • 依赖推导：顺序、并行开工、多节点轨道、汇合到下一节点、首尾为并行组
  • 规范化：删空轨道、删到只剩 1 条轨道退化、删除最后一个节点被拒
  • 发布校验：每条错误 / 警告规则各一组用例；警告未确认时拒绝发布
  • 版本不可变：发布后修改草稿不影响已发布版本；进行中流程使用锁定版本
  • 并发：两人编辑、接管、row_version 冲突、base_version_outdated
  • 新增角色发布后，绑定项目显示未分配
  • 复制模板：复制的是当前版本，生成独立的新模板
  • 权限：非管理员无法创建草稿与发布

19落地计划

阶段内容
M1数据模型、定义 JSON 与依赖推导、角色库、列表 / 详情（只读）、内置模板种子数据
M2草稿编辑（结构编辑、节点配置、自动保存）、发布校验、发布、版本历史
M3与项目对接（绑定、角色推导、新增角色提示）、与流程对接（发起锁定版本、内部读取接口）
M4（P2）版本对比、自动准出配置（配合流程模块与文件模板）
