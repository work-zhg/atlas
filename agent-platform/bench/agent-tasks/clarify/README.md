# clarify：需求澄清（doc/ask-user-question-design.html §12）

同一个需求写两遍：**一句话的模糊题**（tag `ambiguous`）和**写清楚的清晰题**（tag `clear`）。
每题都带模拟用户（`user.brief`：用户心里的完整需求，Agent 看不到）—— Agent 用 `ask_user_question`
提问时，由评测侧的模型（实验配置的 `user_model`）只依据它作答。

| 目录 | 模糊题的指令 | 隐藏的要点（校验看产出里有没有） |
|---|---|---|
| workflow-* | 做个工作流的原型 | 工单、转派、催办（不是审批流） |
| dashboard-* | 帮我做一个数据看板原型 | 客流、坪效、复购（门店运营，不是销售） |
| collab-* | 设计一个团队协作平台的原型 | 素材、批注、版本（设计评审，不是任务看板） |

报告的「需求澄清」一节按 tag 汇总：模糊题的**提问率**与成功率、清晰题的**误问率**与成功率。
模糊题不问也可能碰巧猜对，所以看的是两个比例，不只是成功率。
