0. 方案概览

一句话：CLI 智能体多一个「运行位置」，可以是平台的会话 Pod，也可以是使用者自己的电脑。电脑上装一个连接器，由它主动连到平台的设备网关，并一直保持连接；平台有事就通过这条连接找到电脑。平台和 bridge 之间的协议、审批、断线续传都和会话 Pod 一样，网关和连接器只负责转发。CLI 访问模型、MCP、知识库时，真实凭据由设备网关持有，电脑上只有一个会话令牌。网页上可以只读查看本机工作目录里的文件，文件在打开时才现读，不同步到平台。

打个比方：你住在酒店房间里，外面的人打不进你的房间，因为房间没有直拨号码（电脑在路由器、防火墙后面）。但你可以主动打给前台并一直不挂（连接器连出），前台有人找你，就通过这条线转给你（设备网关）。你要订餐时也打给前台，由前台用酒店的账户付钱（凭据代持）。酒店的信用卡始终不交到你手上。

图 1　方案总览：电脑只往外连；平台通过这条连接找到电脑，CLI 经设备网关使用平台能力

1. 背景与目标

1.1 为什么需要

现在 CLI 智能体只能跑在平台的会话 Pod 里。很多工作更适合在自己电脑上做：

  • 项目代码和数据在本机，或者在只有本机能访问的公司内网里，不方便、也不应该上传到平台；
  • 本机已经有现成的开发环境：装好的依赖、本地数据库、模拟器、访问内网服务的权限；
  • 有些人已经有自己的 CLI 订阅账号。

同时，用户仍然希望用平台提供的东西：在网页上对话和审批、平台的模型、MCP、知识集，以及对话记录。

1.2 目标

  • CLI 跑在使用者自己的电脑上，在网页上对话、审批，体验和会话 Pod 里的 CLI 智能体一样。
  • 电脑在哪都能用，家里、公司、外面都可以，只要能访问平台的 HTTPS 入口。不需要开端口、装 VPN，也不需要管理员权限。
  • 平台的 Key 不落到个人电脑上。
  • 只有本人能让自己的电脑干活。电脑主人在本机能看到、能限制，也能随时停止。
  • 网页上能只读查看本机工作目录里的文件。

1.3 不做什么

  • 不做隔离：CLI 以电脑主人的身份直接操作电脑，这本来就是这类智能体的用途。建会话时界面上会明确提示。
  • 不把本机文件同步或快照到平台：电脑离线时看不到文件（理由见 5.5）。
  • 不从网页往电脑里写：不支持上传、删除、改名。
  • 不同步技能，不注入出站凭据：CLI 用电脑上本人的配置和凭据（git、ssh 等）。
  • 首版只支持 macOS 和 Linux，Windows 用户可以在 WSL 里用。

2. 智能体、设备与会话

2.1 运行位置与默认项目地址

CLI 智能体多一个属性「运行位置」，取值是会话 Pod或用户设备。它和 CLI 类型、镜像一样，建智能体时定下，之后不能改：换运行位置等于换掉整套运行环境，原地改会改变已有会话的行为。界面上，运行位置为用户设备的 CLI 智能体作为第三种类型「本机 CLI」展示。这类智能体没有镜像，用的是电脑上装好的 CLI。

本机 CLI 智能体还要配一个默认项目地址，比如 ~/atlas-projects，其中 ~ 表示电脑主人的主目录，在每台电脑上各自展开。会话的项目目录默认是「默认项目地址 / 会话 id」，是一个新的空目录。被委派时没人选目录，就用这个规则（2.6）。默认项目地址可以改，改了只影响之后新建的会话：已有会话的目录在建会话时就定下了。

本机 CLI 智能体可以共享给别人用，但每个人用时都只跑在自己的电脑上，项目目录也建在自己的电脑上。

2.2 设备

  • 设备只属于一个人，一个人可以有多台。状态有三种：在线、离线、已吊销。
  • 每个人有一台默认设备：第一台配对的设备自动成为默认，之后可以在「我的设备」里换；吊销的正好是默认设备时，改成剩下设备里最近连过的一台。被委派时用这台（2.6）。
  • 在网页的「我的设备」里管理：配对新设备、改名、设为默认、查看在线状态和连接器版本、吊销。
  • 连接器连上平台时，报告这台电脑的系统、连接器版本、装了哪些 CLI（含版本），以及本机允许平台使用的工作目录。

2.3 会话

  • 新建会话时选设备和工作目录。设备只列出自己的、在线的、装了这个智能体所用 CLI 的，默认选中默认设备。工作目录默认是「默认项目地址 / 会话 id」（一个新的空目录），也可以改选电脑上已有的项目目录；不管选哪个，都必须在本机允许的目录范围内。
  • 选已有项目时，网页上列出这台电脑每个允许目录下一层的子目录名，并标出哪些是 git 仓库；不往下展开、不读文件内容，以点开头的不列。也可以手动输入路径，不在允许范围内的直接提示。
  • 设备和目录在建会话时定下，之后不能换。原因是 CLI 的会话记录存在那台电脑上，换电脑或换目录，就接不上之前的上下文了。
  • 一台电脑可以同时跑多个会话，每个会话有自己的 bridge 和 CLI。最多同时跑几个，由本机策略决定。

2.4 模型的两种来源

由智能体配置决定：

平台模型本机 CLI 自己的登录
模型从哪来平台的模型网关，经设备网关代理（见 4）CLI 用电脑上已登录的账号直接连供应商
用量平台统计，记在智能体名下平台看不到
对话里换模型可以，和其他智能体一样不显示模型选择器
适合公司统一管理模型和费用已经有个人订阅

不管模型用哪种来源，MCP 和知识库都经设备网关访问。

2.5 权限主体：使用者本人

本机 CLI 智能体访问 MCP、知识库时，一律按使用者本人的权限判断，不按智能体的权限（数字员工式的授权）。原因是会话令牌就在使用者自己的电脑上，使用者可以绕过 CLI，直接拿它发请求。如果按智能体的权限，而智能体的权限又比本人大，这就成了越权的通道。

2.6 被委派时

其他智能体可以把任务委派给本机 CLI 智能体，比如平台上的通用助手把「在本机项目里写个脚本」交给本机 Claude Code。委派发生时没有人选设备和目录，所以按固定规则来：

用哪个说明
设备使用者的默认设备委派也只会落在使用者自己的电脑上
工作目录默认项目地址 / 会话 id会话 id 是用户看到的那个对话（会话树的根）的 id。同一个对话里多次委派用同一个目录，第一次是空目录，之后接着上次的文件做，和平台上「子智能体与主智能体共用工作区」的规矩一致

图 2　委派给本机 CLI 智能体：设备取默认设备，目录取「默认项目地址 / 会话 id」

  • 主、子两边的文件不共享：主智能体在平台上，子智能体在电脑上，彼此看不到对方的文件。交接只靠任务书和结果，所以任务书要把需要的内容写清楚，结果里要说明产出放在哪。用户可以在子智能体卡片上打开文件抽屉，查看电脑上的产物（5）。
  • 目录不存在就由连接器创建。默认项目地址必须在本机允许的目录范围内，否则连接器会拒绝。
  • 默认设备不在线，或者目录不被允许：这次委派立即失败，原因交还给主智能体，并显示在对话里，比如「你的默认设备 MacBook 不在线」。委派开始之后再断线，按 3.7 一直等待恢复，不设超时。

2.7 调试预览

智能体编辑页的调试预览也要有电脑可跑：它跑在编辑者自己的默认设备上，目录是「默认项目地址 / 调试会话 id」，用当前未发布的配置。编辑者没有默认设备或默认设备不在线时，调试预览不可用，并提示先配对或启动连接器。

3. 网络打通

3.1 难点：两个方向都不通

图 3　从会话 Pod 换到用户电脑后，平台到 CLI、CLI 到平台两个方向都不通

  • 平台 → CLI：现在由平台主动连会话 Pod 的地址，给 CLI 下达开会话、开一轮、审批结果等指令。电脑在路由器、防火墙后面，IP 也会变，平台连不进去。
  • CLI → 平台：CLI 要访问模型、MCP、知识库。这些服务的集群内地址在集群外访问不到。即使把服务暴露出去，智能体的 Key 是这个智能体所有使用者共用的，放到个人电脑上，就等于交给了所有能碰到这台电脑的人。

3.2 思路：电脑主动连出

平台连不进电脑，那就让电脑主动连出来。电脑访问平台的 HTTPS 入口就像打开一个网页，家用网络和公司网络都允许。连接器启动后连上设备网关，这条连接一直不断开，平台通过它找到电脑。

平台这边新增一个设备网关，接住所有设备的连接。对 Atlas server 来说，连设备网关上的一个会话，和连会话 Pod 里的 bridge 完全一样。平台和 bridge 之间的协议、序号确认、断线补发、审批转发都不改，设备网关和连接器只转发，不解读内容。

3.3 为什么选这种方式

做法用户要做的问题结论
组网 / VPN：电脑加入集群网络，平台直接连电脑装 VPN，通常需要管理员权限个人电脑进了集群网络，可以横向访问其他服务；每个人都要装，公司 IT 通常不允许不选
端口映射：每台电脑在中转服务器上映射一个端口装映射工具要给每台设备分配、回收端口；认证用的是共享口令，和平台里的人对应不上不选
电脑直接连 Atlas server装连接器run 可能在 server 实例 B 上执行，而电脑连在实例 A 上，只能在实例之间转发。另外 server 发版频繁，每次发版所有设备都会掉线不选
电脑连出到独立的设备网关装连接器，能访问 HTTPS 入口就行多一个服务选这个

即使电脑和平台在同一个局域网里，也走这条路：电脑的地址会变，本机防火墙也会拦，平台直接连电脑并不可靠。

3.4 设备上线

图 4　配对和上线（实线：请求；虚线：返回）。配对只做一次，之后每次开机，连接器直接从 ⑤ 开始

  1. 用户在「我的设备」里添加设备，平台给出一个一次性配对码（10 分钟内有效）和一行安装命令。
  2. 用户在电脑上安装连接器，并输入配对码。
  3. 连接器用配对码向设备网关换设备令牌。
  4. 平台核对配对码（只能用一次）并登记设备。平台只保存设备令牌的摘要，看不到原文；令牌原文只交给连接器这一次，连接器把它存进系统钥匙串（没有时存进只有本人可读的文件），不放进环境变量。
  5. 连接器带着设备令牌建立控制连接，并报告连接器版本、系统、装了哪些 CLI、本机允许的工作目录。版本太旧的连接器会被拒绝，并提示升级。
  6. 设备网关在在线表里记下：这台设备在线，连在哪个网关实例上。
  7. 双方大约每 25 秒互发一次心跳，用来及时发现电脑睡眠、换网络这类情况。连续几次收不到心跳就判定为离线。电脑醒来后，连接器会自己重连。

3.5 一轮对话

图 5　一轮对话。⑦ 之后的消息都经过设备网关和连接器，图上为了简洁画成直达

  1. 用户在网页上发消息。
  2. Atlas server 查在线表，看会话绑定的设备是否在线。不在线就立即结束这一轮，并告诉用户「你的电脑不在线，请启动连接器」，不显示「系统忙」这类说法。
  3. server 照常组装这一轮的能力（模型、MCP、知识库的真实地址和凭据），交给设备网关登记，换回会话令牌和设备视角的地址（见 4）。
  4. server 向设备网关要这个会话的连接，就像以前连会话 Pod 的 bridge 一样。
  5. 设备网关通过控制连接通知连接器，为这个会话打开一条会话流，并告诉它会话、CLI 类型、工作目录、模型接入方式。
  6. 连接器按本机策略核对：目录在允许范围内、这种 CLI 本机配置过、权限模式不超过本机上限、同时会话数没超。核对通过后，确保这个会话的 bridge 在跑（不在就拉起，bridge 再启动 CLI），再把会话流接到 bridge。核对不通过就拒绝，原因一路传回网页。
  7. server 通过这条通道给 bridge 发开会话、开一轮的消息。这些消息和发给会话 Pod 的完全一样。
  8. CLI 开始干活，过程消息原路回到 server，再显示在对话里。每条消息带序号，server 定期确认收到了哪一条（断线后据此补发，见 3.7）。
  9. 需要审批时，审批请求同样原路传过来。用户在网页上处理，结果原路传回。
  10. 这一轮结束。

3.6 一条连接里跑多路

图 6　一台设备只有一条控制连接，会话和文件请求在里面各走各的通道

  • 为什么只用一条连接：设备网关有多个实例时，server 只需按在线表找到设备连着的那个实例，所有通道自然都在那个实例上，不依赖入口的粘性路由，也不需要在网关实例之间转发。电脑也只维持一条加密连接，经过各种路由器、代理时更稳定。
  • 先后顺序：正在进行的对话优先。文件内容分成小块，穿插在对话消息之间发送，下载大文件不会让对话卡住。
  • 互不拖累：每一路都有自己的缓冲上限。某一路长时间堵住（比如 server 那边读得慢），只关这一路，其他路不受影响。被关掉的会话流按 3.7 恢复。
  • 关闭原因原样传给另一端：bridge 那边说「会话已结束」或「被新连接取代」，server 就不再重连；设备断开、网关重启时，server 收到「可以重连」，会继续重连。

3.7 断线与恢复

图 7　断线后恢复：断开的只是通道，这一轮在电脑上照常进行；接回后从最后确认的位置往后补发

情况结果
网络抖动；电脑睡眠后醒来CLI 在本机接着干。连接器重连后，server 重新接上，从最后确认的位置往后补发，用户看到的过程不缺也不重复
电脑长时间合盖这一轮一直等，不设超时。网页显示「等待你的电脑重新连上」，用户可以随时取消
连接器或电脑重启bridge 进程不在了，这一轮的进度跟着丢失，所以这一轮以失败结束，并说明原因。下一轮发消息时，CLI 按之前记下的会话接着原来的上下文继续
Atlas server 换实例接管新实例经设备网关重新接上会话，和上面一样补发
设备网关重启（比如发版）所有设备断开后自动重连，正在进行的一轮停顿一下就接上
用户在网页上点停止和会话 Pod 一样，请 bridge 取消这一轮。断线期间点停止，server 不再重连，这一轮直接结束

3.8 设备网关有多个实例时

在线表记录每台设备连在哪个网关实例上。server 要连某个会话时，查在线表，直接连那个实例。一台设备只有一条控制连接，它的会话流和文件流都在那个实例上，网关实例之间不转发。实例重启时，连在上面的设备自动重连到其他实例，在线表随之更新。

设备网关和 Atlas server 分开部署：server 发版频繁，网关很少变，设备的长连接不受 server 发版影响。

3.9 对平台入口的要求

  • 电脑只需要能访问平台的 HTTPS 入口（443 端口），会遵守电脑上设置的网络代理。
  • 只走加密连接，所以入口必须是 HTTPS。
  • 只在局域网里的部署，只有同一个局域网的电脑能用。首发选在有公网地址的日本服务器上。

4. CLI 怎么用平台的能力

CLI 要访问模型、MCP、知识库。做法是由设备网关替设备持有凭据：交给电脑的地址都指向设备网关，凭证只有会话令牌；设备网关收到请求后，换上真实凭据再转给平台的服务。

图 8　凭据代持：电脑上只有会话令牌，设备网关在转发时换上真实凭据

  • server 不用改组装逻辑：和会话 Pod 一样组装出真实地址和凭据，只是多一步，交给设备网关登记，再把设备视角的地址和会话令牌交给 CLI。
  • 所有服务用同一套做法：设备网关不需要了解模型、MCP、知识库各自的协议，只做「认令牌、换凭据、转发」。流式回复（模型逐字输出）原样传回。
  • 身份只能由平台写入：设备带来的认证和身份信息一律丢掉，再由设备网关写入使用者本人的身份（2.5）。设备无法冒充别人。
  • 会话令牌的有效期：CLI 启动时读取地址和令牌，中途换不了，所以会话令牌在整个 CLI 会话里保持不变。会话结束并被回收、会话被删除、设备被吊销时，令牌失效。
  • 换 Key、收回授权立刻生效：每轮开始时 server 会重新登记真实凭据。真实凭据只在设备网关这一侧，换了 Key 不用重启 CLI；MCP 网关每个请求都判权，收回授权后的下一个请求就会被拒。
  • 模型用本机登录时（2.4）：平台不下发模型接入，CLI 直接连供应商，不经过设备网关。MCP 和知识库照样走设备网关。

5. 本机工作目录的文件预览

5.1 做法：打开时现读

文件留在电脑上，不同步到平台。网页上要看文件时，经设备网关请连接器现读，读完原路返回。

图 9　看本机文件的链路：网页和预览页都不变，只是 server 读文件的地方从对象存储换成了电脑

  • 网页上的文件抽屉和预览页都不变：server 按会话的运行位置决定去对象存储读还是去电脑上读。HTML、PDF、图片、Markdown、文本的显示方式都照旧。
  • 预览站点仍由 Atlas server 提供：预览站点负责给文件内容加安全限制（内容视为不可信，放在隔离的页面环境里运行，不能冒充平台）。这是安全的关键，只保留 server 这一份，不在设备网关里再做一个。代价是文件内容多经过 server 一次，按预览的数据量可以接受。
  • 看文件不依赖会话在跑：读文件由连接器完成，不经过 bridge。会话闲置、bridge 退出后，只要电脑在线，照样能看。

5.2 文件抽屉的两个页签：改动和全部

图 10　文件抽屉：git 仓库默认打开「改动」，「全部」按目录一层层加载

页签内容为什么
改动（git 仓库时默认打开）还没提交的改动：新增、修改、删除。删除的文件只列出，不能预览本机的工作目录通常是已有项目，用户最关心智能体改了什么。这和现在文件抽屉回答的问题一致：这个会话产出了什么
全部按目录一层层加载，和「我的工作空间」页的浏览方式一样。一层的条目太多时只显示前面一部分，并给出提示本机项目动辄上万个文件，一次全部列出既慢又列不完，按数量截断还会让一部分文件找不到
  • 工作目录不是 git 仓库时，只有「全部」。
  • 「改动」是工作区相对最近一次提交的改动，包括用户自己改的，并不精确对应这个会话做了什么。界面上照实说明。
  • 对话头部显示「设备名 · 本机路径」和设备在线状态。它不链接到「我的工作空间」，因为文件不在那里。

5.3 什么时候刷新

  • 一轮进行中，「改动」列表定时刷新。连接器把结果缓存一两秒，多个标签页同时在看也只算一次。
  • 「全部」只在展开目录时才去读。
  • 预览页按文件版本刷新。版本由文件大小和修改时间算出，不需要读文件内容；版本没变就不再传内容。
  • 预览 HTML 时，页面引用的每个文件（脚本、样式、图片）都要走一遍这条链路。从国内访问日本服务器，每次往返几十到上百毫秒，页面加载会比会话 Pod 慢一些。

5.4 只读，有大小上限

  • 只读：网页上只能查看、下载，不能往电脑里上传、删除、改名。
  • 大小上限：预览不超过 20 MB，下载不超过 200 MB。管理员可以在运行期配置里调整，不用重启。超出上限时提示用户到电脑上直接打开。

5.5 电脑离线时

  • 文件抽屉和预览页显示「你的电脑不在线，文件暂时看不到；启动连接器后自动恢复」，不显示「系统忙」。
  • 对话记录不受影响，包括每次工具调用和审批，都照常可以看。
  • 设备被吊销或换了电脑后，这个会话的文件就看不到了，只剩对话记录。
  • 为什么不做同步或快照：同步意味着把整个项目传到平台，这是隐私问题，用户把代码留在本机往往就是为了不上传；大项目会长期占用用户的上行带宽；平台上的副本和电脑上的文件也会越来越对不上。离线看不到文件，换来的是文件始终只在电脑上。

6. 安全

平台获得了让一台个人电脑执行命令的能力。这一节说明这种能力被限制在哪里。

6.1 只能跑在本人的电脑上

  • 设备只属于一个人。会话建立时绑定设备，平台核对会话的使用者就是设备的主人。
  • 每次连会话、每次看文件都会再核对一遍：请求者、会话创建者、设备主人必须是同一个人。
  • 智能体可以共享给别人，但别人用时只会跑在别人自己的电脑上，不可能跑在你的电脑上。
  • 委派也一样：只会落在这个对话的使用者自己的默认设备上。

6.2 平台能让电脑做什么，由本机决定上限

  • 平台只告诉连接器三件事：用哪种 CLI、在哪个目录、用什么权限模式。实际启动什么命令，由连接器按本机配置决定，平台无法让电脑运行任意程序。
  • 本机策略优先。连接器逐项核对：目录在本机允许的范围内；这种 CLI 本机配置过；权限模式不超过本机上限（比如电脑主人可以规定不允许「全部自动批准」）；同时运行的会话数没有超过上限。任何一项不满足就拒绝，并把原因显示在网页上。
  • 审批照常有效：CLI 要执行的操作按权限模式请求审批，由使用者在网页上决定。

6.3 电脑上有哪些凭据

凭据在电脑上吗说明
设备令牌在，存在系统钥匙串里（没有钥匙串时存进只有本人可读的文件）平台只存摘要。可以在网页上吊销，吊销后这台设备立即断开
会话令牌在，在 CLI 进程里只对一个会话有效；会话结束并回收、会话删除、设备吊销时失效
智能体的模型 Key、MCP Key不在由设备网关持有
知识库访问令牌不在由设备网关持有
本机 CLI 自己的登录在，用户本来就有模型来源选「本机登录」时使用

6.4 传输与配对

  • 只走加密连接（HTTPS）。
  • 配对码只能用一次，10 分钟内有效。设备令牌只在配对时交给连接器一次。
  • 连接器版本太旧时会被拒绝，并提示升级，避免旧版本里的问题被带进来。

6.5 电脑主人看得见、停得了

  • 连接器可以列出正在跑的会话，并能结束其中任何一个。退出连接器，所有远程会话都会停止。
  • 连接器在本机日志里记录每次打开会话、每次远程读取文件（读了什么路径、什么时间）。
  • 远程查看文件可以在本机完全关闭（5）。

6.6 没有隔离

CLI 能做电脑主人能做的任何事，比如读写主人能访问的文件、访问主人能访问的网络。约束它的只有两样：审批（权限模式）和本机策略的上限。建会话时界面会明确提示这一点。

7. 使用流程

  1. 添加设备：在「我的设备」里点添加，按提示在电脑上安装连接器（bridge 随连接器一起安装），然后输入配对码。
  2. 准备本机：设置允许平台使用的工作目录（比如 ~/code，还要包含智能体的默认项目地址，比如 ~/atlas-projects），装好要用的 CLI 和它的适配器。连接器提供自检，检查 CLI、适配器和运行环境是否齐全，缺什么就直接给出修复提示，并把结果报告给平台。
  3. 新建对话：选择一个本机 CLI 智能体。设备默认选中默认设备，目录默认是一个新目录（默认项目地址 / 会话 id），也可以从电脑允许目录下的子目录里改选已有的项目。界面会提示「CLI 将以你的身份在这台电脑上工作」。也可以不直接选它，而是在别的对话里由主智能体委派过来（2.6）。
  4. 对话和审批：和平时一样。对话头部显示「设备名 · 目录」和设备在线状态；电脑离线时会明确提示。
  5. 查看文件：打开文件抽屉，看「改动」和「全部」，点文件名在新标签页预览。
  6. 停止使用：暂时不用就退出连接器；以后不再用这台电脑，就在网页上吊销它。
