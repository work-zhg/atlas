0. 方案概览

图 0　评测只通过平台的公开能力驱动被测方；结果校验与过程分析分开，汇总后进门禁。

1. 目标与原则

评的是平台与 harness，不是模型：模型固定，换的是智能体的配置与执行形态。要回答四个问题：

问题怎么回答
能力：做不做得成公开任务集（可与公开榜单对照）与自建任务的成功率、pass^k
对照：哪种配置更好同题配对比较：原生与 ACP 横比；去掉某项能力的消融
可靠性：平台机制在扰动下守不守得住不变量断言、故障注入、扰动与干净运行配对（§8）
回归：改动之后有没有变差与基线按题配对比较；硬门槛

原则：

  • 看结果，不卡路径：判分看最终产出与环境状态，不强制工具调用顺序；过程断言只用来守平台机制。
  • 校验器先自证：空跑应失败、参考解应通过，否则题目作废。
  • 平台错误与 Agent 失败分开：基础设施的问题单独计数、按协议重跑，评测侧自己的问题不进分母。
  • 多次运行看稳定性：同时报成功率（均值）与 pass^k（k 次全成功）；结论带置信区间。
  • 和真实用户走同一条路：只用平台对外的能力，评测账号是普通用户；评测专用的能力只放在评测档里。

2. 被测对象与对照

被测方是「一份智能体配置」：系统提示词、模型、工具组合、子智能体、执行形态、审批模式、沙箱镜像与档位。同一实验里所有变体用同一个模型，配置变了就是另一个被测方（另建一个智能体，可复用）。

对照做法例子
横比同模型、不同执行形态原生智能体对 ACP（Pod 里的 Claude Code）
消融只去掉一项能力去掉待办清单；只留 Shell（与 Terminal-Bench 的中立基线 Terminus 同构）
基线同配置、不同平台版本本次部署对上次存的基线
扰动同配置、同版本，有无注入故障§8.2

审批模式在评测里固定为「每条命令都请示」，由评测按策略作答：避免自动模式的判断器成为额外变量。

3. 任务模型

一道任务由下面几部分组成。前五项是所有任务都有的；场景设定只在需要的题里出现。

组成说明
指令Agent 看到的全部任务描述
环境初始工作区文件；或题目自带的环境镜像（命令从工作区开始，指令里写明题目的起始目录）
校验Agent 看不到的校验脚本与校验方式（§6.1）
参考解证明题目做得出来，只用于校验器自证
预算时间与 token 的上限。这是评测协议，不是平台限制：超了由评测取消，记「超预算」
配置补丁叠加到被测配置上的改动（换沙箱镜像与档位、给写文件加审批、配一个子智能体）
审批策略全部批准 / 全部拒绝 / 第一次拒绝 / 等 N 秒再批 —— 用来造「审批被拒」「审批很久」的场景
模拟用户用户心里的完整需求（Agent 看不到）；Agent 提问时由评测侧的模型只按它作答
前置会话主任务之前先在另一个会话里发的消息（跨会话场景，如先交代偏好再检验）
事件流断线收到 N 条事件后主动断开再带游标重连
过程断言从轨迹判定平台机制有没有按预期工作，分不变量与场景前提（§6.3）

4. 任务集

任务集题量用途内容
走通集7冒烟、回归代码修复、重构、数据处理、多步小工具；基础题必须让模型稳能做成
工程场景集11平台机制的单点场景审批被拒、慢审批、并行审批续跑、断线重连、跨会话记忆、长读压缩、重复读清理、并行委派、错误路径恢复、大输出、工作区约定
需求澄清集6向用户提问的时机3 对「一句话的模糊题 / 写清楚的清晰题」：模糊题看提问率与成功率，清晰题看误问率
Terminal-Bench 215能力、与榜单对照第一批：简单 3、中等 10、困难 2；含系统管理类（必须 root）；每题自带环境镜像

4.1 公开集接入

  • 固定版本：导入固定到上游仓库的一个提交，题目修订后另起一版，结果不混比。
  • 保留原格式：指令、校验脚本、参考解原样搬入；题目环境用上游预构建的镜像，不在本地重建。
  • 选题：先挑镜像小、不需要 GPU / 虚拟机、没有加密附件、纯文本可做的题，覆盖各难度与类别；之后再扩到全集。
  • 与榜单的差异要写在报告里：资源上限用平台的沙箱配置；Atlas 的命令从工作区开始（指令前加了起始目录）；时间预算含沙箱启动；校验时现场联网（经评测档的出网代理）。

5. 一次 trial 怎么跑

图 1　每个 trial 用全新会话；平台错误换新会话重跑一次。

5.1 评测档沙箱

平台默认的沙箱是收紧的（非 root、根文件系统只读）。公开命令行题按 root 设计（装包、写系统目录），所以单独有一档评测档：

  • root、根文件系统可写，与容器运行时的默认权限一致；不开特权、不挂宿主机目录、不带集群凭据。
  • 镜像由题目给定，只放行评测档自己的镜像白名单；部署没有开评测档时，这类配置在执行命令时直接报错。
  • 出网：部署环境访问不了题目依赖的外网时，评测档沙箱经出网代理访问；默认档与 ACP 不受影响。
  • 与默认档共用工作区存储与回收机制：闲置回收、会话删除时级联回收、配额都覆盖它。

6. 判分

6.1 结果校验

方式做法适用
容器校验把最终工作区拷进隔离容器（无网络）跑校验脚本：退出码判通过，可给部分得分只看文件的题
沙箱原地校验Agent 结束后，把校验脚本送进它用过的沙箱，在题目目录里执行，再读得分文件（1 = 通过）要看环境状态的题：装了什么、服务起没起、工作区以外的文件

图 2　沙箱原地校验：校验脚本在 Agent 结束之后才送进现场，Agent 从头到尾看不到它。

6.2 校验器自证

每道自建题都要过两关才能用：初始状态校验不通过（题目有意义）、参考解校验通过（校验脚本没写错）。公开集沿用上游的人工复核，并用参考解抽查。

6.3 过程断言

从轨迹统计事件条数或过程指标，与期望比较。断言分两类，处理不同：

类别含义例子不满足时
不变量违反即平台缺陷断线重连后不丢事件、不重复事件进硬门槛
场景前提只说明这次场景生效了没有第一次审批确实被拒；确实发生了压缩；子智能体确实并行单列「场景未生效」，不进门槛（否则随模型的随机性红绿跳）

过程断言只守平台机制，不要求 Agent「必须用某种办法做事」。

6.4 结果分类

结果含义进成功率分母
成功校验通过且没超预算是
失败跑完了，没做对是
超预算超时间或 token 预算，被评测取消（工作区照样校验，但不计通过）是
Agent 错误run 失败，原因在 Agent / harness：超步数、上下文溢出、模型拒答是
平台错误run 失败或沙箱不可用，原因在基础设施；重跑一次仍失败才记是，报告首页单列
评测侧错误建会话失败、校验没做成、模拟用户出错否，续跑时重来

7. 统计、报告与门禁

7.1 指标

类别指标
结果成功率（每题 k 次取均值，再按题平均；按题重采样的 95% 置信区间）；pass^k（k 次全成功的题目占比，与成功率差距大 = 不稳定）
成本token（输入、输出、缓存命中）、耗时、审批次数与等待时长
过程工具调用、工具错误、命令失败、重复调用、压缩与上下文清理、子智能体调用与最大并行数、待办更新、提问轮次
失败构成按结果分类与任务类别分组；平台错误与沙箱不可用单列

7.2 比较

  • 配对比较：同一题上两个变体（或两次运行）的成功率差，按题配对重采样；区间不含 0 才算显著。
  • 回归判定：成功率下降且区间不含 0 = 回归。
  • 警告：pass^k 下降 ≥ 10 个百分点；token 或耗时的中位数上升 ≥ 20%；不变量断言失败增加。

7.3 层级

层级触发内容看什么
冒烟每次部署后走通集 × 1 次只看硬门槛（单次有方差，成功率不作门槛）
回归合并前 / 定期走通集 + 工程场景集 × 多次与基线配对比较；硬门槛
能力评测定期 / 换模型或大改 harness公开集 × 多次 × 多变体成功率、pass^k、横比与消融
可靠性评测见 §8.5故障点、扰动变体、记忆、压缩不变量、扰动下的退化

硬门槛：平台错误、沙箱不可用、不变量断言失败，任一非零即不通过。

8. 平台机制的可靠性评测

挂起续跑、审批等待、断线重连、接管、沙箱重建、子智能体、记忆、上下文压缩这些机制，出问题时往往不影响成功率（命令重跑了两遍但恰好幂等），而正常运行几乎走不到故障路径。所以这部分不靠成功率，靠三件事：

  • 不变量：每个机制写清楚必须守住什么，违反一次就是缺陷。
  • 可复现的故障注入：故障按「运行到哪一步」触发，而不是按时间，同一个故障能反复打在同一个位置。
  • 把模型的随机性和平台故障分开：确定性的那一层用脚本化的模型（§8.1）；真实模型那一层用扰动与干净运行配对（§8.2）。

工程场景集里已有的单点场景（审批被拒、慢审批、并行审批续跑、断线重连、跨会话记忆、长读压缩）保留；本节把它们扩成系统化的故障点、扰动变体，并补上记忆与压缩的质量评测。

图 3　故障点：每个机制最容易出错的边界。

8.1 固定故障点测试

在平台自己的测试里跑，每次改动都跑。用脚本化的模型：预先写好每一步的模型输出（调哪个工具、参数是什么、最后说什么），同一个脚本跑多少遍都走同一条路径。每条命令往一个计数文件追加一行，用来清点副作用。

故障点注入必须守住
F1 模型返回后、工具开始前进程崩溃，另一个实例接管这一步的工具最终只执行一次；历史里没有半截的调用
F2 命令执行中进程崩溃 / 别的实例接管命令不重跑：接上原命令拿到结果，或如实告诉模型「结果未知」；副作用计数为 1
F3 结果落库前进程崩溃结果不丢、不重复；事件序号连续
F4 等待审批中重启；批准落在重启之前 / 之后审批不丢、不过期；批准后只执行一次；拒绝的原因回给 Agent
F5 子 run 进行中（父已挂起）重启；子 run 在重启前 / 后完成父 run 只被唤醒一次，结论只回传一次；取消父 run 级联到子 run
F6 压缩进行中进程崩溃历史不损坏；下一轮照常继续，摘要不重复计费
F7 取消落在命令执行途中用户取消命令被中断；run 终态为已取消；不残留运行记录，不挡住沙箱回收

判据是「回放等价」：同一个脚本，在任一故障点中断并恢复后，终态要和没中断的那次一致 —— 消息历史（工具调用与结果）、工作区文件、副作用计数、run 终态与用量；事件序列除了重连标记，不缺、不重、不乱序。故障点 × 脚本全排列都跑，任何一格不等价即失败。

脚本覆盖三类 run：只有命令的单 Agent；带审批的单 Agent；带委派（子智能体又委派）的多层。每类至少一条脚本经过全部适用的故障点。

8.2 端到端故障变体

在测试环境的真实部署上、用真实模型。同一批工程任务分「干净」与「扰动」两种跑，每种 k 次，按题配对。扰动由评测在轨迹到达某一步时触发（如收到第 N 次命令开始的事件），保证每次打在同一个位置。

扰动触发时机期望
服务实例被删第 N 次命令开始后别的实例接管，run 继续完成；有副作用的命令最多执行一次
滚动部署run 进行中同上；客户端带游标重连，事件不丢不重
沙箱被删命令执行中 / 两条命令之间告诉模型环境重建过；工作区文件仍在；Agent 能继续
事件流断开收到第 N 条事件后重连后不丢、不重、不乱序
审批迟迟不批每次审批等 N 分钟run 不被当成超时或孤儿，批准后继续
模型服务短暂不可用第 N 次模型调用按策略重试，或明确失败并给出原因；不半途卡死

图 4　扰动与干净运行按题配对：不变量决定通过与否，成功率差衡量退化。

只在测试环境跑；扰动运行之间串行注入，同一时刻只有一个扰动，结论才能归到具体的那一种。

8.3 记忆评测

分两部分：能力（记得对不对）用公开记忆基准；不变量（该隔离的隔离、该删的删掉）自建。

图 5　记忆评测：基准样本经平台真实的记忆通路写入，再在新会话里提问。

  • 基准：LongMemEval，固定版本。它考五种能力：信息抽取、跨会话推理、时间推理、知识更新、拒答（问到没发生过的事要说不知道）。先用只含证据会话的版本（每题几段会话，成本低、只测记忆通路），再用带大量干扰会话的版本（考噪声里的召回）。
  • 抽样：每种能力抽同样多的题（先每种 10 题），拒答题单独计；固定抽样种子，前后可比。
  • 判分：模型判分，对照标准答案；知识更新题答出旧值记为「过时」，与答错分开计；拒答题只有明确说不知道才算对。
指标说明
分能力准确率五种能力各自的准确率，不只报总分
拒答正确率该拒答时拒答的比例；不该拒答时拒答单独计（过度保守）
过时事实率知识更新题里答出被取代的旧值的比例 —— 比「答错」更有害
写入与成本每题写入的条目数、召回耗时、记与取消耗的 token

8.4 上下文压缩评测

压缩发生了不等于信息还在。用探针测「压缩后还记得什么」，再用任务成功率测「压缩对做事的影响」，两者一起看。

图 6　压缩探针离线跑在已归档的轨迹上，不用重跑任务；再用开 / 关压缩的配对成功率确认实际影响。

探针类别问什么
回忆压缩前出现过的具体事实：数值、报错信息、用户给的约束
产物改过哪些文件、文件里现在是什么、生成了哪些结果
接着干下一步该做什么、还剩哪些没做
决策之前为什么选了这个方案、排除了哪些做法
  • 素材：工程场景集与公开集里的长任务轨迹；每个压缩点各出四类探针，参考答案由能看到完整历史的模型生成，抽样人工复核。
  • 判分：模型判分，看到探针、回答、压缩后的上下文与参考答案；「编造」（答出历史里没有的内容）单独计，比遗漏更严重。
  • 局限的补偿：探针只测到被问到的信息，所以必须同时看「压缩开 / 关」的配对成功率；关压缩时用足够大的窗口或不触发压缩。
  • 指标：四类探针各自的得分、编造率、压缩后的成功率差、每次压缩节省的 token。

8.5 运行节奏

评测何时跑在哪跑结论怎么用
固定故障点（8.1）每次改动平台自己的测试任一格不等价即不合并
端到端故障变体（8.2）发版前 / 每周测试环境不变量进硬门槛；退化进报告
记忆（8.3）记忆相关改动时 / 每月测试环境不变量进硬门槛；分能力准确率与上次比
上下文压缩（8.4）压缩策略或模型改动时离线（探针）+ 测试环境（配对）探针得分与成功率差一起决定是否采用新策略
