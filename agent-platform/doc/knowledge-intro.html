Atlas 知识库服务介绍

日期：2026-11-04 · 配套的 C4 图在 c4-model/knowledge/

知识库服务管文档的入库与检索：把各种格式的文档解析、分段、向量化，再按库级和文档级权限检索，给智能体提供领域知识。员工在控制台里建库、上传文档、调检索设置、做召回测试；智能体在运行时检索它绑定的库。

1　它是什么

有两类调用方。员工在控制台的知识库页面里管理知识库和文档，浏览器经网关直接调本服务。Agent 平台在智能体运行时检索它绑定的库：原生智能体经内部接口检索，会话 Pod 里的 CLI 智能体经 MCP 端点检索。

知识库服务依赖两个外部服务：用户中心负责操作码、库级权限和主体展开，库的授权也登记在那里；向量、重排、对话模型都经模型平台调用。

图 1　知识库服务和它周边的系统

它有几个值得先知道的特点：

  • 两层权限，授权都在用户中心。库级权限决定能动哪些库（读 < 写 < Owner）；文档级权限把文档的 ACL 和调用者的主体标签求交，决定能看到库里哪些文档。智能体检索时一律按这一轮的身份判断：绑定不是授权，每次检索都逐库校验，撤权立即生效。
  • 入库看得见、停得下、续得上。一个文档一个入库任务，按阶段跑，每个阶段的状态立刻可见；可以暂停、恢复、重试。进程死了，巡检会把停住的文档续上。不设到点结束的超时。
  • 换向量模型不停服。新建一个索引版本，在后台重建，期间新入库的文档双写；建好后原子切换，旧版本保留，随时可以切回去。
  • 混合检索。稠密向量和 BM25 稀疏向量放在向量库的同一条记录上，BM25 的分词和 IDF 统计由 Milvus 内置完成；检索前做查询理解，召回后融合、重排。每次检索都记下过程，可以看到每个分段在哪一环掉的。

2　几个基本概念

图 2　知识库、文档、分段、索引版本和权限

概念是什么
知识库一组文档，以及它们的处理和检索规则：分段结构、默认检索设置、入库增强和审核开关、文档可以带的元数据字段。库级权限（谁能读、写、管理）登记在用户中心。
文档上传的一个文件。带启用、归档、审核状态，以及业务元数据、ACL、版本与生效区间。这些变了只改向量库里的标量字段，不重新向量化。上传新版本会取代旧版本。
DocIR解析的产物：带类型（标题、段落、列表、表格、图片……）、层级、页码和坐标的块序列，附一份解析质量报告。解析和分段之间只隔这一层。
父分段 / 子块分段把 DocIR 切成父分段和子块：父分段是返回给模型的上下文，子块是检索入口。默认按标题切小节。通用模式下分段自己就是检索入口。
入库从上传到能被检索的过程：解析 → 分段 → 增强 → 写分段 → 分批向量化。每个阶段的状态都看得到，可以暂停、恢复、重试。
增强入库时用对话模型给分段补上下文、给大表写摘要。没配对话模型或开关关着就不做；失败只是少了增强，不影响入库。
索引版本一个库用某个向量模型建出的一套向量，对应向量库里的一个 collection。换向量模型或改分词规则，都是新建一个版本，建好后切换；旧版本保留，用于回滚。
查询理解检索前改写问题、生成多种表述、拆子问题、抽取过滤条件。失败就用原问题检索。
主体标签调用者展开后的身份：本人、所在的角色和部门。文档的 ACL 和它求交，决定能看到哪些文档。
检索记录每次检索的过程：每一环的候选、分数和名次，控制台画成漏斗，用来排查「为什么没检索到」。分段的命中次数也从这里汇总。

3　由哪些部分组成

图 3　运行起来的几个部分。接口和 worker 是同一个包、同一个镜像，以两个子命令分别运行

  • 知识库接口：Python / FastAPI，有三个入口。管理接口给控制台；内部接口给 Agent 服务，用于运行时检索和编辑智能体时列出可读的库，网关不转发；MCP 端点给会话 Pod 里的 CLI 智能体，只认 Atlas 签发的令牌。接口进程里还跑着入库巡检。
  • 入库 worker：Celery，只消费入库队列。负责解析、分段、增强、向量化上传的文档，以及重建索引版本。
  • PostgreSQL：知识库、文档、分段与子块、索引版本、元数据字段、检索记录和文档向量缓存。
  • Redis：入库任务队列、入库锁、暂停标记，以及查询向量和查询理解的缓存。
  • 向量库 Milvus：每个知识库的每个索引版本一个 collection，里面是稠密向量、BM25 稀疏向量（由 Milvus 内置的 BM25 从检索文本生成）和文档级标量字段。
  • 对象存储：OSS。存上传的原文件，以及解析出的 DocIR 和图片。

两个进程里的组件

图 4　入库一条线，检索一条线。两个进程里同名的组件是同一份代码；管理接口还会做召回测试，走的也是检索

组件在哪个进程管什么
管理接口接口给控制台：知识库、文档、分段、共享、索引版本、元数据、召回测试和检索记录。
内部接口接口给 Agent 服务：智能体运行时检索，编辑智能体时列出可读的库。网关不转发。
MCP 端点接口给会话 Pod 里的 CLI 智能体提供检索工具。只认 Atlas 签发的令牌，库和身份都取自令牌，不认身份请求头。
入库任务workerCelery 任务：一个文档一个入库任务；重建索引版本。
知识库两者库的配置、共享（直接改用户中心）和元数据字段。删库、加字段发事件，各领域处理自己的数据。
文档与入库两者上传、文档状态（暂停、恢复、重试、启用、审核、删除）和属性。worker 里持锁按阶段编排入库；进程死了，接口里的巡检把停住的文档重新投递。
解析worker（分段预览也用）各种格式 → DocIR，附解析质量报告。PDF 做版面分析；不做 OCR，扫描页标记出来，先进待审核。
分段两者切父分段和子块，做上下文补全和大表摘要。人在控制台编辑分段后，同步重写向量。
向量索引两者稠密向量和 BM25 稀疏向量写进同一条记录，BM25 的分词和 IDF 交给 Milvus；文档级字段只改标量字段；索引版本的重建与切换。
检索接口查询理解、检索范围（权限、版本、元数据）、混合召回、融合与重排、组装。每次检索记一条过程记录。
访问控制接口调用身份、操作码、库级权限、文档级主体标签、MCP 令牌。自己不存授权，都在用户中心；用户中心不可用时一律拒绝。
模型接入两者向量、重排、对话模型。本地 fastembed 模型打在镜像里；远程模型一律经模型平台，取服务级 Key。对话模型可以不配，增强和查询理解就不做。
