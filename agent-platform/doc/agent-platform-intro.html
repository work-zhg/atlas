Atlas Agent 平台介绍

日期：2026-11-04 · 配套的 C4 图在 c4-model/agent/

Agent 平台管智能体的配置、会话和执行。它用同一套会话、审批、事件流和容错机制，同时跑两种智能体：在服务进程里执行的原生智能体，以及跑在沙箱里、由 bridge 接进来的外部 CLI 智能体（如 Claude Code）。它按长任务设计：没有到点结束的超时，等人的时候不占进程，实例挂了别的实例接着跑。

1　它是什么

员工在控制台里创建、配置智能体，和它对话；业务应用（如 AI TeamFlow）引用智能体，经会话下发任务、取回输出。每一轮对话在后台执行，模型的输出、工具调用、子智能体的过程实时推到控制台。

平台自己不托管模型、工具和知识。模型平台、MCP 网关、知识库服务、技能应用、记忆服务都是独立部署的同级服务，Agent 平台按智能体的 Key 或签名令牌去调用。用户、组织和权限以用户中心为准。执行命令用的沙箱由开源的 OpenSandbox 在 K8s 里按需创建。

图 1　Agent 平台和它周边的系统

和一般的「对话 + 工具」系统相比，它有两点不同：

  • 两种智能体，一套平台。除了在进程里执行的原生智能体，还能把 Claude Code 这类外部 CLI 智能体接进来，两者共用会话、审批、事件流和容错。
  • 按长任务设计。没有到点结束的超时。等人批准、等子智能体的时候整段挂起，不占进程。实例挂了，别的实例接着跑。

2　几个基本概念

图 2　智能体、会话、Run、段

概念是什么
智能体一份配置：模型、系统提示词、工具、知识库、技能、审批模式、权限类型。每保存一次就是一个新版本，会话和 Run 都指向某个版本，改配置不影响正在跑的。
原生 / CLI 智能体智能体的两种类型。原生智能体在 Agent 服务进程里，由自研内核（基于 LangGraph）执行。CLI 智能体是 Claude Code 这类外部命令行智能体，跑在沙箱里，由 bridge 接进平台。
会话一段对话：消息历史、一个工作区、一条事件流。子智能体在自己的子会话上干活，所以会话是一棵树。
Run（一轮）从用户发一条消息到智能体给出回答，是一个 Run。同一个会话同一时刻只有一个 Run 在进行。
段Run 的一次连续执行。要等外部的事（审批、提问、子智能体）时本段结束、Run 挂起，等到了再跑下一段。不需要等的 Run 只有一段。
事件Run 里发生的每件事：模型输出的片段、工具调用和结果、审批请求、上下文用量…… 原生和 CLI 智能体产出的是同一套事件。
等人决定的事工具调用的确认、计划审批、向用户提问，统称审批事项。用户在会话里做决定。
沙箱K8s 里的隔离 Pod，智能体在里面执行命令、读写文件。按人管理：一个人默认一个，这个人的会话共用。
工作区一个人的文件，存在对象存储里，整个挂进沙箱的 /data。根会话有一个 workspace，子孙会话共用它。

3　由哪些部分组成

图 3　运行起来的几个部分。CLI 智能体自己直接调用模型平台、MCP 网关和知识库

  • 控制台：Next.js 写的，提供智能体编辑器和会话工作台。知识库、技能、模型、MCP 的管理页面直连对应的服务。
  • Agent 服务：Python / FastAPI。接口和 Run 执行器在同一个服务里，可以部署多个实例。任何实例都能领 Run、都能给用户推事件，进程本身不保存状态。
  • PostgreSQL：事实源。智能体和它的版本、会话和消息、Run 和检查点、审批事项都存在这里。
  • Redis：存事件流、会话锁、取消标记、唤醒广播。这里只放丢了也能恢复的东西。
  • 沙箱 Pod：由 OpenSandbox 按人创建。原生智能体的命令经 execd 在里面执行；CLI 智能体由 bridge 拉起，也在里面跑。
  • 对象存储：OSS。按人分目录，每个人的整个目录挂进他的沙箱的 /data。

Agent 服务里面

图 4　Agent 服务里的组件。运行时登记审批事项、起子 Run，是经审批组件和会话管理组件提供的接口完成的，图中没画这两条

组件管什么
智能体管理智能体的配置和版本（保存即新版本）。在用户中心登记数字员工和数据对象，共享靠它；在模型平台、MCP 网关各要一把 Key。决定这一轮按谁的权限判断：以人为权限，还是以智能体的数字员工为权限。
会话管理会话和消息、提交一轮与取消、会话事件流、子智能体、文件和上下文面板。「同一个会话同时只做一件事」的闸门也在这里。
审批管等人决定的事：登记、记下决定并唤醒 Run、作废。原生和 CLI 智能体共用。
平台管理持久指令：人主动写下、每轮都带给智能体的规则，分平台和个人两层。
Run 执行器领取 Run、续租约、写检查点、收尾。挂起的 Run 等到了就放回队列；实例挂了，由接管的实例收拾现场。
原生运行时在进程里跑原生智能体的一段：按槽位叠中间件，调模型和工具，管上下文。要等外部的事就挂起。
CLI 运行时让沙箱里的 CLI 跑一轮：接上会话，把权限请求转成审批，把内容翻成事件。断线或接管后接回事件流。
事件中继Agent 服务里唯一碰 Redis 的组件，负责会话事件流、会话锁、取消标记、唤醒、提交幂等、观看名额。
模型接入取智能体的 Key，检查要用的模型都已分配，交出调用端点和模型的规格、能力。
工具接入MCP 工具、知识库检索、技能目录。编辑器里能选的和运行时能用的出自同一个来源。
记忆常驻记忆放进系统提示词，其余的按主题按需加载。对话中写入，会话结束后补记。
工作区一个人的文件：他的沙箱在跑时经沙箱读写，否则直连对象存储。
沙箱按人供给和回收沙箱，在沙箱里执行命令。沙箱的地址和令牌不出这个组件。
凭据决定一个会话这一轮能用哪些出站凭据，如某个仓库的推送权限。
