AI TeamFlow 页面体验优化方案

逐页从用户的角度重看现在的界面（11-28 部署在日本服务器上的版本，用真实数据截的图），列出问题、给出改法，关键页画了「新样子」。先评审这份方案，定了再改代码。

0总的问题：界面在讲「系统怎么实现」，没讲「用户该做什么」

你举的例子是最典型的一处：节点页右侧「流程空间」页签只有一句 本节点的会话把流程空间挂在 /space，上游、并行节点的文件都在里面 · 打开流程空间。用户不需要知道「会话」「挂载」「/space」，他只关心：这一步要交什么、上一步给了我什么、文件在哪。同类的话几乎每页都有：

页面现在写的问题
流程空间页头Agent 平台的应用工作空间 01a22171 · 这条流程所有节点的数字员工会话都挂载它（/space）实现细节 + 内部编号，用户看不懂也用不上
流程详情页头发起时锁定（锁形标签）「锁定」是系统行为，用户不知道锁了什么、对他有什么影响
追溯 / 最近「技术方案」开工指令已发给数字员工、锁定执行的数字员工，会话挂载流程空间系统内部步骤当成业务事件给人看；一次同意产生 5 条记录
节点页 · 本节点产出目录 需求澄清/ · 开工指令里的约定；提交时由执行人选文件，不限目录写给开发看的说明
提交评审弹窗评审期间本节点会话不再写入。产物不做版本管理，只记下这一轮提交了哪些文件同上；关键信息（谁来评审）反而没突出
项目配置流程空间：每条流程发起时向 Agent 平台申请一个，这条流程所有节点的数字员工会话都挂载它不是配置项，不该出现在配置页
团队设置团队管理员 = 这个团队的 Owner（用户中心团队数据权限）、渠道要部署时配好凭据才会真的推权限模型、部署细节
节点页 · 评审记录01a22172-533f-7bc0-a298-903a27d0e…（文件名的位置显示成了一串编号）缺陷：把「提交记录的编号」当文件名显示了
流程空间预览Markdown 原文（# ## ** 都露在外面）数字员工的产出大多是 Markdown，应渲染成文档

除了用语，还有三类结构性问题：① 每页没有回答「现在什么情况、要我做什么」（例如流程详情要自己去流程图里找哪一步在等谁）；② 同一件事拆在好几个地方（流程详情 / 流程空间 / 追溯是三个页面，节点右侧又有五个页签）；③ 说明性小字太多（几乎每个卡片底下都有一行灰字解释原理）。

1改的原则

原则落到界面上
说用户的话界面上不出现：会话、挂载、/space、Agent 平台、应用工作空间、锁定、开工指令、数据权限、用户中心、Owner、凭据、内部编号。需要指 Agent 平台时用用户看得到的名字「Atlas」。
每页先回答「现在怎样、我该做什么」流程页、步骤页顶部放一张「现在」卡：进行到哪一步、谁在处理；轮到我时变成醒目的待办卡，带一个直接去做的按钮。
一件事一个地方流程详情、流程空间、追溯合成一个流程页的三个标签：概览 / 文件 / 记录。步骤页右侧从五个页签减到四个，去掉只有一句话的「流程空间」页签。
记录只记人关心的事记录里只留里程碑：谁开始了、数字员工写了什么文件、谁提交评审、谁同意或退回、谁上传了资料。系统内部的步骤（指令投递、开评审、状态迁移）不进记录。
少解释、多给入口删掉卡片底下的原理说明；规则类信息（谁评审、什么规则）放在要用的地方（评审区），空状态告诉用户下一步点哪里。

2统一用语

现在改成理由
节点步骤用户说「到哪一步了」，不说「到哪个节点」。模板编排里也叫步骤（并行的叫「同时进行的步骤」）
流程空间文件（页签名）／流程文件它就是这条流程的共享文件夹。概念上仍是一条流程一个，界面只说「文件」
追溯记录「追溯」偏审计口吻；记录既能看也能导出
产出物交付文件和「提交评审」「准出」对应：这一步交出去的文件
输入参考资料上一步交付的文件 + 成员上传的资料
本节点说明这一步要做什么、谁负责、谁评审
接管 / 交还暂停数字员工 / 让它继续「接管」容易被理解成「接管账号、接管浏览器」
驳回修改 / 打回上游退回修改 / 退回上一步口径统一用「退回」
过程文件草稿没被交付过的文件
执行 Agent / 执行的数字员工数字员工直接写名字，如「需求分析师」

步骤状态

现在改成说明
待开始未开始
人机协同中进行中「人机协同」是产品理念，不是状态
待准出准出评审中和「准入评审中」对称
待下游准入已准出悬停提示「等下一步的人确认接收」
准入评审中准入评审中不变
已通过已完成
已打回被退回
要你定：「准入 / 准出」我保留了（它是这个产品的核心概念，用户在模板里就要配），只是状态改成更顺的说法。如果想更口语化，可以改成「交付评审 / 接收评审」。

3项目 · 流程列表

现在的问题

  • 标题「流程」+ 副标题「支付中台」+ 面包屑「支付中台 / 流程」：同一信息说三遍
  • 「等你」单独一列，大多数时候是一列「—」；真有事等我时反而不醒目
  • 「各节点」一排无标签的色条，看不出是第几步
  • 看不到谁在处理、多久没动了

改成

  • 页头就是项目名；左侧菜单已经说明了这是「流程」
  • 等我处理的流程排在最前、整行浅橙底色，标题旁直接写「待你准出评审」
  • 「进展」一列：当前步骤 + 状态 + 「2 / 4」；色条保留但带悬停
  • 新增「负责」（当前步骤的人和数字员工）和「更新」两列；筛选加「只看与我有关」

技术方案：支付渠道回调幂等

目标：同一笔回调无论重投多少次，入账只发生一次；老数据零改造兼容。

1. 方案

  • 新增幂等表 t_pay_callback_idempotent + 唯一索引
  • 用 upsert 作为唯一并发闸门，不依赖「先查后写」

2. 风险

  • R1 幂等键选错导致真实支付丢失

7流程 · 记录（原「追溯」）

  • 筛选：全部步骤 / 某一步；只看评审。导出保留
