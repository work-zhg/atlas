设计说明

这个页面只调用定时任务库自带的管理接口（JobRoutes），不依赖 Atlas 的业务接口，所以 aiassistant、TeamFlow 这些宿主可以复用同一个页面组件；每个宿主把它挂在自己的管理后台里，权限由宿主实现的 JobGuard 决定。

主题规则
页面结构列表页（筛选 + 表格，列只有名称、触发规则、运行份数、状态、操作）→ 点一行打开右侧详情抽屉（概览、当前这一次、执行历史）；新建、编辑也是右侧抽屉；立即触发是弹窗。和控制台其他管理页一致：深色主题、Rail + 内容区。
普通任务、预置任务、系统机制普通任务：管理员在这里建的，可新建、编辑、删除、暂停、立即触发。预置任务：安装时自动建好的（如「清理任务执行记录」），名称旁带「预置」标签，可以改参数、停用，不能删除。系统机制：系统运行必需的（如兜底 run、续租 run），名称前带 🔒，所有操作按钮不出现，详情只显示每个实例的运行情况；鼠标悬停解释「系统运行必需，只能查看」。实现上，系统机制的定义写在代码里，另外两种存在库里。
运行份数列表里显示「1 份」「4 片」「每个实例」。分片任务运行中显示进度（已完成片数 / 总片数）和进度条，详情里有每一片的实例、开始时间、最近续租、状态。表单里「N 片」只有类型声明支持分片时可选；「每个实例」在表单里不可选，只有系统机制这样跑。
触发规则cron 旁边显示人话（「每天 03:00」）和时区；表单里给常用模板，输入后实时预览接下来 5 次触发时刻，表达式非法时红字提示、不能保存。固定间隔、一次性各有自己的输入。
参数按类型的 JSON schema 自动生成表单（字段名、类型、默认值、说明都来自任务类型自己声明的参数模型），可以切到 JSON 编辑；保存时服务端再校验一次。立即触发可以临时覆盖这一轮的参数，不改定义。
状态只有三种：启用 / 已暂停 / 运行中（带脉冲圆点，显示在哪个实例上跑、已跑多久；分片任务显示已完成片数）。系统机制也按这三种显示，只靠名称前的 🔒 区分。上一次的结果、失败原因不放在列表里，在详情的提示条和执行历史里看。任务类型已经从系统里移除的，显示「类型不存在」黄色标签，不再调度。
暂停与恢复暂停只影响以后的触发，正在跑的这一轮跑完为止；按钮旁有确认气泡。恢复后从下一个计划时刻开始，不补跑暂停期间错过的。
编辑冲突保存时带版本号；别人先改过时提示「已被 xx 在 hh:mm 修改」，提供「查看对方的修改」和「刷新后重新编辑」，不覆盖。
删除二次确认，说明「执行历史保留，到期自动清理」；预置任务只能停用、不能删除，删除按钮置灰并说明原因。
执行历史按时间倒序，可按结果筛选；每条显示触发时刻（计划的）、触发方式（到点 / 手动 + 操作人）、分片、实例、耗时、结果。失败展开看错误摘要和这一轮的参数；lost 表示跑它的实例中途没了，下一条通常就是重跑。
只读用户JobGuard.view 通过、operate 不通过的人：看得到全部内容，「新建任务」和行内操作不出现，详情底部只有「关闭」。原型顶部「切换为只读用户」可以看效果。
