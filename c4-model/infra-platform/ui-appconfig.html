设计说明

页面只调用应用配置库自带的管理接口（ConfigRoutes：列表、查看、改值、历史、回滚），宿主各自挂在自己的管理后台里；能不能看、能不能改由宿主实现的 ConfigGuard 决定。

主题规则
页面结构列表（按配置项前缀分组：sandbox、approval……）→ 点「修改」打开右侧编辑抽屉，点「历史」打开修改历史抽屉；回滚是确认弹窗。没有「新建」：配置项由系统在代码里定义，页面上只能改值。
当前值显示生效的值。没改过的旁边是灰色「默认」标签；改过的是蓝色「已修改」标签，下面小字显示默认值，方便对比。列表、映射超过 3 项只显示前 3 项和「等 N 项」。
按类型编辑整数、小数：数字框，按类型校验；开关：开关控件；文本：多行输入框；列表：一行一项，可以增删、上下移动；映射：键 + 值两列，键不能重复。列表和映射都可以切到 JSON 编辑。元素类型不对时红字提示，不能保存。
修改前后对比编辑抽屉底部实时显示「当前 → 修改后」，列表、映射按项标出增加和删除的，避免误删一项还不知道。
恢复默认编辑抽屉里单独一个「恢复默认」按钮（值清空，以后跟着代码里的默认值走），同样记一个新版本。已经是默认值时不出现。
修改说明可选，最多 500 字，记进历史。建议写「为什么改」，回头查历史时最有用。
生效范围保存按钮旁提示「保存后对所有实例立即生效（下一次读取）」；不是逐个实例生效，也不需要重启。
版本冲突保存时带上打开编辑时的版本号；别人先改过时不覆盖，提示「已被 xx 在 hh:mm 改成 …」，给出「用最新值重新编辑」。原型顶部「版本冲突」可以看效果。
历史与回滚每个版本一行：版本号、值（和上一版的差异）、修改说明、修改人、时间；最新的在前。任意一版可以「回滚到这一版」：确认弹窗里显示当前值 → 目标值的差异；回滚是把那一版的值写成一个新版本，不删除任何历史。当前这一版没有回滚按钮。
只读用户ConfigGuard.view 通过、edit 不通过的人：能看列表和历史，「修改」「回滚」按钮不出现。原型顶部「切换为只读用户」可以看效果。
