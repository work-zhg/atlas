    CLI 智能体接入记忆的原理（目标设计）

    一句话：记忆的语义全留在 server，CLI 只多拿到两样东西。一是系统提示词里追加的常驻块：开会话、恢复会话时经 ACP 的 _meta.systemPrompt.append 交给适配器，常驻块变了就以新提示词恢复 CLI 会话。二是三个 MCP 工具：由 bridge 在 Pod 里开的本机 MCP 提供，调用经 atlas.host.v1 回到 server，由和原生同一份的 MemoryTurn 执行。快照、版本表、写前必看、幂等、卡片和撤销都不用为 CLI 再写一遍；Pod 里也没有记忆服务的地址和令牌。CLI 自带的记忆（~/.claude 里的 CLAUDE.md 和自动记忆）不关，和 Atlas 记忆并存。下面五张图，场景同上面的时序图：用户隔了 40 分钟回到会话，期间在别的会话里改过「沟通偏好」（23 → 24），这一轮 CLI 用 save_memory 取代 #12。橙色是这次实际走的路，灰色虚线是没走的分支。现在的代码里这些都还没有，要做的改动列在最后。

    图 1　CLI 拿到记忆的路：常驻块、工具，加上照旧的补记

    1. 1常驻块进 CLI 的系统提示词：记忆组件算出常驻块（可写时加上写入指引），CLI 运行时在 session.open 里交给 bridge，bridge 用 ACP 的 _meta.systemPrompt.append 交给适配器，追加在 Claude Code 的预设提示词之后。和原生一样按会话存快照，只在该刷新时才变（图 2）。
    2. 2记忆工具：bridge 在 Pod 里开一个只听 127.0.0.1 的 MCP，CLI 看到的是三个普通的 MCP 工具（不可写时只有 load_memory）。调用经 tool.call 回到 server，由这一轮的 MemoryTurn 执行（图 3）。Pod 里没有记忆服务的地址和任何令牌，关联主键也只在 server 这边。
    3. 3会话后补记照旧：维护者读 message 表里这个会话的用户、助手正文（CLI 的回答也落在这里），补上漏记的。CLI 接上 save_memory 之后，补记对它和对原生一样，只补缺的部分。
    4. 4CLI 自带的记忆不关，和 Atlas 记忆并存：Atlas 不读不写它，记忆页也看不到（图 5）。

    图 2　常驻块：什么时候以新提示词恢复 CLI 会话

    1. 1CLI 的系统提示词在进程启动时就定了，中途换不了（和 MCP、模型一样）。所以 server 记下 CLI 会话现在用的是哪份追加（cli_session 里的哈希），每轮开始时比一次：一样就照常 attach；bridge 重启过需要 open 时，也带上同一份追加，CLI 看到的系统提示词不会因为重连而变。
    2. 2不一样就以新提示词恢复会话：session.open 带上 resume 和新的追加，bridge 发 session/resume。适配器按会话指纹（systemPrompt、mcpServers…）发现变了，重建 Claude Code 进程，从会话记录恢复上下文。这只发生在缓存本来就会失效的时候，不额外丢缓存，只多一次进程启动。
    3. 3恢复不成时沿用现在的处理：报 session.lost，新会话带上新的追加；新会话里只有常驻块，已知版本按首次处理。
    4. 4判据和原生同一份代码，只有两处不同：压缩由 CLI 自己做，不动系统提示词，所以不重建；CLI 的轮次在线等审批、不挂起，没有续跑段。

    图 3　工具调用：从 CLI 经 bridge 回到 server

    1. 1本机 MCP 只听 127.0.0.1，带一把本会话的随机密钥（随 MCP 配置交给适配器）。它对 CLI 来说就是一个普通的 HTTP MCP 服务，换别的 CLI 也一样能接。
    2. 2tool.call 是 atlas.host.v1 新增的 bridge → server 请求，和 permission.ask 同一种形态：带 turnId 和会话内序号；不属于本轮的直接拒绝；server 断线时在 bridge 里等着，重连 attach 后再交，等多久不限。处理它的是连着这个 bridge 的那个 server 实例，也就是正在跑这一轮的那个。
    3. 3执行的是这一轮的 MemoryTurn，和原生同一份代码：守卫、写前必看、幂等键、作废处理、版本推进都一样。CLI 没看过「工具链」就调 save_memory 时，同样不写，先把最新条目作为工具结果交回。
    4. 4卡片随 MCP 结果的 structuredContent 回到 CLI，CLI 报工具完成时带出来，翻译层认出 mcp__atlas__* 的结果，把卡片放进 tool.completed 的 artifact，和原生逐字段一致。适配器的 rawOutput 带不带 structuredContent 要验证；不带的话，CLI 运行时按工具名和参数把 tool.call 的结果对上。

    图 4　版本表：CLI 自己压缩之后

    1. 1更新提示拼在这一轮 prompt 的开头，用的是和原生同一个 MemoryTurn.reminders()，形状也一样（<system-reminder name="memory_updates">）。
    2. 2原生的压缩是 Atlas 做的，压缩后重建常驻块、重置已知版本；CLI 的压缩是 Claude Code 自己做的，Atlas 只能靠通知知道。bridge 在 ACP initialize 里声明 session.compaction 能力，适配器每次压缩都会发 compaction_update，bridge 原样经 agent.update 转交，翻译层认出它。
    3. 3认出后，已知版本里只留常驻主题（它们在系统提示词里，压缩不动），按需加载过、写入过的主题全部去掉并存库：之后加载会返回全部条目，保存会先把最新条目交回。常驻块本身不用重建。

    图 5　CLI 自带的记忆和 Atlas 记忆并存

    1. 1按拍板的方案，CLI 自带的记忆不关。它存在 /data/home/.claude，一人一份、跨会话保留，这个人的所有 CLI 会话都会加载；Atlas 不读、不写、不展示。
    2. 2代价是两套记忆可能重复或矛盾，用户也只能管 Atlas 那一套。约束只放在提示词上：写入指引让 CLI 优先用 save_memory。后面如果发现两边打架多，可以再改成关掉 CLI 自带的自动记忆（按 CLI 版本的设置项或环境变量）。

    为什么这样做

    做法为什么
    工具调用经 bridge 回到 server，不让 CLI 直连记忆服务或 Agent 服务记忆的语义（快照、版本表、写前必看、守卫、幂等、卡片）都在 server 的 MemoryTurn 里，回到 server 才能和原生共用一份；处理它的正是跑这一轮的实例，状态都在手边。Pod 里不放记忆服务地址和令牌，也不用放通 Pod → server 的入站；断线等重连的做法和 permission.ask 一样。
    本机 MCP，不改 CLIMCP 是 CLI 都认的工具接口，换别的 CLI 也能接；bridge 只转交，不理解参数。
    常驻块进系统提示词，不拼进每轮的 prompt系统提示词不受 CLI 压缩影响，前缀缓存也稳；拼进 prompt 的话会被压缩摘要掉，Atlas 还不知道，而且每次刷新都在历史里多一份。
    常驻块变了才以新提示词恢复会话CLI 的系统提示词进程启动时就定了。变的时机和原生刷新同一套判据，都是缓存本来就会失效的时候，重开不额外丢缓存。
    CLI 压缩后重置已知版本不重置的话，加载会误报「已在上下文中」，写入也不再基于完整内容。
    记忆工具免询问和原生一致：写入不审批，换来的是每次写入当场可见、一键撤销；只能取代或遗忘，都可以恢复。
    CLI 自带的记忆并存拍板的方案：不改 CLI 自己的行为，代价是两套记忆可能重复或矛盾（图 5）。

    和现在代码的差别：要做的改动

    地方改动
    atlas.host.v1（libs/host）session.open 加 systemPrompt.append；新增 bridge → server 请求 tool.call（turnId、callId、工具、参数 → content、structuredContent、isError）。
    bridge（pod/bridge）起本机 MCP（127.0.0.1，本会话密钥），把 server 给的工具清单挂上、调用转成 tool.call；open 时把追加放进 _meta.systemPrompt、三个工具放进 allowedTools；ACP initialize 声明 session.compaction。
    CLI 运行时（atlas_agent/cli）能力解析时调 MemoryRuntime.turn；比对 cli_session 里的追加哈希，变了就带新追加 open；prompt 前拼更新提示；接 tool.call 交给 MemoryTurn；翻译层认出 mcp__atlas__* 的卡片和 compaction_update。
    数据库cli_session 加一列：CLI 会话现在用的追加内容的哈希。
    记忆组件（atlas_agent/memory）MemoryTurn 加「已知版本重置为常驻主题」的入口（CLI 压缩时调）；写入指引给 CLI 多一句优先用 save_memory。其余不变。
    要先验证适配器的 tool_call_update 里 rawOutput 带不带 MCP 的 structuredContent；resume 换 systemPrompt 时恢复出的上下文是否完整。
