本机浏览器设计：本机智能体用电脑上的浏览器，画面经连接器到网页

一句话：本机 CLI 智能体也能用浏览器。浏览器跑在使用者自己的电脑上：一个画在虚拟屏幕上的有界面 Chrome，和沙箱浏览器是同一套组件，由连接器拉起。模型有两种操作方式，各配一个技能、按需选：快照（读清单、按编号点）和 computer use（看截图、用系统键鼠）。遇到登录就请人接管，虚拟屏幕的画面经连接器已有的那条连接传到 Atlas 网页上；登录态留在电脑上，不上传平台。打个比方：家里的助理用你书房那台电脑办事，只用旁边一台副显示器（虚拟屏幕），你的主显示器他不碰；要输密码时，他通过你们一直通着的电话把副显示器的画面投给你，你远程输完再交还给他。

这是沙箱浏览器设计（design-browser.html）的延伸：拍快照、按编号点、屏幕按对话分块、接管是审批的一种，这些都沿用，这里只写不同的地方。方案的背景、目标和取舍见方案设计（device-browser-design.html）。

先认识几个词

词意思例子
浏览器组件装在电脑上的一组程序：虚拟屏幕、有界面的 Chrome、画面服务、浏览器守护、browser 命令。和沙箱浏览器镜像里装的是同一套。电脑主人自己装。连接器的一条安装命令
computer use模型看屏幕截图，说出要点的坐标，程序用系统层面的键盘鼠标去点、去输入，和人坐在电脑前操作一样。要用能看图的模型。「点 (750, 257)，粘贴手机号」
Runtime 调试域调试接口（CDP）里管「在页面里执行脚本、收控制台输出」的那一部分。打开它，相当于替页面打开了开发者工具的「控制台」，有的网站能察觉。Playwright 一连上浏览器就会给所有页面打开它。zhipin 察觉后跳到 about:blank
画面流连接器和设备网关之间那条控制连接里新加的一路，专门传画面和键鼠，和会话流、文件流并列。人点「打开」接管时开一路

原理 1　浏览器在电脑上：同一套组件，三处不同

  1. 1谁来拉起：连接器。平台不能让电脑运行任意程序，只能请连接器做几件固定的事。模型第一次执行 browser 命令、或者人打开接管时，连接器按本机策略核对后拉起守护，守护再拉起虚拟屏幕、Chrome 和画面服务。一段时间没有命令、没人看画面、没有接管窗口，连接器就关掉它们，把内存还给电脑（一个 Chrome 约 0.5–1.5 GB）。
  2. 2profile 在哪：电脑主人目录下，长期保留。沙箱会被回收，所以那边要把登录态存到平台；电脑上的目录不会被回收，浏览器关了再开，登录还在。所以本机浏览器没有附加件，登录态不导入、不导出，交还时也不比较 cookie、不存。
  3. 3画面从哪出：控制连接里的画面流。电脑在路由器、防火墙后面，网页连不进去；画面服务只听 127.0.0.1，经连接器已有的那条连接出去（原理 5）。
  4. 4平台这边：浏览器宿主多一个实现。接管、画面只认浏览器宿主这个扩展点（原生、CLI、设备）。设备宿主把确保、开关接管窗口、画面都变成经设备网关请连接器做；审批、卡片、原样转发都不用改。

一台电脑一个浏览器：这台电脑上的几个会话共用一个 Chrome，各开各的窗口，cookie 是同一份。bridge 拉起 CLI 时带上会话名和对话 id，browser 命令据此找到自己的窗口和对话那一块屏幕。被委派的本机子智能体有自己的会话名，窗口也放在对话那一块里。首版只支持 Linux（含 WSL）：虚拟屏幕用 Xvfb，macOS 上没有现成的。

原理 2　两种操作方式，按需选

  1. 1普通网页用快照。读内容、填表、点按钮：按编号点不会偏，省 token，纯文本模型也能用。和沙箱浏览器同一套用法。
  2. 2这几种情况用 computer use：会检测自动化的网站（如 zhipin）、画布、地图、滑块和拖动、快照里找不到要点的东西、要读的内容在图片里。模型平台登记模型时标注能不能看图；会话开始时，平台经 bridge 的系统提示追加告诉 CLI 这次能用哪几个技能，不能看图的模型只给快照技能。
  3. 3限制（快照暂不换底层）：Playwright CLI 一连上，浏览器里所有页面都开了 Runtime，而且一直连着，直到浏览器重新拉起。所以一个浏览器里只要有会话用过快照，检测型网站就会被认出，computer use 也救不回来；浏览器闲置关停后重新拉起就恢复干净。computer use 技能里写明：页面突然变空白、跳到 about:blank，就停下告诉用户，不要反复重试。根治的办法是把快照换成修补连接（patchright，不开 Runtime），已验证可行，留到以后。

算例：怎么知道是 Runtime

同一个有界面的 Chrome 打开 zhipin 职位页，只改「怎么连浏览器」（大阪的云服务器，C 组在一台 Mac 上测）：

组怎么连结果
A只开调试端口，没有程序连着正常（未登录，被转到登录页）
B官方 Playwright 连上（快照现在就是这样）跳到 about:blank，读到 0 字
C直接用调试接口，只开 Page 域正常，职位列表都在
D直接用调试接口，比 C 只多开一个 Runtime 域跳到 about:blank
E修补版（patchright）连上正常，登录页能读出内容

C 和 D 只差一个 Runtime，结果一好一坏，所以原因就是它。

原理 3　computer use：只在自己那一块里看、点

  1. 1看：截这个对话那一块（1920×1080），缩到 1280 宽给模型。同一块里的接管窗口、网页弹出的窗口也截到，和人看到的画面一致；看不到别的对话。
  2. 2点：模型报的是截图上的坐标，守护乘缩放比例（1920 ÷ 1280 = 1.5）、加上这一块的左边界，换成屏幕坐标，再用系统键鼠（xdotool）去点。上图：(750, 257) → (1920 + 750 × 1.5, 257 × 1.5) = (3045, 386)。事件经 X 服务器进浏览器，网页分不出是人还是程序。
  3. 3输入和读字：文字先放进剪贴板再粘贴，中文也能输（逐键模拟输不了中文）；读文字是全选、复制、从剪贴板取整页纯文本，比看截图认字准。打开网址是在自己窗口的地址栏里用键盘输入。开会话窗口、接管窗口改用只管窗口的调试命令，不碰页面——临时连一下 Playwright 也会给所有页面打开 Runtime。

算例：模型点得准不准

同一张 zhipin 登录页截图（1280×624），让 MiniMax-M3 报 5 个元素的中心点，连问 3 次，和页面上的真实位置比：15 次里 13 次落在目标上。大按钮、输入框基本都准，11 像素的勾选框有一次偏了 20 像素。所以 computer use 技能要求每动一次就再看一眼，没点中就重来。不连调试接口时也实测过：键盘打开 zhipin、全选复制拿到整页 243 字、粘贴中文进输入框，页面都正常。

原理 4　人接管：经连接器开关窗口

  1. 1CLI 请求接管走 bridge 本机 MCP 上的平台工具，和会话 Pod 里的 CLI 智能体是同一条通道。用工具而不用 Shell 命令：Shell 命令有执行时限（Claude Code 的 Shell 最长 10 分钟），接管却不设期限。
  2. 2CLI 在线等：这一轮仍在跑，标为等人处理，bridge 和 CLI 一直在电脑上。等的时候连接断了，按本机 CLI 方案的断线恢复办；连接器或电脑重启了，bridge 不在了，这一轮以失败结束，接管随之作废。
  3. 3平台先核对是会话创建人，再看电脑在线、装了浏览器组件、本机允许查看画面（来自连接器上线时的报告）。不满足就把原因写在卡片上（「你的电脑不在线」），不说「系统忙」。
  4. 4画面怎么走见原理 5；人在画面里的输入直达浏览器窗口，不进模型的上下文，也不进日志。
  5. 5交还时只关窗口：电脑上的浏览器不会被回收，登录就留在它的 profile 里。点「不处理」也关窗口，结果是「用户没有接管」和原因。
  6. 6工具结果和沙箱浏览器一样，提示模型先重新看一眼页面再接着做。

原理 5　画面怎么到人眼前：控制连接里的画面流

  1. 1控制台这一头和沙箱浏览器完全一样：接管卡片里的画面、对话头的「浏览器」按钮、新标签、全屏、复制粘贴。Agent 服务按会话的浏览器宿主选路：沙箱走沙箱的画面通道，设备走设备网关。画面不要口令：画面服务只听电脑的 127.0.0.1，谁能看由 Agent 服务核对本人、设备网关核对设备，两处已经做完。
  2. 2画面流是控制连接里的第三种通道，发送顺序是：控制帧 → 会话流 → 画面流 → 文件流。画面数据比对话消息大得多，排在会话流后面才不会让对话变慢；人在打字、点按钮，又比看文件急。每一路有自己的窗口，画面这一路堵住只关它自己，控制台提示「画面断了」，点一下重连。
  3. 3画面流只带会话和对话，不带地址和端口：连接器自己找本机画面服务，平台借画面流连不到电脑上的其他程序。连着画面算浏览器在用，不会被闲置关停。

算例：画面有多大、多快

项估算怎么算的
一整块屏幕的原始大小约 8 MB1920 × 1080 个像素，每个 4 字节
打开一个登录页（整块都变）约 100–300 KB画面服务只传变了的区域并压缩；网页大多是大片纯色和文字，压缩比高
输入一个字符几 KB只有输入框和光标那一小块变

原理 6　边界：平台多拿到了什么，限制在哪

问题怎么限制
谁能看画面只有本人：请求者、会话创建者、设备主人必须是同一个人，每次打开画面都核对
能看到什么只有浏览器所在的虚拟屏幕，而且只看本对话那一块；电脑的真实桌面、其他程序的窗口都不在上面
平台能不能借画面流连别的东西不能：画面流不带地址和端口，连接器只接本机浏览器的画面服务
电脑主人能不能拒绝能：本机策略关掉「远程查看浏览器画面」，接管和看画面都打不开；不装浏览器组件就根本没有浏览器
电脑上有没有对外开的口子没有：虚拟屏幕、调试接口、画面服务都只听 127.0.0.1，电脑只往外连
computer use 会不会点到别的对话不会：截图只截自己那一块，坐标换算后越界就拒绝
密码会不会被模型看到人输的密码只经画面进浏览器窗口，不进模型的上下文。CLI 和浏览器以同一个电脑用户运行，CLI 读得到 profile 里的 cookie——和沙箱浏览器是同一个取舍，在自己电脑上本来如此

设计决策

决策理由
浏览器画在电脑上的虚拟屏幕里，不用电脑主人日常的 Chrome不打扰电脑主人，不碰他的书签、密码、已有登录；远程只共享这一块，不共享真实桌面。代价是和日常浏览器的登录不通
电脑上用和沙箱同一套浏览器组件分块、窗口、弹窗、复制粘贴这些在沙箱上已经做好，沿用不重来；网页上的接管、画面页面也就完全一样
设备是浏览器宿主的第三个实现接管、画面只认扩展点，审批、卡片、原样转发都不用改
浏览器由连接器拉起，闲置关停平台只能请连接器做几件固定的事；Chrome 吃内存，闲置就还给电脑，profile 留着所以登录不丢
画面经控制连接里的画面流，不开端口、不直连电脑在路由器、防火墙后面；复用在线表和本人核对，不多一套鉴权。代价是画面绕道平台，多几十到上百毫秒
画面流排在会话流之后、文件流之前画面数据大，不能挤占对话；人在操作，又比看文件急
登录态留在电脑上，不上传、不和沙箱互通profile 不会被回收，不需要平台保管；少一份个人数据出电脑；登录常和设备环境、IP 绑定，搬来搬去反而触发风控
加 computer use，和快照各配一个技能、按需选computer use 不经过调试接口，检测型网站认不出；画布、滑块也能做。快照点得准、省 token、纯文本模型也能用，普通网页仍以它为主
快照暂不换底层先用改动小的 computer use 覆盖检测型网站。代价是同一个浏览器里用过快照，这类网站就会被认出，要等浏览器重新拉起；根治（换修补连接）已验证可行，留到以后
CLI 用平台工具请求接管，不用 Shell 命令Shell 命令有执行时限，接管不设期限；同一条通道也补上沙箱 CLI 智能体的接管
首版只支持 Linux（含 WSL）虚拟屏幕用 Xvfb；macOS 以后可以用容器跑同一套组件，平台这边不用改

改到的现有部分

部分改什么
智能体配置、模型平台本机 CLI 智能体也能开「浏览器」（现在保存时拒绝），开了不换镜像；模型登记时标注能不能看图，决定给不给 computer use 技能
连接器新增「本机浏览器」：上线报告带浏览器组件，拉起、闲置关停守护，开关接管窗口，画面流接到本机画面服务；本机策略加「远程查看浏览器画面」和闲置时长；安装浏览器组件的命令
设备网关控制连接里多一种通道「画面流」，优先级在会话流之后、文件流之前；转发开关接管窗口的控制请求
Agent 服务 · 浏览器浏览器宿主多一个实现「设备」：确保只核对、开关接管窗口和画面经设备网关；交还时不存登录态；画面按宿主选路
bridge、CLI 运行时bridge 本机 MCP 上的平台工具 request_takeover（沙箱 CLI 智能体同用）；拉起 CLI 时带会话名和对话 id；系统提示追加告诉 CLI 能用哪几个浏览器技能
浏览器守护、browser 命令加 computer use 的子命令（截本对话那一块、按坐标点击拖动滚动、粘贴、按键、全选复制、键盘打开网址），键鼠本机排队；开窗口改用只管窗口的调试命令；快照仍是 Playwright CLI；技能拆成快照、computer use 两个。沙箱镜像加上键鼠工具后同样能用
控制台接管卡片、画面页不变；补上电脑不在线、本机不允许查看画面时的提示；「我的设备」显示浏览器组件状态；「我的登录」注明只含平台保管的登录态
