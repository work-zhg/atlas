本机 CLI 智能体设计：CLI 跑在用户自己的电脑上

一句话：电脑主动连出，平台通过这条连接找到电脑；会话的消息原样转发，凭据留在平台。用户电脑上的连接器连到设备网关，一直不断开；平台要开会话、读文件，都在这条连接上开一路。Agent 服务连设备网关上的会话，和连会话 Pod 里的 bridge 用法一样，协议、断线补发、审批都不改。CLI 调模型、MCP、知识库时，只有一个会话令牌，真实的 Key 由设备网关在转发时换上。

打个比方：你住在酒店房间里，外面的人打不进你的房间（电脑在路由器、防火墙后面），但你可以主动打给前台并一直不挂（连接器连出）；有人找你，前台就在这条线上转给你（设备网关）。你要订餐也打给前台，由前台用酒店的账户付钱（凭据代持），酒店的信用卡始终不交到你手上。方案的取舍和产品形态见方案设计稿，这里讲机制，各图的链接在文末。

原理 1　电脑主动连出，一条连接跑多路

平台连不进电脑：电脑在家用路由器、公司防火墙后面，地址还会变。反过来，电脑访问平台的 HTTPS 入口就像打开网页，几乎处处可行。所以连接永远由电脑发起：

  1. 1连接器带着设备令牌连上设备网关，连上就报告系统、版本、装了哪些 CLI、本机允许的目录。断了按退避间隔一直重连，不设上限；只有被拒（令牌无效、版本太旧）才停下，提示重新配对或升级。
  2. 2一台设备只有这一条连接，会话流、文件流都在里面多路复用。每路有自己的发送窗口和缓冲上限：会话流先走，文件内容 64 KB 一块穿插着发；某一路长时间堵住只关这一路，被关的会话流靠 bridge 的断线补发恢复。
  3. 3设备网关把「这台设备在线、连在实例 X」写进在线表，心跳约 25 秒一次、顺带续期；实例崩溃时它写的条目自己过期。
  4. 4Agent 服务的任何实例要找这台设备，查在线表、直接连实例 X。所有通道都在实例 X 上，网关实例之间不需要转发，也不依赖入口的粘性路由。设备换到实例 Y 重连后，下一次查在线表自然连到 Y。

原理 2　会话地址和 bridge 一样：只转发，不解析

会话 Pod 里，Agent 服务的上游连接直接连 bridge。换到用户电脑上，中间多了设备网关和连接器两跳，但它们只转发、不解析，两端看到的是同一套消息：

  1. 1设备网关收到 Agent 服务的连接，按会话取出登记（在哪台设备、启动参数），在设备的控制连接上开一条会话流，把启动参数作为开流的头交给连接器。之后两边的帧原样对转。
  2. 2连接器按本机策略核对（目录、CLI、权限模式上限、会话数），bridge 不在就在项目目录里拉起（命令取本机配置），把会话流接到 bridge 的本机回环地址上。
  3. 3序号、确认、补发、审批都由 Agent 服务和 bridge 两端处理。所以断线恢复的做法和会话 Pod 完全一样：重连、attach、从最后确认的序号之后补发，不缺不重。

中间两跳只做一件和协议有关的事：关闭原因原样传给另一端。Agent 服务的重连策略按关闭原因判断要不要重连，传错了要么空等，要么提前放弃：

发生了什么Agent 服务收到接下来
bridge 说会话已结束、或被新连接取代原样不重连
电脑睡眠、网络断开、设备不在本实例、网关发版可以重连按退避间隔一直重连，不设窗口；网页显示「等待你的电脑重新连上」，用户可以取消
连接器或电脑重启过（bridge 已不在）attach 得到 bridge_restarted这一轮以失败结束并说明；下一轮 CLI 按记下的会话 id 接着原来的上下文
本机策略拒绝（目录不允许、CLI 没配置…）不可重连 + 原因这一轮失败，原因原路显示在网页上
开始前电脑就不在线DeviceOffline（没连上）立即失败：「你的电脑不在线，请启动连接器」

原理 3　凭据代持：电脑上只有会话令牌

智能体的模型 Key、MCP Key 是这个智能体所有使用者共用的，放到某个人的电脑上，就等于交给了所有能碰到这台电脑的人。所以真实凭据留在设备网关，电脑上的 CLI 只拿一个会话令牌：

  1. 1每一轮，Agent 服务照常组装能力，再把每个上游（模型、每个 MCP 服务、知识库）的真实地址和真实请求头登记到设备网关，连同启动参数。
  2. 2第一次登记时网关生成会话令牌，之后每轮沿用同一个，只整份覆盖上游。回执是令牌和每个上游在网关上的地址（/u/m1、/u/s1…）。
  3. 3Agent 服务把能力改写成 CLI 看到的样子：地址指向网关、凭证只有会话令牌，经会话流在 session.open 时交给 CLI；模型接入随启动参数交给连接器、放进 CLI 的环境变量。
  4. 4CLI 照常调模型、MCP、知识库，带的是会话令牌。
  5. 5能力代理按令牌摘要找到登记，取出编号对应的上游，把设备带来的认证（Authorization、x-api-key）和身份（X-Uid 等）全部去掉，换上真实凭据，身份按登记写入使用者本人，流式转发、原样传回。

为什么令牌整个 CLI 会话不变、上游却每轮覆盖：CLI 进程启动时读一次地址和令牌，中途换不了；而真实凭据只在网关一侧，换了 Key、收回了授权，下一轮（MCP 是下一个请求）就生效，不用重启 CLI。会话删除、设备吊销时登记作废，令牌随之失效。权限按使用者本人判断：令牌就在使用者自己的电脑上，他可以绕过 CLI 直接发请求，但只能做本人本来就能做的事。

原理 4　运行位置：CLI 运行时的一个扩展点，两种实现

CLI 运行时（一轮的编排、上游连接、权限转发、内容翻译）不知道 CLI 在哪。它只向「运行位置」要两样东西：一个能连的 bridge 地址，和下发给 CLI 的能力。会话 Pod 和用户设备各实现一份：

会话 Pod用户设备
bridge 在哪平台集群里，按人共享的 Pod用户电脑上，每个会话一个进程
谁拉起 bridgeAgent 服务经 execd连接器，命令取本机配置
CLI 拿到的能力集群内地址 + 智能体的 Key设备网关地址 + 会话令牌
出站凭据（git 等）经 Credential Vault 注入不注入，用电脑上本人的
工作目录对象存储上的工作区，挂进 Pod电脑上的项目目录，建会话时定
网页上看文件读对象存储，可上传经设备网关现读，只读
拿不到时建不起来报「系统忙」电脑不在线，报「你的电脑不在线」
隔离沙箱没有：CLI 以电脑主人的身份工作，靠审批和本机策略约束

原理 5　设备和项目目录怎么定

CLI 的会话记录存在那台电脑那个目录里，换了就接不上之前的上下文，所以设备和项目目录在建会话时定下、写进会话、之后不变。定的规则只有两条：

委派用根会话的 id，是为了同一个对话里的多次委派落在同一个目录，和平台上「子智能体与主智能体共用工作区」的规矩一致。区别在于：主智能体在平台上、子智能体在电脑上时，两边看不到对方的文件，交接只靠任务书和结果。默认目录不存在由连接器建；用户选的已有目录不存在就拒绝，多半是选错了。没有默认设备、默认设备不在线，委派立即失败，原因交还给主智能体。

直接新建时选「已有项目」，网页上列出这台电脑每个允许目录下一层的子目录名，并标出哪些是 git 仓库：经设备网关请连接器列，不往下展开、不读文件内容，以点开头的不列。它不属于哪个会话，不受「远程查看文件」开关限制，但仍只在允许的目录里。

智能体编辑页的调试预览也是一个会话，按第三条规则定：编辑者自己的默认设备，目录「默认项目地址 / 调试会话 id」。编辑者没有默认设备、默认设备不在线时，调试预览不可用，并提示配对或启动连接器。

原理 6　本机文件：打开时现读，在电脑上把关

文件留在电脑上，不同步、不做快照；网页上要看时，经设备网关开一条文件流，请连接器现读。预览站点和它的安全响应头仍是 Agent 服务那一份，只是读文件的来源换了。路径能不能读，由连接器在电脑上判，不信任平台给的路径：

网页上要读的路径（项目目录 ~/code/shop-web）结果为什么
src/app.ts读六关都过。版本按大小和修改时间算，没变就回 304、不传内容
../../.ssh/id_rsa拒绝② 整理后是 ~/.ssh/id_rsa，④ 不在项目目录里
docs/home（一个指向 ~ 的符号链接）下的文件拒绝③ 解析后到了项目目录外，④ 不过——只看字面路径会被这种链接绕过
.env拒绝⑤ 以点开头；和平台上看工作区文件的规则一致
certs/server.pem拒绝⑥ 电脑主人配了 *.pem 的拒绝规则

文件抽屉分两个页签：「改动」是 git 里还没提交的改动（包括电脑主人自己改的），「全部」按目录一层层加载。只读：文件流的协议里没有写的操作。大小上限（预览 20 MB、下载 200 MB）在平台这一侧判，读运行期配置。电脑离线时返回「设备离线」，界面说「你的电脑不在线，启动连接器后自动恢复」。

设计决策

决策理由
连接只由电脑发起，平台从不主动连电脑电脑在路由器、防火墙后面，地址会变，平台连不进去；只要求电脑能访问 HTTPS 入口，不用开端口、装 VPN。组网（VPN）会让个人电脑进入集群网络，端口映射的认证和平台里的人对应不上，都不选。
设备网关独立部署，不放进 Agent 服务Agent 服务发版频繁，放在一起每次发版所有电脑都会掉线；run 可能在任何一个 Agent 服务实例上执行，设备连在哪个实例就得在实例之间转发。
一台设备一条控制连接，会话流和文件流多路复用按在线表找到设备所在的网关实例就够了，所有通道都在那里，实例之间不转发；一条加密连接经过路由器和公司代理也更稳定。
会话地址和 bridge 用法一样，中间只转发不解析CLI 运行时的上游连接、bridge 都原样复用，断线补发、审批的做法和会话 Pod 完全一样；上游协议升级时网关和连接器不用跟着改。
真实凭据不出集群，电脑上只有会话令牌智能体的 Key 是所有使用者共用的；会话令牌只对一个会话有效、随时可作废，换 Key、收回授权不用重启 CLI。
权限按使用者本人判断会话令牌在使用者自己电脑上，可以绕过 CLI 直接用；按本人的权限，就不会成为越权的通道。
运行位置是 CLI 运行时定义的扩展点依赖倒置：CLI 运行时只说要什么（地址和能力），会话 Pod 和用户设备各自实现；新增运行位置不改 CLI 运行时。
设备和项目目录建会话时定、不改；委派用默认设备和「默认项目地址 / 根会话 id」CLI 的会话记录在那台电脑那个目录里；委派时没人选，用根会话 id 让同一个对话的多次委派共用一个目录。
本机策略优先，启动命令由本机配置决定平台能让电脑干活，但不能让电脑运行任意程序；哪些目录能用、权限能放多大，由电脑主人决定。
本机文件打开时现读、只读，不同步不快照把代码留在电脑上往往就是为了不上传；同步还会占带宽、和电脑上的文件对不上。代价是电脑离线时看不到文件。
不设运行和重连的时限电脑睡眠时 CLI 也停了，醒来接着做；断线只是通道断了，按关闭原因一直重连，用户随时可以取消。
