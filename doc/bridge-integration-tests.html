1. agent 子进程：bridge/tests/test_agent_process.py

验证 bridge 与 agent 之间的 stdio 管道和进程生命周期。这类问题只有真进程才暴露得出来。

#用例场景关键断言
1test_line_roundtrip 经 stdio 发一个 initialize，收响应 返回 protocolVersion == 1
2test_environment_is_not_inherited 安全bridge 自身带有敏感环境变量时启动 agent agent 只能看到白名单变量（ONLY_THIS），看不到 BRIDGE_SECRET
3test_oversize_line_is_skipped_and_the_next_frame_survives agent 输出一行 200 KB 的 update（上限 64 KB），紧跟一个权限请求 只丢掉超长的那一行，后面的 session/request_permission 照常收到；on_oversize 回调触发 1 次，并带上大小和行首片段
4test_stderr_is_collected_and_truncated agent 往 stderr 写一行普通日志和一行 5000 字符的长日志 能收到 stderr；长行被截断到 stderr_line_bytes（100）
5test_terminate_kills_the_whole_process_group agent 自己又拉起一个子进程，然后 bridge 终止 agent 孙进程也被一起杀掉，不留孤儿（os.kill(pid, 0) 抛 ProcessLookupError）
6test_exit_is_observable_and_send_after_exit_fails agent 在 prompt 中途崩溃（exit 3） receive() 返回 None，wait() 返回 3，之后再 send 抛 ChannelClosed
7test_sigterm_ignored_escalates_to_sigkill 进程忽略 SIGTERM 宽限期（0.5s）过后升级为 SIGKILL，5s 内结束，退出码为负

2. bridge 端到端（上游协议）：bridge/tests/test_upstream_e2e.py

BridgeApp 监听随机端口，测试用 UpstreamProbe 扮演 server，按 atlas.host.v1 协议通信。

#用例场景关键断言
握手与健康检查
1test_health_endpoints 访问 HTTP 探针 /healthz → 200 ok；/readyz → 200 idle；未知路径 → 404
2test_handshake_is_rejected_before_upgrade
参数化 ×3		 安全token 错误 / session_id 不匹配 / 子协议不支持 在 WebSocket 升级之前就拒绝，分别返回 401 / 403 / 426
3test_missing_token_is_401 安全完全不带 token 去连 401
4test_subprotocol_is_negotiated 客户端同时提供 v9 和 v1 协商结果为 atlas.host.v1
一轮对话
5test_a_full_turn_over_websocket open → turn.start → 正常结束 → ack open 返回 ACP 信息和 bridge 实例 id；消息顺序为 running → update×2 → ended；seq 从 1 开始严格递增、不跳号；ack 之后 outbox 缓冲清空
6test_permission_round_trip_over_websocket agent 请求权限，上游回复 allow permission.ask 带整数 id、选项、expiresInS=600；状态依次为 running → awaiting_permission → running → ended；agent 确实收到了批准
7test_cancel_over_websocket agent 一直不出声，上游发 turn.cancel 立即返回 cancelling；最终结果 cancelled / requested
错误码
8test_error_codes 依次触发各类协议错误 未 open 就 start → -32010 not_opened；重复 open → -32011；空 prompt → -32602；并发两轮 → -32012（带上进行中的 turnId）；取消不存在的轮次 → -32013；未知方法 → -32601
连接管理
9test_new_connection_supersedes_the_old_one 同一会话先后建立两条连接 旧连接以 SUPERSEDED 关闭；新连接照常工作
10test_session_close_closes_with_4410_and_later_connections_too 一轮进行中调用 session.close 这一轮先以 session_closing 结束；连接以 4410 SESSION_GONE 关闭；之后的新连接也会收到 4410；进程不退出，等待 Pod 回收
11test_turn_survives_a_disconnect_and_attach_resends 断线等待审批时断线，重连后 session.attach 断线不会结束这一轮；attach 之前什么都不发；attach 返回 in_turn / awaiting_permission，resendFrom = lastSeq+1；补发的 seq 连续，权限询问沿用原 id；响应排在补发消息之前；批准后正常完成
12test_attach_to_a_restarted_bridge_is_refused 拿旧的实例 id 去 attach -32010 bridge_restarted，并返回当前实例 id
13test_already_open_tells_the_instance 会话已经 open，再次 open 错误数据里带上 bridgeInstance 和 agentSessionId，供 server 改用 attach
14test_turn_is_cancelled_when_upstream_does_not_come_back 断线断线后超过重连窗口（0.3s）仍未回来 这一轮以 upstream_lost 取消；结果留在缓冲里，之后 attach 仍能取到
故障恢复
15test_agent_crash_is_recovered_over_websocket 崩溃SIGKILL 杀掉 agent 进程 推送 session.state=ready，restarts=1；FakeAgent 不持久化会话，所以 resumed=false，并且换了新的 agentSessionId（如实上报）；之后新的一轮正常完成

3. server ↔ bridge：tests/test_host_runtime.py

server 侧的 HostRuntime.run_turn 直连真实的 BridgeApp，产出 TraceEvent 流；审批、会话存储、取消信号、Pod 分配都用替身。

#用例场景关键断言
正常路径与会话
1test_a_full_turn 完整的一轮 事件依次为 run.started → message.delta×2 → message.completed → usage.updated → run.finished；seq 连续；文本正确拼接；agent_session_id 当场持久化
2test_second_run_on_the_same_pod 同一个 Pod 上跑第二轮（open 返回 ALREADY_OPEN） 正常 run.finished，不出现 session.lost
3test_resume_on_a_new_pod_that_lost_the_session_is_visible 在新 Pod 上恢复一个已经丢失的会话 产出 session.lost 让用户看到；记下新的会话 id；这一轮照常完成
审批
4test_permission_approved 审批通过 approval.required 出现在 tool.started 之后，且带上工具名；之后是 tool.completed，没有 tool.failed
5test_permission_rejected_says_why 审批被拒绝 tool.failed 的 result 为「用户拒绝了这次调用。」；正文非空，所以这一轮仍是 run.finished
6test_expired_ask_is_withdrawn_and_marked 审批超时（0.5s），一直没人答复 审批行被标记为 expired；tool.failed 说明是超时、按拒绝处理；这一轮正常结束
7test_silent_rejection_is_a_failure 工具被拒绝，而且 agent 一个字都没输出 run.failed，error_kind=subagent_silent（end_turn 不能当作成功）
取消、超时与故障
8test_cancel 运行 0.5s 后用户取消 run.cancelled
9test_deadline_is_enforced_by_the_bridge timeout_s=1，agent 一直不出声 run.failed，run_timeout（截止时间由 bridge 执行）
10test_agent_crash_mid_turn 崩溃agent 在一轮中途崩溃 run.failed，runtime_crashed
11test_pod_unavailable Pod 分配失败（quota） pod_unavailable
12test_bridge_unreachable bridge 地址不通 runtime_unreachable
13test_wrong_token_is_unreachable_not_a_hang 安全token 错误 快速失败（不会挂住）：runtime_unreachable，消息里带 401
断线、重连与 attach
14test_next_run_attaches_instead_of_opening 第二轮复用已知的 bridge 实例 走 attach 而不是 open；全部消息都已确认，bridge 缓冲清空
15test_disconnect_mid_turn_reconnects_and_the_approval_is_not_duplicated 断线等待审批时网络抖动（1011），重连后才被批准 approval.required 只出现 1 次，只登记了 1 条审批，没有 expire；工具完成；事件 seq 连续
16test_bridge_restarted_mid_turn_is_bridge_lost 断线一轮中途断线，重连时发现实例 id 变了 bridge_lost；server 忘掉这个实例，下一轮重新 open
17test_superseded_connection_does_not_reconnect 另一条连接接管了会话 不再重连：runtime_unreachable，消息里说明被「取代」
18test_server_that_forgot_the_bridge_attaches_via_already_open server 重启后丢了进程内记忆 open 得到 ALREADY_OPEN 并拿回实例 id，改用 attach，这一轮正常完成

缺口说明
真实 ACP adapter所有自动化用例都用 FakeAgent；与 @zed-industries/claude-code-acp 的协议兼容性（能力位、session/resume 能否真正恢复）只有 deploy/local/acp_smoke.py 手动验证
会话真正恢复成功FakeAgent 是独立进程，不持久化会话，所以真进程场景下只测了 resumed=false 的分支；resumed=true 的分支只在组件层 test_recovery.py（进程内 agent）覆盖
容器启动python -m atlas_bridge 加环境变量的启动路径没有自动化用例；tests/test_cluster_host_bridge.py 只校验模板生成的环境变量能被 BridgeConfig 解析
