2. 目标、分期与服务形态

2.1 分期

期atlas-server（运行时）atlas-config（配置端）
P1 跑通技能链路 修 G1、G2；configplane/ 客户端 + 永久版本缓存；技能 / MCP 只读 API； 保存时钉死技能版本、记录 MCP 工具指纹；skill.loaded 等事件与用量统计 新建服务；技能两张表；发布流水线（解析 + 机械扫描 + 上传）以命令行提供； 运行时只读接口 + 管理端只读接口
P2 管理闭环MCP 目录切到 ConfigPlaneCatalog；按复核结果过滤工具 上传 / 异步扫描 / 人工审查 / 停用 / 紧急下架的 HTTP 接口；MCP 注册表增删改与工具复核；审计表
P3 凭证与收口ACP 改发网关会话令牌user 作用域 OAuth、经 Higress 收口

非目标：租户自建技能（skill.html §10 建议本期不开放）；stdio 类型 MCP server 托管；技能内容怎么写；计费。

2.2 为什么独立成服务，而不是 server 里的一个模块

A：server 内模块，共用数据库B：独立服务 atlas-config（推荐）
工作量最少：直接调函数、同一事务多一个进程、一个数据库、一层 HTTP 客户端
归属技能的审查发布和会话执行混在一个进程，谁拥有技能有两个答案技能与 MCP 注册表只有一个所有者（与 cluster 拥有 Pod 生命周期同理）
发布节奏改审查规则要重新部署运行时，打断在途会话的连接独立部署，运行时不受影响
权限运行时进程需要技能区的写权限只有 atlas-config 能写 _skills/；运行时只读
运行时可用性—运行时按版本永久缓存，atlas-config 宕机时已用过的技能照常工作
以后拆分同语言共库，很快会出现跨模块直接查表，再拆就是数据迁移边界从第一天就由 import-linter 和独立数据库保证
同语言最大的风险是「顺手 import」：两边都是 Python，server 直接 import atlas_config.db 去查表只要一行。 所以和 cluster 一样，用 import-linter 规定 server 只能 import atlas_config.schemas，atlas_config 不能 import 任何其他 atlas_* 包，违反即 CI 红。

3. 总体架构与职责划分

职责atlas-configatlas-server
技能内容与版本权威：解析、审查、发布、停用、下架只读消费；拿不到草稿（内部接口根本不返回）
技能被谁引用不知道权威：引用在 agent_version.spec 里；提供反查接口
技能用量不知道权威：skill_usage_daily
MCP server 定义权威（P2）只读；P1 仍来自环境变量
MCP 工具发现不做权威：发现、缓存、digest、变更检测
MCP 工具复核结论权威（P2）按结论过滤工具
凭证只存占位符，永远看不到真值解析占位符、发起连接
调用方向只有一个：server → config（只读）。 管理页需要的"被谁引用""用量""MCP 当前工具定义"都在运行时，前端直接向 server 要，不让 config 反向调 server。 MCP 复核时，前端把从 server 拿到的 digest 提交给 config 记录；config 不需要（也无法）验证它。
对 structure.html 的两处修正： ① 配置端语言由 Java 改为 Python，仓库从独立的 atlas-config/ 改为本仓 workspace 成员 config/； ② 它把"MCP 工具目录探测"放在配置端，但又规定凭证只在运行时进程里——两条不能同时成立。本设计保留"凭证不出运行时"，探测留在 server。评审通过后同步修改 structure.html。

5. 技能：数据模型与生命周期

5.1 表（atlas_config 库）

class Skill(Base):
    __tablename__ = "skill"
    slug        = String(63), primary_key          # ^[a-z][a-z0-9-]{0,62}$；P2 不开放租户自建，暂不加 org 前缀
    source      = String(16)                       # builtin | tenant | imported
    origin_url  = Text, nullable                   # imported 必填：第三方出处
    created_by  = String(255)                      # iam 的用户标识（sub）
    created_at

class SkillVersion(Base):
    __tablename__ = "skill_version"
    slug, version                                  # 复合主键；version 从 1 递增，草稿不占号（发布时分配）
    id          = UUID, unique                     # 草稿阶段用它寻址
    status      = String(16)                       # pending_review | rejected | published | disabled | revoked（实现：无 draft/scanning，见 §20）
    description = Text                             # 来自 frontmatter，发布后不可改
    frontmatter = JSON
    storage_key = Text                             # 草稿：_skills_drafts/{id}/；发布后：_skills/{slug}/{version}/
    content_hash= String(80)                       # sha256(排序后的 [路径, 文件哈希] 列表)
    size_bytes, file_count, has_scripts
    files       = JSON                             # [{path, size, sha256, executable}]
    scan_result = JSON                             # 各层结论与命中项
    reviewed_by, reviewed_at, review_note
    status_reason = Text
    published_by, published_at
    updated_at
    # 约束：一个技能同时只有一个 draft/scanning/pending_review
    #   partial unique index (slug) WHERE status IN ('draft','scanning','pending_review')
    # 约束：status='published'|'disabled'|'revoked' 时 version 非空

草稿阶段 version 为空——审查不通过的草稿不该消耗版本号，否则清单里会出现"v4 不存在"的空洞。

5.2 生命周期

规则原因
published 之后包内容、description、content_hash 永不修改；只有 status / status_reason 可变运行时按版本永久缓存；描述是模型的路由依据，改描述等于改行为
revoked 不可撤销（要恢复只能发新版本）；disabled 可以重新启用下架是安全事件，撤销会让"已处理"的问题静默回来
不提供物理删除引用关系在运行时，配置端无法判断"引用归零"；停用 / 下架已覆盖所有止损场景
审查人 ≠ 上传人四眼原则；含脚本的技能等同代码评审
扫描规则升级后可 rescan 存量版本：结果只追加到 scan_result.history，不改内容；发现问题走下架新规则常能发现老技能里漏掉的问题

6.1 一份代码，两个入口

async def approve(version_id: UUID, *, reviewer: str, note: str) -> SkillVersion: ...
async def publish(version_id: UUID, *, actor: str) -> SkillVersion:

6.2 各步骤

步骤检查 / 动作失败处理
1 归档安全拒绝符号链接、绝对路径与 ../、设备文件、二进制可执行文件（按魔数）；解压后总大小 ≤ 20MB、文件数 ≤ 500、单文件 ≤ 5MB（可配置）blocker → rejected
2 结构SKILL.md 存在；frontmatter 是合法 YAML 且有 name、description；name 与 slug 一致；description ≤ 1024 字符blocker → rejected
3 内容模式私钥 / 云密钥 / Bearer token 模式；curl … | sh 等危险命令；"忽略之前的指令""你现在是"等注入特征；可疑外部地址只记 warn，交给人工审查判断
描述冲突与其他已发布技能描述做相似度（字符 3-gram Jaccard）；> 0.8 记 warnwarn
4 人工审查has_scripts 或 source != builtin 时必经reject 必填理由
发布事务内：取 max(version)+1（行锁 skill）→ 拷贝对象 → 列出目标前缀核对对象数与 content_hash → 改 status=published拷贝失败回滚事务；残留对象下次发布前清理（目标前缀非空且库里无对应版本 = 残留）

P2 的异步扫描：上传请求只做步骤 1–2（同步、快），然后状态置 scanning，由进程内后台任务做步骤 3。 状态在库里，进程重启时把 status='scanning' 的行重新入队——不需要引入消息队列。

7. 技能：运行时消费

7.1 configplane/（server 侧新增）

class SkillDirectory(Protocol):
    async def catalog(self) -> list[SkillCatalogItem]: ...                # 编辑器选择器
    async def get(self, slug: str, version: int) -> SkillVersionOut: ...   # 不存在 → SkillUnavailable
    async def latest(self, slug: str) -> SkillVersionOut | None: ...       # 只看 published
    async def revoked(self) -> frozenset[tuple[str, int]]: ...

# HttpSkillDirectory —— 调 atlas-config /internal/skills/*（类型直接用 atlas_config.schemas）
# FakeSkillDirectory —— 内存实现，单测用
数据缓存策略原因
get(slug, version) 的内容字段内存 + 磁盘（var/cache/configplane/），永久版本不可变。若同一版本拿到不同 content_hash：用缓存并告警（对方破了契约）
status、revoked()TTL 60 秒；拉取失败时继续用上一次结果可变状态；下架要在一分钟内生效，配置端短暂不可用不能让运行时停摆
catalog()、latest()TTL 60 秒只用于编辑器和保存时解析

atlas-config 不可用时：已缓存的版本照常装配；只有首次用到的新版本、以及保存 agent 时的版本解析会失败，错误指明"技能目录不可用"。

7.2 保存时钉死版本（修 G1）

# services/agent.py（新增，创建 / 发新版本前调用；主 agent 与每个子智能体都处理）
async def _pin_skills(self, refs: list[SkillRefIn], previous: set[tuple[str, int]]) -> list[SkillRefIn]:
    out, budget = [], 0
    for ref in refs:
        if ref.version is None:
            info = await self._skills.latest(ref.slug)
            if info is None:
                raise InvalidSpec(f"技能 {ref.slug} 没有已发布的版本")
        else:
            info = await self._skills.get(ref.slug, ref.version)
        key = (info.slug, info.version)
        if info.status == "revoked":
            raise InvalidSpec(f"技能 {key} 已被紧急下架，请移除")
        if info.status == "disabled" and key not in previous:
            raise InvalidSpec(f"技能 {key} 已停用，不能新增引用")
        budget += len(info.description)
        out.append(SkillRefIn(slug=info.slug, version=info.version))
    if budget > settings.skill_index_budget_chars:                # 默认 2000
        raise InvalidSpec("技能描述总长超出预算", total=budget)
    return out
  • 停用的技能：沿用（上一版本已引用）放行，新加入拒绝——否则引用了停用技能的 agent 再也改不了别的配置。
  • SkillRefIn.to_engine() 改为版本为空时报错，不再写 0。
  • 存量：一次性脚本列出 agent_version.spec 中 version == 0 的引用，由人决定是否发新版本修正；不改写历史版本。
  • P1 上线时，现有 _skills/ 下手工放的技能用 python -m atlas_config skill adopt <slug> <version> 登记进表（只计算哈希、不移动对象），避免已有 agent 失效。

7.3 建会话与装配

环节变化
skill_metas_fordescription 改从 SkillDirectory.get() 取，去掉 slug 兜底；改为 async
建会话拷贝（主 agent / 子会话）拷贝前过滤 revoked()：跳过并发 skill.skipped。不让会话创建失败——下架是为了止损，不是让 agent 不可用

7.4 技能被加载（修 G7）

"选中"的可观测定义：模型读取了 /skills/<slug>/SKILL.md——正文只有被选中时才读。

类型检测位置
nativeOssFilesystem 读路径命中 /skills/{slug}/SKILL.md 时发 skill.loaded {slug, version}（同一 run 同一技能只发一次）

    name            = String(24), primary_key   # 工具前缀；^[a-z][a-z0-9-]{0,23}$；改名 = 新 server

    transport       = String(24)                # streamable_http | sse

9. MCP：智能体引用与变更检测

引用粒度沿用 tool_names（mcp:github:search_issues）：native 按工具选，编辑器按 server 分组展示。

# AgentSpec / SubAgentSpec 新增（快照纪律：必须有默认值）
mcp_tool_digests: Mapping[str, str] = {}      # "mcp:github:search_issues" → digest
mcp_drift_policy: Literal["warn", "block"] = "warn"
  • 保存时由服务端填写，客户端传的值忽略：读每个引用工具当前快照的 digest。工具不存在或 invalid → 400。
  • 装配时比对：当前 digest ≠ 记录值 → 本轮发一次 mcp.tool_drift。warn 照常使用；block 该工具不进本轮（跳过并提示，run 照常进行）。
  • 存量 agent 没有记录（空字典）→ 不比对，下次保存时补上。
  • 编辑器的「待复核」= 当前快照与 agent 当前版本记录的 digest 不一致；"确认"就是重新保存一个版本。

# host/runtime.py _open()：由 spec.tool_names 中的 mcp:* 推出 server 集合
def acp_mcp_servers(spec, catalog, user_id) -> list[dict]:
    servers = sorted({p[0] for t in spec.tool_names if (p := parse_tool_id(t))})
    out = []
    for name in servers:
        cfg = catalog.server(name)                 # 未注册 / 已停用 → McpUnavailable，run 失败
        if cfg.credential_scope != "platform":
            raise McpUnavailable(f"{name} 需要用户授权，ACP 暂不支持")   # P3 前
        conn = connection_for(cfg, timeout_s=…)    # 解析 ${ENV}；缺变量明确报错
        out.append({
            "type": "http" if cfg.transport == "streamable_http" else "sse",
            "name": name,
            "url": conn["url"],
            "headers": [{"name": k, "value": v} for k, v in conn["headers"].items()]
                       + [{"name": "X-Atlas-User", "value": str(user_id)}],
        })
    return out

params["mcpServers"] = acp_mcp_servers(prepared.spec, catalog, user_id)   # 新建与 resume 都传
要点说明
粒度只能到 serverACP 的 mcpServers 是 server 级的，CLI 会看到该 server 的全部工具。编辑器对 ACP 只提供 server 级选择（原型需小改：显示"github · 全部 6 个工具"），保存时自动展开为该 server 当前全部可用工具，以便记录指纹
会话内不变只在新建 / resume 时下发。server 被停用后在途会话不受影响，紧急下线要在网关侧做（P3）；管理页对停用操作给出该提示

20.2 与上文设计的偏差

设计实现原因
状态有 draft / scanning，扫描异步无这两个状态：上传即同步扫描，结果是 pending_review 或直接 published≤ 20MB 的正则扫描是毫秒级；多一个中间态只多一种「重启后卡在半路」
skill_version 主键 (slug, version)主键 id（UUID），(slug, version) 唯一待审查 / 被拒的上传没有版本号
动作用 …:approve子路径 …/approveStarlette 路径参数会吞掉冒号后的部分
block 策略下全被拦则 run 失败跳过并提示，run 照常与复核闸门同一套行为，更简单
loads = 加载次数loads = 加载过该技能的 run 数同一 run 常分段读同一个 SKILL.md，按次数会虚高
没有配置服务时 = 不可用兼容模式：技能必须写明版本号，描述以 slug 兜底接入前已存在的部署不应因此失效
运行时 API 按角色检查暂未检查用户模块未上线，现在只有 dev 身份
ACP 子智能体编辑器按 server 选后端不展开通配；下发按 server，闸门按 server（任一工具未复核整台不下发）CLI 自己 tools/list，平台无法按工具裁剪
