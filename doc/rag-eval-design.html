1. 原则

原则说明
公开数据为主文档与题目优先取自公开评测集：题目经过设计、有人工标注、覆盖面广、外部可复现，且能与论文 / 排行榜结果对照。自建或自动出的题只作为私有文档的补充
检索与生成分开评检索错了生成不可能对；分开评才能定位问题。检索评测尽量不用大模型（便宜、确定）
平台中立只通过各平台公开 API 交互；出处按原文片段 / 页 / 段落标注，不依赖任何平台的分段 ID
复用成熟实现大模型裁判类指标直接用 RAGAS，不重写；评测集自带的官方指标也要算，用于对照公开结果
跑题与判分分离原始结果落盘；判分可离线重跑、换裁判、加指标，不重跑平台
结论讲统计报告给置信区间与显著性；差距在误差内写「无显著差异」

5. 统一数据模型

Corpus 语料：documents[{doc_id, path, sha256, format(md|pdf|html|txt|docx), lang, meta}] Question id, source(评测集), split(dev|test), lang task qa | summarization | continuation | correction （CRUD-RAG 的非问答任务） question 问题（续写 / 摘要任务为指令 + 原文） answers 可接受答案列表（同义写法、数值的不同格式） reference 参考答案（给 RAGAS 正确性 / 召回类指标） evidence 标准出处，多条，每条一种粒度： {doc_id, quote} 原文片段（首选） {doc_id, page} 页（FinanceBench） {doc_id, passage_id} 段落（C-MTEB、RGB） {doc_id} 整篇（只能判到文档级） tags 单跳 | 多跳 | 汇总 | 表格 | 数值 | 拒答 | 噪声 | 反事实 | 错误前提 | 时效 …（可多个） unanswerable 资料中无答案 false_premise 问题前提错误（应指出而不是作答） official 评测集原始字段（官方口径判分用）

出处多粒度是为了兼容不同评测集的标注方式；检索判分按粒度选择匹配规则（§9.2）。所有导入结果带评测集版本与随机种子，写入 manifest.json。

6. 导入与语料构建

6.1 导入器

评测集导入要点
CRUD-RAG问答题直接映射；摘要 / 续写 / 幻觉修改映射为对应 task；证据新闻转 doc_id + quote
RGB每题的正例文档作为出处，干扰文档进语料；拒答子集标 unanswerable，反事实子集标 反事实
MultiHop-RAG证据句（fact）转 quote；空答案题标 unanswerable；保留查询类型
FinanceBench下载 PDF；证据转 {doc_id, page} + quote（证据原文）
CRAG每题 5 个网页作为 HTML 文档进语料；题型、错误前提、时效标签映射到 tags
C-MTEB段落一篇一个文档、按「不切分」导入（与官方口径一致），用于模型选型

6.2 语料规模控制

全量入库成本高（CRUD-RAG 8 万篇）。语料采用「标准文档 + 干扰文档抽样」：抽样题目的全部证据文档必须入库，再按固定种子抽 N 倍干扰文档（默认 10 倍）。报告注明语料规模；另设「全量」档位做规模压力测试。

6.3 划分

每个评测集固定种子划分 dev / test（默认 2:8）。dev 只用于调参（赛道 B，§14），test 只出分。抽样题目时按 tags 分层，保证各场景都有题。

6.4 私有文档补充（RAGAS 出题）

步骤做法
生成RAGAS TestsetGenerator：文档 → 知识图谱（标题切分、摘要、主题、实体，按摘要相似度与实体重叠建关系）→ 按比例生成单跳具体题、多跳抽象题、多跳具体题；可设提问者画像
转换RAGAS 输出的问题、参考答案、参考段落转统一格式；参考段落转 quote
审核进入「待审核」状态，人工删改后才进入评测集；记录审核人
补拒答题RAGAS 不生成拒答题：从其他文档的题目中抽一部分作为本库的拒答题（资料中无答案）

9. 检索评测

9.1 两种模式

模式做法用途
链路模式文档按平台 / 配置自己的方式解析、分段后检索评测完整检索链路（解析 + 分段 + 向量 + 混合 + 重排）；分段方式、平台对比
段落模式段落一篇一个文档、不切分，只比检索本身向量 / 重排模型选型，可与 C-MTEB 公开结果对照

9.2 出处匹配规则

出处粒度命中判断
原文片段 quote两边归一化（全角转半角、去空白与标点、小写）后包含即命中；片段被分段边界切开时，用模糊匹配（相似度 ≥ 90）或「相邻两段拼接后包含」兜底，记为部分命中
页 page段落带页码时按页码；不带时用该页证据原文按 quote 规则匹配
段落 passage_id段落模式下按 ID；链路模式下转成段落原文按 quote 匹配
整篇 doc段落来自该文档即命中（只作参考，粒度太粗）

指标：命中率@k、召回率@k（多出处）、MRR、nDCG@10、返回字数；按 tags 分项。粒度粗或无出处的题（如摘要）用 RAGAS 上下文召回率补充。

9.3 为什么出处匹配自研、指标计算用现成库

检索评测分两步：① 判定每个检索结果是否命中标准出处，得到每题「第几名命中了哪条出处」；② 按判定结果计算命中率、MRR、nDCG 等。②是标准公式，用 ranx（与 BEIR / C-MTEB 使用的 pytrec_eval 口径一致）计算，不自己写；①没有现成实现能满足跨平台评测，必须自研：

现成方案做法为什么不够
RAGAS IDBasedContextRecall / Precision检索段落 ID 与标准段落 ID 求交集各平台分段不同，段落 ID 互不相通；同一平台换分段方式后 ID 也全变，无法比较
RAGAS NonLLMContextRecall / Precision标准段落与每个检索段落算整串编辑距离相似度，取最大值，超过 0.5 算命中整串比较而非「是否包含」：标准出处 50 字、检索到的父块 2000 字时，即使完整包含相似度也很低，会大量误判为未命中；分段越大越吃亏，恰好扭曲分段方式对比
RAGAS LLMContextRecall / Precision大模型逐条 / 逐段判断花钱、有波动，不适合每次改动都跑；作为补充指标保留
评测集官方脚本（pytrec_eval 等）按评测集自己的段落 ID 计算只适用于「段落模式」；链路模式下平台会重新分段，官方段落 ID 不再对应检索结果

自研的判定层只做一件事：把多粒度出处（原文片段 / 页 / 段落 ID / 整篇）统一转成「第几名是否命中」，规则见 9.2（中文归一化、包含判断、边界被切开时的模糊与拼接兜底、部分命中单列）。段落模式下直接用评测集的段落 ID，结果可与官方口径对照。

10. 生成评测

题型主要指标说明
普通问答CRAG 计分、事实正确性、忠实度CRAG 计分看对错并惩罚编造；忠实度看是否有依据；两者结合可区分「答错但有依据（检索错了）」与「答错且无依据（模型编造）」
拒答题拒答准确率、误拒率无答案应拒答；有答案时拒答记为误拒
噪声 / 反事实 / 错误前提噪声敏感度、错误识别率RGB 反事实：资料有误时能否指出；CRAG 错误前提：能否指出前提错误
摘要 / 续写（CRUD-RAG）官方口径 + RAGAS 忠实度官方 BLEU / ROUGE / BERTScore / RAGQuestEval 对照论文；忠实度看是否编造
所有题回答相关性、引用正确率、两两胜率相关性只看切题；引用看标注出处是否真的支持说法

错题归因：结合检索与生成结果自动归类——检索未命中（解析 / 分段 / 检索问题）、命中但答错且不忠实（模型编造）、命中且忠实但答错（理解或推理错误）、应拒未拒、误拒。报告按归因统计，指导改进方向。

11. RAGAS 集成

11.1 用到的能力

RAGAS 能力在本体系中的用途
Faithfulness忠实度 / 幻觉率；引用正确率（对引用段落单独算）
FactualCorrectness与参考答案比对的正确性（F1）
ResponseRelevancy回答相关性、含糊其辞检测
LLMContextPrecisionWithReference检索排序质量（大模型判断每段有无用）
LLMContextRecall出处粒度粗时的检索召回
NoiseSensitivity干扰资料下的出错比例（RGB、CRAG）
离散 / 自定义指标机制承载 CRAG 计分、拒答判断，复用 RAGAS 的大模型调用与提示词管理
TestsetGenerator私有文档出题（§6.4）
adapt_prompts把指标提示词转成中文并人工校对，结果存入仓库，避免每次自动翻译

11.2 接入方式

环节做法
样本转换原始结果 → RAGAS 样本：user_input = 问题，retrieved_contexts = 检索段落（按排名），response = 回答，reference = 参考答案，reference_contexts = 出处原文
模型RAGAS 的大模型与向量模型都指向 litellm 网关（兼容 OpenAI 接口）；裁判模型与生成模型不同
封装scoring/ragas_metrics.py 统一包装：输入原始结果、输出逐题分数与理由；RAGAS 版本固定，API 变化只改这一层
缓存按（指标, 版本, 提示词哈希, 样本哈希）缓存结果，重跑判分不重复调用
批量与限流并发上限、失败重试；单题失败记为缺失，不中断整批
可选依赖RAGAS 作为 atlas-bench[ragas] 可选依赖；只跑检索评测时不需要安装

11.3 成本估算（每题大模型调用次数）

指标调用次数
忠实度2（拆陈述 + 逐条判断）

12. 裁判模型与人工校准

项要求
选择与生成模型不同家族，避免偏袒同类回答；温度 0
提示词中文题用中文提示词（RAGAS 提示词经 adapt_prompts 转换并人工校对）
校准每个评测集抽 50～100 题人工标注，计算裁判与人工的一致率（Cohen's kappa）；低于 0.6 时调整提示词或换裁判
人工复核工具review export 导出盲评表（隐去平台与配置、随机顺序），review import 回填，结果参与统计
稳定性每题重复 3 次取多数 / 平均；报告裁判自身的波动

17. 风险与限制

风险应对
公开评测集与实际业务分布不同公开集用于横向对比与回归；业务决策同时参考私有文档评测
评测集可能已被模型训练过（数据污染）关注相对差距而非绝对分；私有文档结果作为对照
英文评测集为主的场景（多跳、PDF）缺少中文对应用私有中文文档 + RAGAS 出题补充；持续关注中文新评测集
出处被分段边界切开导致误判模糊匹配与相邻拼接兜底，单列「部分命中」并抽查
大模型裁判的波动与偏差温度 0、多次取平均、异家族裁判、人工校准一致率
RAGAS 接口变化较快；主分支最近更新于 2026-02固定版本，封装在 ragas_metrics.py；关注维护活跃度，必要时换 DeepEval 等，只换判分器
评测成本（入库 + 大模型调用）语料抽样、题目分层抽样、结果缓存、默认指标集最小化
当前能力短板会主导分数（向量模型偏弱、无 PDF 版面解析）先做 E2 选模型；PDF 相关实验等接入解析器后再做
非商用许可证对外发布前逐项确认（§15）
