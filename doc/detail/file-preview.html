Detailed Design · Workspace File Preview

会话文件预览

会话右侧现在只能列出文件、下载文件。智能体产出的东西（一份报告、一段代码、一个能点的 Web 原型）用户必须先下载、再用本地工具打开，才知道它做得对不对。这份设计让文件在平台里直接看。其中最难的一种是 HTML 原型：它是多个文件组成的站点，会执行脚本。所以设计的重心是把工作区当成一个隔离的只读站点来提供。

只读工作区 = 站点令牌放在 URL 路径里sandbox 不透明 origin按 ETag 刷新新标签页

01目标与范围

目标说明
点开即看在文件面板里点一个文件，不下载就能看到内容。
HTML 能跑index.html 引用的 assets/app.js、assets/styles.css 都能正确加载，页面能点、能交互。这正是当前会话 065c767d… 的真实产物形态。
不伤平台预览的内容是模型生成的，一律视为不可信。它的脚本不能读写平台页面、不能借用户身份调用 API。
跟得上运行run 进行中文件在变，预览要能看到新内容，但不能把用户正在操作的页面突然刷掉。
不在本文范围

编辑文件；预览技能区（.skills/）和隐藏文件；Office 文档、音视频、压缩包浏览；对外分享链接（预览令牌是短期的个人凭据，不是分享机制）；窄屏（<1280px）下文件面板被隐藏、没有预览入口的问题（现状如此，放到 P2）。

02现状

位置现在做什么与预览相关的约束
GET /v1/threads/{id}/files递归列出工作区对象（WorkspaceListing.list），跳过以点开头的路径段，最多 2000 条只返回 path / size / modified_at，没有 ETag，前端无法判断"内容变了没有"
GET /v1/threads/{id}/files/download?path=流式返回整个文件，Content-Disposition: attachment要带 X-User-Id 请求头，所以前端只能用 fetch 下载，iframe / img 用不了
WorkspaceListing.open用 _to_key 把路径限制在本会话的 workspace 前缀内会话隔离的唯一安全关键点，预览必须复用它，不能另写一套路径解析
FilesPanel.tsx右侧 340px 列表 + 下载按钮；运行中每 10s 刷新一次340px 放不下 HTML 预览；屏幕窄于 1280px 时整块隐藏
components/Markdown.tsxreact-markdown + rehype-sanitize，禁 img，链接强制 noopener可以直接用来渲染 .md
身份identity.current_user 从 X-User-Id 取，缺失时回落默认用户（决策 1：不做鉴权）现在 iframe 不带请求头也能访问，但以后换 JWT 就会失效。设计不能依赖"不鉴权"这个现状

03核心判断：预览 = 只读站点

最直观的做法是"新增一个返回文件内容的接口，前端按类型渲染"。对文本、图片够用，对 HTML 不行：

  • 把 index.html 的内容塞进 iframe srcdoc，里面的 <script src="assets/app.js"> 会相对于平台页面解析，全部 404。
  • 前端自己改写所有相对路径、内联资源？要解析 HTML、CSS 里的 url()、JS 里的动态 import() 和 fetch()，写不完，也写不对。
决定

把一个会话的工作区当成一个只读静态站点，挂在 /v1/previews/{token}/ 下。浏览器按正常的相对路径规则解析子资源，服务端按路径从对象存储里取文件。所有预览读取（HTML、图片、文本）都走这条路，下载仍走原来的 download 接口。

这样就有了三个连锁的设计点，后面逐个展开：

问题答案章节
iframe / img 不能带请求头，身份怎么传？短期预览令牌，放在 URL 路径里（不放 query，否则相对路径解析时会丢掉）06
站点里的脚本是不可信的，怎么隔离？iframe sandbox + 响应头 CSP: sandbox，两层都让文档运行在不透明 origin07
文件在变，怎么知道该刷新？文件列表补上 etag，预览接口支持 If-None-Match09

动作行为

06后端接口

接口说明
新POST /v1/threads/{id}/files/preview为这个会话签发预览令牌，返回 { base_url, expires_at }。要求请求身份对会话有读权限（现在等价于会话存在；有鉴权后改为 created_by == user）。
新GET /v1/previews/{token}/{path:path}只读站点。不看 X-User-Id，令牌本身就是凭据。支持 Range、If-None-Match。
改GET /v1/threads/{id}/files每项加 etag（S3 ETag 去引号）。纯新增字段，旧前端不受影响。
不变GET /v1/threads/{id}/files/download下载语义不变。预览不复用它：它要带请求头、又强制 attachment。

预览令牌

项决定理由
形态32 字节随机数，base64url。存 Redis：atlas:preview:{token} → {thread_id, user_id, workspace_thread_id}比 HMAC 签名令牌多一次 Redis 读，换来可吊销（删会话时可以连带删掉）和不用管密钥轮换。站点的每个子资源都会读一次 Redis，量级是单页几十次，可以接受。
位置URL 路径：/v1/previews/{token}/index.html放在 query 里的话，<script src="app.js"> 按相对路径解析时会把 query 丢掉，子资源全部 401。
有效期preview_token_ttl_s = 3600，每次命中续期（EXPIRE）正在看的页面一直有效；放着超过一小时没有任何请求才失效。前端在 50 分钟内复用同一个；遇到 410 自动换一个重试一次，「重新加载」也会换新令牌。
范围一个会话工作区、只读子会话的令牌按 workspace_thread_id 解析到父会话的工作区，与 list_files 的口径一致。
失效时返回 410 + 一个极简 HTML 页"预览已过期，请回到平台重新打开"iframe 里拿不到状态码，至少要让人看得懂。

站点路由的行为

GET /v1/previews/{token}/{path} 1. token → Redis 取会话；不存在 → 410；存在 → EXPIRE 续期 2. path 规范化：空 或 以 / 结尾 → 追加 index.html 3. 任一路径段以 . 开头 → 404 # 与列表的 _is_hidden 一致，.skills/ 不可经此读取 4. WorkspaceListing.open(path, range=, if_none_match=) └─ 复用 _to_key + workspace 前缀检查 # 会话隔离只有这一个关卡 └─ PathEscape → 400 NoSuchKey → 404 S3 304 → 304 5. 响应：StreamingResponse(body)，状态 200 / 206 Content-Type 按扩展名，文本类加 ; charset=utf-8，未知 → application/octet-stream Content-Length / Content-Range / ETag / Accept-Ranges: bytes 安全头见 07

需要扩展 WorkspaceListing.open：把 Range 和 IfNoneMatch 原样传给 get_object，返回值从 (body, size) 改为一个小结构 (body, status, headers)。原有的 download 调用方只取 body 和 size，改成关键字参数默认不传，行为不变。

配置新增两项：preview_token_ttl_s，以及 preview_base_url（可选，见 07 的独立 origin）。POST …/preview 返回的 base_url 由它拼出；没配置时用 API 自身的地址。

07安全模型

威胁的出发点：预览内容是模型写的，而模型的输入里可能有网页、文档等外部内容，所以预览的 HTML 可以是任意脚本。要守住的是平台本身，而不是预览页自己：预览页读到的只是它所在工作区的文件，这些文件它本来就能引用。

威胁防线
脚本读平台页面的 DOM、localStorage，或带着用户身份调用 API两层 sandbox，都不给 allow-same-origin：iframe 的 sandbox 属性，加上响应头 Content-Security-Policy: sandbox …。文档运行在不透明 origin，和平台、和 API 都不同源。响应头这一层是为了"新标签打开"和有人直接访问 URL 的情况，那时没有 iframe。
令牌经 Referer 泄露给页面引用的 CDNReferrer-Policy: no-referrer（响应头），iframe 上也设 referrerpolicy="no-referrer"。
令牌出现在访问日志里访问日志中间件对 /v1/previews/ 的路径做掩码，只保留令牌前 6 位。
用 ../、%2e%2e、绝对路径读其它会话只走 _to_key + 前缀检查这一个关卡（与 download 同一道），并补测试。
浏览器把文本按 HTML 嗅探执行X-Content-Type-Options: nosniff；.md、.txt 一律 text/plain 或 text/markdown。
点击劫持：别的站点把预览嵌进去CSP frame-ancestors 只允许平台前端的 origin（取 CORS_ORIGINS）。
弹出的新标签逃出沙箱不开 allow-popups-to-escape-sandbox：弹出的页面同样受限。代价是外链在新标签里也处在 sandbox 状态，第三方站点可能工作不正常，可以接受。

sandbox 授权清单

iframe sandbox="allow-scripts allow-forms allow-modals allow-popups allow-downloads" referrerpolicy="no-referrer" 响应头 Content-Security-Policy: sandbox allow-scripts allow-forms allow-modals allow-popups allow-downloads; frame-ancestors <平台前端 origin> Referrer-Policy: no-referrer X-Content-Type-Options: nosniff Access-Control-Allow-Origin: * # 见下 Cache-Control: no-cache # 每次用 ETag 重新校验，见 09 永远不加 allow-same-origin # 加了它再配 allow-scripts，sandbox 形同虚设 allow-top-navigation / allow-popups-to-escape-sandbox
不透明 origin 带来的副作用：要开 CORS

sandbox 文档的 origin 是 null。它加载同一站点下的 <script type="module">、fetch('data.json')、Web 字体时，在浏览器看来都是跨域请求，需要 CORS。所以预览路由返回 Access-Control-Allow-Origin: *。这是安全的：响应不依赖 cookie 或请求头凭据（凭据在路径里），* 本来就不允许带凭据。要验证的一点：全局的 CORSMiddleware 遇到 Origin: null 时不能覆盖或剥掉这个头（13）。

同源部署 vs 独立 origin

开发 / 本机生产（建议）
站点地址和 API 同一个地址：http://localhost:8000/v1/previews/…独立域名：https://preview.<domain>/v1/previews/…（配置 preview_base_url）
隔离依赖完全依赖 CSP sandbox 头一定会下发sandbox 加上浏览器同源策略，两层
理由本机多起一个域名不值得任何一处漏发 CSP 头（比如有人改了中间件、或从网关直接回源），独立域名仍然隔离得住。以后上 cookie 鉴权时，这一点是必需的

08读取上限、编码与二进制判定

项决定
文本上限前端请求时带 Range: bytes=0-1048575（1 MiB），服务端透传给 S3，返回 206 + Content-Range: bytes 0-1048575/<总大小>。总大小大于 1 MiB 时，顶部显示"只显示前 1 MiB，共 N MiB · 下载完整文件"。文件本身小于上限时 S3 返回 200，前端两种都接受。
截断边界截断点可能落在一个多字节 UTF-8 字符中间：用 TextDecoder('utf-8', { fatal: false }) 解码，末尾那个 U+FFFD 直接丢掉。
编码只按 UTF-8 解码（智能体写出来的文件几乎都是 UTF-8）。BOM 去掉。不做 GBK 等编码探测，乱码时用户可以下载。
二进制判定只对扩展名不认识的文件做：先请求前 8 KiB，里面有 NUL 字节就判为 binary，否则按 text 再取 1 MiB。认识的扩展名不做判定，少一次请求。
图片上限> 20 MiB 不渲染，显示"图片过大"和下载按钮。避免一张大图把标签页内存撑爆。
HTML不设上限：iframe 按需加载子资源，跟正常浏览一个站点一样。

09运行中文件在变

现状：run 进行中，FilesPanel 每 10s 拉一次文件列表，收到 file.written 时也立刻刷新。在这个基础上：

渲染器etag 变了之后理由
text / markdown / image自动刷新。react-query 的 key 是 [threadId, path, etag]，etag 一变就重新取这些是只读视图，刷新不会打断用户；看着智能体一点点把文件写出来，正是想要的效果
html不自动刷新，顶部出现"文件已更新 · 重新加载"条，点了才 reload iframe用户可能正在原型里点到第三屏，自动刷新会把状态清掉。站点由多个文件组成，任何一个变了都提示（比较整个列表的 etag 集合，而不只是入口文件）

iframe 内的子资源由浏览器 HTTP 缓存管理：预览响应带 Cache-Control: no-cache + ETag，所以 reload 时每个资源都发一次条件请求，没变的走 304，变了的才重新传。不需要在 URL 上加版本号。

11失败与边界情况

情况表现
部署没有配置对象存储沿用现状：文件面板显示"没有文件能力"，没有可点的文件；直接访问预览页时 POST …/preview 返回 404，页面显示同样的提示
令牌过期（放置 >1h）iframe 内显示 410 提示页；文本类请求失败后前端自动重新申请一次令牌再试，仍失败才报错
文件在预览期间被删404 → "文件已不存在"；列表刷新后同步消失
文件名含中文、空格、#、?逐段编码；补测试
HTML 引用了工作区外的绝对路径 /foo.js会解析到 /foo.js（API 根），404。这是原型自身的问题，不改写。源码视图里能看到
HTML 依赖外网 CDN，而部署在内网页面样式缺失。提示文案："页面引用的外部资源可能无法加载"，不做代理
文件列表被截断（>2000）沿用现状提示；深链到列表里没有的文件仍可预览（站点按路径取，不依赖列表），只是没有 etag，不会自动刷新
屏幕窄于 1280px文件面板本来就隐藏，入口也就没有了；预览页本身不受影响（P2 再给窄屏一个入口）

测试断言
路径逃逸../、%2e%2e/、..%2f、绝对路径、.skills/x 都拿不到工作区外或隐藏的内容（400 / 404）
令牌范围会话 A 的令牌读不到会话 B 的同名文件；子会话令牌读到的是父会话工作区
安全头每一个预览响应（含 404、410、304）都带 CSP sandbox、nosniff、no-referrer，且 sandbox 中没有 allow-same-origin
Range / 条件请求206 + 正确的 Content-Range；If-None-Match 命中返回 304
目录与 index/v1/previews/{t}/ 与 /v1/previews/{t}/sub/ 返回对应的 index.html
CORSOrigin: null 的请求拿到 Access-Control-Allow-Origin: *，没有被全局中间件改掉
测试环境注意

当前 pytest 与开发共用一个数据库，clean_db 会删掉非内置的 agent。预览相关测试尽量用替身 S3 和 fakeredis，不依赖数据库里的会话行；要依赖时先确认不会清掉开发数据。

13风险与未决

#项现状判断处理
1同源部署下，隔离完全依赖 CSP 头漏发一次就是 API origin 上的 XSS"每个响应都带安全头"写成测试；生产用独立域名
2CORSMiddleware 与预览路由自己设的 ACAO: * 是否冲突已验证（Starlette 1.6）：Origin: null 时中间件只追加 Access-Control-Allow-Credentials: true，不动 ACAO: *；对非凭据请求浏览器忽略前者由 test_opaque_origin_gets_wildcard_cors 守住
3Chrome 的 PDF 查看器在 sandbox iframe 或带 CSP sandbox 的响应里不工作已知行为P1 只提供"新标签打开"（PDF 响应单独去掉 sandbox，只保留 nosniff 和 Content-Disposition: inline），P2 再定是否引入 pdf.js
4会话读权限现在不鉴权，任何人知道 thread_id 就能列文件、能签发令牌（与 download 现状一致）签发接口预留 created_by == user 检查的位置，随权限设计一起打开
5S3 ETag 在分片上传时不是 MD5不影响用途：只用来判断"变没变"无
6令牌在用户本机浏览器历史、截图里可见一小时空闲过期，范围只读、只有一个会话接受。会话删除时清掉对应的令牌（P2）
7一个大站点的子资源请求很多，每个都要读一次 Redis + 一次 S3原型规模（几十个文件）无压力不做缓存；真成为问题时在路由里加进程内 LRU（令牌 → 会话，TTL 30s）
