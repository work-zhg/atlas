1. 为什么要管上下文

问题表现
窗口溢出长任务里工具结果（读文件、跑命令、检索）迅速堆满窗口，模型调用直接 400
信息稀释窗口没满但塞满了过期的工具输出，模型注意力被稀释，开始遗忘早期的约束与已否决的方案
成本每轮都重发全部历史；前缀缓存一旦被打乱（中间插内容、压缩改写），整段按全价重新计费
不可见用户不知道为什么智能体「忘了」，运维不知道一轮的 token 花在了哪

上下文管理要同时回答四个问题：放什么（构成）、放多少（预算）、满了怎么办（清理 / 压缩 / 恢复）、怎么让人看见（可观测）。

2. Claude Code 怎么做：全景

Claude Code 把一次模型请求的上下文拆成几层，每层有自己的来源、预算和清理方式：

┌ 静态前缀（最稳定，缓存命中的基础） │ 系统提示词 · 工具定义（MCP 工具可延迟加载，只列名字） ├ 会话上下文（每个会话算一次，memoize） │ CLAUDE.md 分层指令（托管 / 用户 / 项目含 rules / 本地，@include）· git 状态（≤2000 字符）· 当天日期 ├ 对话历史（compact boundary 之后的部分） │ 用户消息 · 助手消息 · 工具调用与结果 · 压缩摘要 └ 每轮附件（追加在最后，不破坏前缀） <system-reminder> 包裹的 40 余种：文件被改动、待办提醒、相关记忆、新可用工具、 技能清单、token 用量、计划模式、日期变化、IDE 选区…… 每次请求前的处理流水线（按顺序）： 取 compact boundary 之后的消息 → 工具结果预算：单条过大落盘留预览；一条消息里的工具结果总量封顶 → 历史剪裁（snip，内部实验） → 微压缩（microcompact）：清掉旧的工具结果 → 上下文折叠（context collapse，内部实验） → 自动压缩（autocompact）：超阈值时把整段历史压成摘要 → 调模型 → 失败恢复：上下文超限 → 反应式压缩后重试；输出被截断 → 提高输出上限续写

3. Claude Code 的关键机制

3.1 计量：以 API 返回的用量为准

  • 有效窗口 = 模型窗口 − min(最大输出, 约 20k)（预留给压缩时摘要的输出；取值依据是摘要输出的 p99.99）。
  • 当前占用 = 最近一次 API 响应的 usage（input + cache_creation + cache_read + output）+ 之后新增消息的估算。不靠纯字符估算，也不额外调 count_tokens。
  • 阈值分档：自动压缩在「有效窗口 − 13k」；警告、错误提示再各留 20k 余量；手动 /compact 只留 3k。可用环境变量把窗口人为调小（便于测试与控成本）。
  • 熔断：自动压缩连续失败 3 次就停（避免上下文已不可救时每轮白打一次压缩请求）。

3.2 工具结果预算：落盘而不是截断

  • 单条工具结果超过阈值（默认约 5 万字符，可按工具覆盖）→ 完整内容写到会话目录的 tool-results/，消息里只留约 2KB 预览和文件路径，模型需要时再用读文件工具取。
  • 一条消息里所有工具结果的总量也有上限（约 20 万字符）——并行十个工具各返回一点，加起来同样会撑爆。
  • 读文件工具自身有分页上限，不走落盘（落盘后再读是循环）。

3.3 微压缩：清旧工具结果，优先不碰缓存

  • 只清「可再生」的工具结果：读文件、Shell、grep、glob、网页搜索/抓取、编辑、写入——这些都能重新执行拿回来。清掉的位置换成一句「旧的工具结果已清除」。
  • 时间触发：距上一条助手消息超过 60 分钟（服务端 1 小时缓存必然过期，整段前缀反正要重写）→ 请求前把旧结果清掉、只留最近 5 个。缓存还热的时候不动，因为改历史会打掉缓存。
  • 缓存编辑（内部）：用 API 的 cache editing 在服务端删除旧工具结果，本地消息不变、缓存前缀不失效。
  • 服务端上下文管理：API 原生的 clear_tool_uses（超过输入阈值时清工具调用，保留最近若干）与 clear_thinking（只保留最近若干轮的 thinking）。

3.4 全量压缩：结构化摘要 + 工作集恢复

  • 压缩用一个不带工具的分叉 agent完成，复用主对话的前缀缓存（实验数据：不复用时压缩请求约 98% 缓存未命中）。
  • 摘要先写 <analysis> 草稿再写 <summary>，草稿丢弃。摘要固定九段：主要请求与意图、关键技术概念、文件与代码片段、错误与修复（含用户的纠正）、问题解决、全部用户消息、待办、当前工作、下一步（必须与用户最近的明确请求一致）。
  • 压缩请求自身超长 → 截掉最旧的若干 API 回合重试，最多 3 次。
  • 压缩后恢复工作集：重新附上最近读过的文件（最多 5 个，每个 ≤5k token，总 ≤50k）、用过的技能正文（每个 ≤5k，总 ≤25k）、当前计划与异步任务状态。技能清单本身不重发（省一次缓存写入，模型的工具定义里还有技能工具）。
  • 支持「部分压缩」（只压前半段，保留后半段原文）与压缩前钩子（PreCompact hook，可附加用户指令）。

3.5 会话记忆：后台记笔记，压缩时直接用

  • 后台的分叉 agent 周期性维护一份结构化 markdown 笔记：标题、当前状态、任务规格、文件与函数、工作流、错误与纠正、系统文档、经验、关键结果、工作日志。每节有长度上限，「当前状态」每次必更新。
  • 触发：上下文增长超过 token 阈值且（工具调用数达到阈值或上一轮没有工具调用）——token 阈值始终必需。
  • 压缩时若笔记可用，直接拿笔记当摘要（省一次 LLM 调用、几乎零延迟），保留最近 1 万～4 万 token 原文、至少 5 条文本消息，且切分点不拆开 tool_use / tool_result。

3.6 持久指令与长期记忆

  • CLAUDE.md 分层：托管（全员）→ 用户（个人全局）→ 项目（入库，含 .claude/rules/*.md）→ 本地（个人、不入库）；离当前目录越近优先级越高；支持 @path 引用其它文件，防循环。
  • 自动记忆：MEMORY.md 索引（≤200 行、≤25KB，超出截断并警告）+ 单条记忆文件；每轮按相关性挑选记忆作为附件注入；后台从对话中抽取新记忆。

3.7 按需加载，压低固定开销

  • 延迟工具：MCP 工具默认只通告名字，模型用 ToolSearch 按需加载完整 schema——几十个 MCP 工具的定义不再常驻上下文。
  • 技能：上下文里只有技能名与一句描述，调用时才加载正文。
  • 子 agent：子任务在独立上下文里跑，主 agent 只收到结论。

3.8 一条贯穿始终的约束：不打掉前缀缓存

附件只追加在末尾、压缩分叉复用缓存、微压缩只在缓存已过期时改写历史、缓存还热时用 cache editing——几乎每个机制的取舍都先问「会不会让前缀缓存失效」。

5. 设计原则

原则说明
事实源不变message 表永远存完整原文（用户视角完整）；所有清理 / 压缩只改「模型这一轮看到的视图」。延续现有 §7.4 的做法，不引入 checkpointer
能重新拿到的先丢清理顺序：可再生的旧工具结果 → 过期附件 → 早期对话（摘要）。用户消息与决定最后才动，且只以摘要形式保留
不打掉缓存稳定内容在前、变化内容在后；只在必要时改写历史前缀（超阈值、或缓存已过期）
一处计量、统一预算所有注入物（指令、记忆、知识、附件、工作集恢复）从同一个预算里分配，不各自为政
失败要说压缩失败、清理发生、预算截断都产出事件，用户看得到「早期内容已压缩 / 已清除」
渐进先补计量、恢复、摘要结构这些低风险高收益项；会话笔记、延迟工具等放后面

6. 总体架构：分层上下文

一次模型请求的组成（自上而下 = 越来越易变；缓存断点放在 L1 末尾与历史末尾） L0 静态前缀 平台基础提示词 · 智能体 system_prompt · 工具定义（常驻部分） 每个智能体版本固定 L1 会话指令 平台 / 组织 / 用户指令 · 工作区 ATLAS.md · 技能清单 会话内基本固定 L2 会话摘要 thread.summary（压缩后才有） 压缩时才变 L3 对话历史 message 表重建 → 视图变换（清理旧工具结果 / 截掉已压缩部分） 每轮追加 L4 本轮附件 记忆 · 知识库片段 · 工作集恢复 · 待办提醒 · 文件变化 · 用量提醒 每轮重算，不落库 组件（native 运行时内） ContextBudget 计量当前占用、给各层分配预算、决定触发哪一档处理 ContextPipeline 请求前的有序变换：工具结果预算 → 旧结果清理 → 自动压缩 Compactor 生成摘要、写 thread.summary、准备工作集恢复（已有，扩展） AttachmentProviders 每轮附件的提供方，统一接口、统一预算、统一渲染为 <system-reminder> ContextInspector 记录每次请求的构成，供 API / 事件 / 链路查看

7. 计量与预算

  • 窗口：取自模型目录（model_catalog.context_window、max_output_tokens，已有字段）。有效窗口 = 窗口 − min(本次请求的最大输出, 20k)。
  • 当前占用：以上一次模型调用的 usage（input + cache_read + cache_creation + output）为基线，加上之后新增消息的估算；没有基线（新会话、续跑首段）时退回现有的字符估算。DeepSeek 等网关同样返回 usage，不依赖 Anthropic 专有能力。
  • 分档（比例相对有效窗口，可按智能体配置）：
档位默认动作
清理60%清掉较早的可再生工具结果（§8 ②）
压缩80%（现为 75%）自动压缩（§9）
提醒90%给模型一条用量附件：「上下文将满，请精简输出、尽快收尾或保存进度」
超限API 返回上下文过长反应式压缩后重试一次（§8 ⑤）
  • 附件预算：L4 总量默认 ≤ 有效窗口的 10%，按优先级分配：工作集恢复 > 知识库 > 记忆 > 其它提醒；超出部分截断并在附件里写明。
  • 熔断：同一会话自动压缩连续失败 3 次 → 本会话停止自动压缩，发事件告知（用户可手动触发或新开会话）。

8. 请求前流水线

在 kernel 的 before_model 阶段按序执行（现有 CompactionMiddleware 扩展为流水线；顺序固定写在一处并注明理由）：

#步骤做法是否改写历史前缀
①工具结果预算单条超限外置到工作区 /large_tool_results/（已有）；新增同一批工具结果总量上限（默认 8 万 token），超出的从最大的开始外置否（只影响新结果）
②旧工具结果清理只清可再生的工具：read_file、search、execute、MCP 只读类、知识库检索；保留最近 N 个（默认 5）；替换为「[旧的工具结果已清除，可重新调用 X 获取]」。触发：占用 ≥ 清理档，或距上次助手消息已超过缓存 TTL（缓存反正失效）是，所以只在上述两种情况触发
③自动压缩占用 ≥ 压缩档 → §9是
④附件注入§12，追加到最后一条用户消息之后否
⑤失败恢复模型返回「上下文过长」→ 立即强制压缩并重试一次；返回「输出被截断」（max_tokens）→ 提高本次输出上限续写一次（不超过模型上限）按需

★ 视图变换只作用于本轮发给模型的消息列表；message 表、事件归档不变。清理与压缩都产出事件（context.cleared / context.compacted），前端在对话里显示一条分隔说明。

9. 压缩：摘要与工作集恢复

9.1 摘要结构（扩展现有四块）

#段落来源
1用户的原始目标与硬约束现有
2已确认的关键事实与数据（必须带来源）现有
3已做出的决定，以及已排除的方案与排除理由现有（最易丢、最贵的失败模式）
4涉及的文件、命令与关键片段新增
5遇到的错误与修复，尤其是用户的纠正新增
6全部用户消息（逐条，非工具结果）新增——用户意图的变化轨迹，摘要最容易抹掉它
7待办现有
8当前正在做什么、下一步（必须与用户最近的明确请求一致）新增
  • 先写草稿（<analysis>）再写摘要，只保留摘要。
  • 摘要模型：默认用智能体自身的模型（质量与当前任务一致，且能复用前缀缓存——见 §15）；可配置为便宜模型（compaction.summarizer_model，空 = 用自身模型）。去掉写死的 haiku。
  • 压缩请求自身超长 → 截掉最旧的回合重试，最多 3 次；仍失败走现有降级（只保留最近回合 + 告知）。

9.2 压缩后恢复工作集

摘要写得再好，也丢掉了「刚才正在看的那几个文件的原文」。压缩后的下一次请求，以附件形式补回（不落库）：

内容上限来源
最近读 / 写过的工作区文件（当前内容）最多 5 个，每个 ≤5k token，总 ≤40k从被压缩区间的工具调用里收集路径，按最近使用排序；重新从对象存储读当前版本
本会话已加载的技能正文每个 ≤5k，总 ≤20k压缩区间里读过的 SKILL.md
当前待办清单—最新的 todos 快照
进行中的委派 / 挂起状态—未结束的子 run

9.3 会话笔记（P3，可选）

参照 Claude Code 的会话记忆：后台在阈值满足时（上下文增长 ≥ X token 且 工具调用 ≥ Y 或上一轮无工具调用）更新一份结构化笔记（存会话的 system 前缀，用户在会话侧栏可见）；压缩时优先用笔记作摘要，省一次模型调用、压缩几乎无延迟。代价是后台额外的模型调用——P3 视成本数据决定是否开启。

10. 持久指令分层

Claude Code 靠本地文件系统发现 CLAUDE.md；Atlas 是服务端多租户，指令来源换成「数据库分层 + 工作区文件」：

层谁维护存哪例子
平台管理员配置服务（新表 instruction，scope=platform）合规要求、输出语言、禁止事项
组织 / 团队团队管理员同上，scope=org团队规范、术语表
用户用户本人同上，scope=user「默认中文、技术术语保留英文」这类个人偏好
智能体智能体作者AgentSpec.system_prompt（已有）角色与能力说明
工作区任何能写工作区的人 / 智能体工作区根目录的 ATLAS.md（兼容读取 AGENTS.md）项目约定、目录说明
  • 注入位置：L1，紧跟系统提示词，顺序 平台 → 组织 → 用户 → 工作区（后者优先级高，放后面）。
  • 每层大小上限（默认 4k token），总上限 12k；超出截断并在事件里提示。
  • 会话开始时快照一次（会话内保持不变，保住缓存）；用户修改后从下一个会话生效，或手动「刷新指令」。
  • 与记忆的分工：指令是人主动写的规则（必须遵守）；记忆是系统观察到的事实（参考、可能过期）。

11. 长期记忆与知识的注入

  • 记忆（衔接记忆设计）：开启自动注入后，每轮用本轮提问检索 top-k（默认 5）相关记忆，作为 L4 附件注入，预算 ≤2k token；附件写明「以下是关于用户的历史记忆，可能已过期，与当前指令冲突时以指令为准」。不落库、不进历史（下一轮重新检索），与知识库 auto 模式同一做法。
  • 知识库：auto 模式现状不变（本轮注入、不落库），改为从统一的附件预算里分配。
  • 两者都附来源（记忆 id / 文档名 + 标题路径），便于模型引用、用户追溯。

12. 每轮附件（system-reminder）

把散落的「本轮额外信息」统一成附件机制：

13. 工具与技能的按需加载

  • 延迟工具（P3）：智能体挂的 MCP 工具超过阈值（默认 20 个或定义超过 10k token）时，非核心工具改为只列名字 + 一句描述，提供 tool_search 工具按需加载完整定义；加载过的工具本会话内常驻。模型侧需要支持动态增加工具（LangChain 每次调用都 bind_tools，可在中间件里按会话状态扩展）。
  • 技能：现状已是「清单 + 按需读 SKILL.md」，保持；压缩后不重发清单（清单在 L1 本就常驻）。

14. 子智能体与 ACP

  • 子智能体：独立子会话、只回结论（现有，保持）。委派时的输入上下文显式（task 描述 + 必要文件路径），不继承主会话历史——这本身就是最有效的上下文隔离。子会话各自有压缩与预算。
  • ACP：上下文由 CLI 自管（Claude Code 自带上述全部机制），平台不介入改写；但把 ACP 的 usage_update 翻译成平台的用量事件，用于展示上下文用量与链路观测（目前日志里是「未翻译的 session/update 类型」）。

15. 与 prompt cache 协同

做法理由
固定顺序 L0 → L1 → L2 → L3 → L4，缓存断点放在 L1 末尾与 L3 末尾稳定的在前；附件每轮变，放最后不影响前面命中
旧工具结果清理只在「超档」或「缓存已过期」时触发缓存还热时改写历史 = 整段重新计费，得不偿失
压缩默认用智能体自身模型，请求 = 原历史 + 摘要指令命中原历史的前缀缓存（Claude Code 实测不复用时约 98% 未命中）。用便宜模型时缓存无法复用——二者的成本取舍按「历史长度 × 缓存价差」决定，提供配置
指令在会话开始时快照会话内 L1 不变
缓存 TTL 来自模型目录 / 网关配置（5 分钟或 1 小时）时间触发的清理依赖它；DeepSeek 等网关的缓存语义不同，按实际配置

16. 可观测与用户可见

  • 上下文构成：每次模型调用记录各层 token（L0 工具定义 / 指令 / 摘要 / 历史：对话 + 工具结果 / 附件按名字），写入 OTel span 属性 atlas.context.*，并提供 GET /v1/runs/{id}/context 返回最近一次请求的构成。
  • 事件：context.compacted（已有，补充压缩前后 token、摘要模型、是否用了笔记）、context.cleared（清了几个工具结果、释放多少）、context.warning（达到提醒档）。
  • 前端：会话顶部显示上下文用量条（占有效窗口的比例，颜色对应档位）；对话里在压缩 / 清理处显示分隔说明；「查看上下文构成」弹窗（同 Claude Code 的 /context）；支持手动「压缩」按钮（可附加「重点保留什么」的说明）。

20. 风险与限制

风险缓解

摘要遗漏关键约束八段结构强制覆盖用户消息与纠正；工作集恢复补原文；评测里专门加「压缩后仍需遵守早期约束」的任务

与设计的偏差

  • 持久指令每一轮开始时读一次，而不是在会话开始时固定一份快照：修改从下一轮生效；本轮内不变，前缀缓存不受影响。
  • 组织层指令暂不做：用户中心的组织模型还没接进 Atlas。
  • 平台指令要求 instruction:manage 权限，但这个操作还没在用户中心注册（缺管理员凭据），暂时以 model:manage 兜底。
  • 延迟工具只覆盖 MCP 工具，原生工具一直常驻。阈值是 MCP 工具超过 20 个，或定义总量超过 10k tokens（deferred_tools_min_count / min_tokens）。
  • 旧版本智能体的 spec 里存着旧默认值 summarizer_model: claude-haiku-4-5，现在按「未设置」处理，改用智能体自己的模型（resolve_summarizer_model）。
  • 摘要提取有兜底：deepseek-chat 有时只写完 <analysis> 就结束、不输出 <summary>，这时退回使用 analysis 正文。

验证中顺带修复

  • OSS 文件系统对越界路径或工作区根（如 read_file("/workspace")）原来是直接抛 PathEscape，会打断整个 run，而且被误归类成 model_unavailable。现在 read / write / edit / delete 都改为返回错误结果，由模型自行纠正。
