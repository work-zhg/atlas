01 / Overview

项目概括

Atlas 做两件事：智能体管理（配置模型、提示词、工具、子智能体、运行限制， 并可直接试跑）与多轮对话（带完整运行轨迹的会话工作台）。 它不满足于「给一个最终答案」—— 一次对话 run 的执行过程本身就是产品的一部分： 待办清单的更新、每一次工具调用的入参与结果、子智能体的委派边界、token 消耗、 产生的文件，都会按发生顺序流到前端。

功能亮点

  • 过程可见、可回放 —— 待办清单、每次工具调用的入参与结果、子智能体的委派边界、 文件产物、token 消耗，按严格有序的事件流实时呈现；刷新页面、切后台、开多个标签页都能从断点续上。
  • 高风险操作要人点头 —— Shell 命令与编码任务默认进审批，弹窗展示完整参数； 拒绝不会让整轮白跑，而是作为工具结果回给智能体，它可以换个方案继续。
  • 命令与代码跑在隔离容器里 —— Shell 沙箱按会话起容器、默认无网络、非 root； 编码任务另起一次性容器，两者共用同一个工作区卷，改完的文件立刻能被看到。
  • 配置即版本 —— 保存就产生一份配置快照，任何一条历史会话都能回答 「当时用的是哪份配置」，也可以回滚；草稿不用保存就能直接试跑。
  • 长会话不会突然失忆 —— 接近上下文上限时自动摘要压缩，并明确告诉用户「这里压缩过」， 而原始消息一条都不会丢。

02 / Architecture

系统架构

层职责关键约定
web会话工作台 · Agent 编辑器 · 事件归约与渲染 只认 TraceEvent 契约与 REST 契约，不感知内核
server路由 / 编排 / 持久化 / 凭据注入 / 后台执行 repositories/ 是唯一接触 Postgres 的地方
engineAgentSpec → 编译 → 执行 → 产出 TraceEvent 唯一对外入口 runner.run()；模型、hooks、clock 全由调用方注入
kernel模型 ↔ 工具 ↔ 子智能体的执行循环 自有代码，可按项目需要直接裁剪与改造

一次 run 的骨架

  • POST /threads/{id}/runs 幂等校验 + 会话串行锁，落库后立刻返回 202 {run_id}
  • executor 在后台 asyncio.Task 里自建 session 与 Redis 连接，跑 engine.run()
  • 事件经 relay XADD 进 Redis Stream，SSE 侧 XRANGE 补发 + XREAD BLOCK 续推
  • 终态先落库（助手消息 / run 状态 / 事件归档 / 文件），再发布 run.finished

三层边界

  • web 只认 TraceEvent 契约与 REST 契约
  • server 独占凭据、持久化与编排
  • engine 无 FastAPI / DB session / HTTP，可脱离数据库单测
  • 依赖方向由 import-linter 契约在 CI 上强制

03 / Kernel

内核架构

kernel/ 是 engine 之下的执行内核， 它把「模型 ↔ 工具 ↔ 子智能体」这个循环装配成一张图， engine 只负责把 AgentSpec 翻译成装配参数。

graph.py · 图装配

  • 唯一入口 create_deep_agent(model, system_prompt, tools, filesystem_tools, backend, middleware, subagents)
  • 产出模型 ↔ 工具 ↔ 子智能体的执行循环，engine 侧 agent.py 是它唯一的调用者
  • skills / memory / permissions / checkpointer / store 等参数从不传，对应分支结构性不激活

middleware/ · 能力叠放

  • filesystem —— ls / read / write / edit / glob / grep / execute，兼大结果外置与权限挂点，最大的一件
  • subagents —— task 委派的本体
  • summarization —— 只装在子智能体栈；主图走 engine 自己的 CompactionMiddleware，不会双重压缩
  • patch_tool_calls 修复被截断的 tool call · prompt_caching 注入 cache_control

backends/ · 文件与执行后端

  • state —— 默认虚拟文件系统，不落磁盘
  • sandbox —— 容器执行的基类，server 的 DockerSandbox 继承它
  • protocol —— 后端协议与响应类型，server 直接 import 这一层
  • composite —— 多后端按路径路由，为将来的深度路径映射留的载体

04 / Features

核心功能

智能体管理与版本

  • 创建 / 编辑 / 启用 / 归档，列表支持搜索与按模型筛选
  • 保存即产生新版本：PATCH 新建 agent_version 并切换指针，不做原地更新
  • 版本列表可回滚；DELETE 是归档语义，历史会话仍可解释
  • 草稿试跑 dry-run：带未保存的 spec 直接跑，不落 thread

多轮对话

  • thread / message 两层，message 永远保存完整原文
  • 首轮自动生成会话标题（haiku），title_source 区分 generated / manual / fallback
  • 历史轨迹回放：从 run_event 表读，不走 SSE
  • 会话虚拟文件列表，中间产物可下载

实时运行轨迹

  • TraceEvent 契约共 23 种事件类型，当前产出 20 种
  • SSE + Last-Event-ID，游标是 seq（单 run 内从 1 严格递增、无空洞）
  • Redis Stream 做实时通道（TTL 24h），超期从 run_event 表回放
  • 前端按 seq 去重补齐，刷新页面 / 切后台 / 多标签页都能续上

工具体系

  • write_todos 待办清单 · task 子智能体委派
  • 虚拟文件系统：ls / read_file / write_file / edit_file / glob / grep
  • web_search 裸搜索 API —— 搜几次、搜什么由模型自己决定
  • MCP 接入：仅 HTTP/SSE 远程传输，凭据用 ENV 占位符，不落库
  • execute（沙箱 Shell）· coding_task（容器化编码智能体）

人工确认（HITL）

  • 高风险工具默认进 require_approval_for，弹窗展示完整参数
  • engine 侧 await 一个接缝，server 用 Redis BLPOP 等人点头
  • approval 表留审计：谁、什么时候、批了还是拒了
  • 拒绝不终止 run：拒绝作为工具结果回给 agent，它可以换方案继续

隔离执行

  • Shell 沙箱按会话起容器（懒创建、闲置回收），文件在会话内持续存在
  • --network none · 非 root · --cap-drop ALL · 只读根 + tmpfs · 512m / 1cpu / 256pids
  • coding_task 每任务一个一次性容器，跑完即弃
  • 两者共用 atlas-ws-{thread} 卷：编码智能体改的文件，Shell 立刻能看到
  • WorkerBackend 抽象后端，Docker 先行，K8s 是第二个实现

上下文与运行限制

  • 接近上下文窗口时自动摘要压缩，并以 context.compacted 事件让用户看见
  • 压缩只改「模型视角」，message 表原文不动
  • 步数 / 超时 / token 上限 / 并发 / 递归深度，全部可配置且真实生效
  • 取消位 run:cancel、幂等键 Idempotency-Key、会话串行锁（同一会话同时只跑一个 run）

模型接入

  • 经 litellm 网关走 Anthropic 原生 /v1/messages，不走 OpenAI 协议路径
  • model_catalog 维护能力矩阵而非单价：上下文窗口、thinking、effort、temperature、缓存
  • 巡检不可用的模型标 is_available=false，编辑器里直接禁选
